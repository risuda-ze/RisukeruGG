# spec-authoring

1. 草案は `reference/spec-template.md` の項目順・書式で書く（実装側の受け入れ基準 spec-intake と同じ項目）
2. 方針が複数ありうる場合は `reference/patterns.md` の軸で案を比べ、採用案と理由を「根拠・仮定」に書く
3. 受入条件は「入力・操作 → 観測できる結果」。曖昧語（適切に・正しく・ちゃんと・など）を使わない
4. 用語は `docs/共通用語/共通用語.md` の定義に合わせる。新語は「用語追加候補」に列挙する
