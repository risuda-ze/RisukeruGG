# 動画依頼の追加

## 目的・対象範囲

配信チームが依頼内容をDiscordとタスク管理に二重入力する手間をなくす。Webの動画依頼画面、カテゴリ設定、タスク、Discordへの配送と納品操作を対象とする。既存のブリーフ・予定通知は独立して動く。

## 正本仕様との関係

[動画依頼](../仕様・計画/video-request/README.md)を追加し、入力・権限・列と状態・操作フローを管理する。タスク列の定義はtask、Discordの共通機能はintegrationが管理する。

## 受入条件

| ID   | 操作                                                             | 期待結果                                                                                                                       |
| ---- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| AC-1 | 任意の名前の3列を割り当て、列名を変更して依頼・納品する          | 作成時、Discord送信後、納品後の各タスクが指定した列IDに移動する                                                                |
| AC-2 | 列を未設定のまま依頼する                                         | 設定を案内し、依頼・タスクを作成しない                                                                                         |
| AC-3 | サムネ作成を切り替えて依頼する                                   | オフでは動画のみ、オンでは動画とサムネのタスク・スレッドを作る                                                                 |
| AC-4 | 制作中にサムネのみ承認する                                       | サムネが完了し、動画は制作中のまま                                                                                             |
| AC-5 | 動画依頼の初稿納期に編集開始日より早い日を入力し、次に同日にする | 逆順ではエラーで送信不可、同日ではエラーが消える。既存の制作ブリーフでは共通カレンダーを引き続き使える                         |

## 設計と互換性

チーム設定と動画依頼の管理操作はメンバーだけが行い、スタッフは閲覧・担当作業に限定する。Functionsが依頼作成時に現行のロール（`member` / `staff`）と列の存在を検証する。旧ロールは事前に現行ロールへ変換して保存するため、実行時の互換処理は持たない。依頼、タスクと列IDの保存は単一トランザクションで行う。データ項目は[モデル](../仕様・計画/video-request/model.md)を参照する。

新規依頼の同期にはリスケるGGの既存Botを使う。FunctionsがFirestoreの作成イベントを受けて投稿し、Webの既存Interactions Endpointが納品操作を受ける。

## 運用方針と障害復旧

新規依頼は既存BotをFunctionsから利用し、Firestore上の `discordRouting` とスレッドIDを正本とする。Discordのボタンは作成元アプリに属するため、作成済みの投稿を書き換えない。

投稿途中で停止した場合は、依頼カードに保存したスレッド情報を使って再送信する。再送信はメンバーだけが実行でき、既存スレッドを新しく作成しない。投稿そのものの途中で切断された場合は同一本文が重複する可能性があるため、カードの既存スレッドリンクを確認してから再送信する。

Webでは既存のカテゴリ設定に列の選択欄を追加する。チーム設定の書き込みはFirestoreルールで管理権限に限定し、Functionsは作成時にも3列の重複・欠落・完了列との兼用を検査する。サムネ画像はDiscord投稿のリンクを保持するため、Storageルールの変更は不要。日付は動画依頼フォーム内で入力し、共通の日付部品とNext.js設定は従来どおりとする。

## 影響・制約

動画依頼画面、カテゴリ設定、Firebase Functions、Firestoreルール・索引、既存Botの受付、シードデータを更新する。移行時はチーム別に列とDiscord接続先を設定する。Discord投稿後に処理が停止した場合は部分送信が残り得るため、作成済みスレッド数・理由・リンクをカードに表示する。

## 根拠・用語

PR #232 のレビューに基づき、チーム独自の列名や他用途のBotへの依存を解消する。ロールはPR #258の2ロール方式（`member` / `staff`）に合わせる。「動画依頼」を共通用語に追加する。
