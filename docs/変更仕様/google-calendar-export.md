# Google カレンダー連携の転換（ミラー廃止 → チーム予定の書き出し） 変更仕様

Issue: #208

## 背景・目的

Google カレンダー連携の方向を転換する。

- **やめること**: メンバーの Google カレンダー予定をチーム配下へミラーする方式（`MemberCalendarEvent`、SC-019 系）と、自分の Google 予定の読み取り表示（`source: 'google'`）
- **やること**: RisukeruGG のカレンダーにはチームの予定だけを置く。「Google カレンダーに書き出す」ボタンを押すと Google の同意画面が開き、チームの予定が自分の Google カレンダーへ追加される（チーム → 個人の一方向）

## 決定事項

Issue #208 の論点に対する決定。★ はユーザー確認済み、それ以外は本仕様での既定。

| # | 論点 | 決定 |
| - | ---- | ---- |
| 1 | 一回限りか継続同期か | ★ **一回限りの書き出し**。ボタン押下時点の予定を流し込む。以後の変更は再度ボタンを押すと反映される（再書き出し）。サーバー側の処理・リフレッシュトークン保管は持たない |
| 2 | iCal 購読 URL | 採用しない |
| 3 | スコープ | `https://www.googleapis.com/auth/calendar.app.created`（アプリが作成した副カレンダーとその予定だけを扱える）。ユーザーの既存予定は読めない・触れない |
| 4 | 専用カレンダーか primary か | **専用の副カレンダー**「RisukeruGG - {チーム名}」をチームごとに 1 つ作る。primary には書かない |
| 5 | 対象の予定 | ★ **チームの全予定**（`participantIds` で絞らない）。範囲は「書き出し当日 0:00（JST）より後に終了する予定」。過去分は入れない。ブリーフの公開予定日・工程締切は対象外 |
| 6 | 対応づけ | Google イベントの `extendedProperties.private.risukeruScheduleId` に `scheduleId` を持たせる。Firestore に予定単位の対応表は持たない |
| 7 | 逆方向の編集 | 取り込まない。Google 側での変更は次回の書き出しで上書きされる。説明文の末尾に「この予定は RisukeruGG から書き出されたものです。編集は RisukeruGG で行ってください」を付ける |
| 8 | 通知の重複 | `reminders: { useDefault: false, overrides: [] }` で Google 側の通知を付けない（締切前の通知は Discord が担う） |
| 9 | 失敗の見せ方 | 同意の拒否・トークン取得失敗・API エラーは画面上にエラー表示する。一部の予定だけ失敗した場合は「N 件中 M 件を書き出せませんでした」と件数を出し、再実行を促す。サイレント失敗させない |
| 10 | ボタンの置き場 | スケジュール画面。PC はヘッダーのボタン、モバイルは ⋯ メニュー。対象はアクティブチーム。複数チーム所属時はチームを切り替えてそれぞれ書き出す |
| 11 | 自分の Google 予定の読み取り表示 | ★ **同時に廃止** |

### 継続同期を見送ったことによる制約

- RisukeruGG 側で予定を追加・変更・削除しても、Google カレンダーには自動で反映されない。反映には再書き出しが必要
- そのため UI には最終書き出し日時を表示し、再書き出しの導線を常に出しておく

## 仕様

### 書き出しの動作

1. ユーザーがスケジュール画面（PC はヘッダーのボタン、モバイルは ⋯ メニュー）から「Google カレンダーに書き出す」を押す（`operator` / `member` / `rom` すべて可。チーム側のデータは読むだけ）
2. `calendar.app.created` スコープを付けた Google 認可ポップアップを開き、アクセストークンを取得する
   - ログイン時にはカレンダースコープを要求しない（incremental auth）
   - トークンはその場の書き出しにだけ使い、localStorage や Firestore へ保存しない
3. 書き出し先カレンダーを決める
   - `users/{uid}.googleCalendarExports.{teamId}.calendarId` があり、Google 側に実在すればそれを使う
   - 無い、または Google 側で削除済み（404 / 410）なら、副カレンダー「RisukeruGG - {チーム名}」を新規作成し、予定を書き込む前に `calendarId` を保存する（`exportedAt` は未設定のまま）
4. 専用カレンダー上のイベントを一覧し、`risukeruScheduleId` で対象予定（当日 0:00（JST）より後に終了するチームの予定）と突き合わせる
   - Google 側に無い予定 → 追加
   - Google 側にあり、内容（タイトル・説明・開始・終了・通知なし）が違う予定 → RisukeruGG の内容で上書き。一致していれば何も送らない
   - Google 側にあるが RisukeruGG 側に無い（削除された）予定 → 当日 0:00（JST）より後に終了するものだけ削除。当日より前に終了したイベントには触れない（履歴として残る）
   - 同じ `risukeruScheduleId` のイベントが複数ある → 1 つだけ残して削除
   - `risukeruScheduleId` を持たないイベント（利用者が Google 側でこのカレンダーに足したもの）には触れない
5. 追加・更新・削除は 1 件ずつ順に送る。1 件の失敗で残りを止めず、失敗件数を数える
6. すべて成功したら `exportedAt` を更新し、追加・更新・削除の件数を表示する。1 件でも失敗したら `exportedAt` は更新せず、失敗件数を表示する

同じ操作を何度行っても結果は同じになる（冪等）。変更が無ければ Google へは一覧取得だけを送る。

### イベントへの対応づけ

| Google イベント | 値 |
| --------------- | -- |
| `summary` | `title` |
| `start` / `end` | `allDay: false` は `dateTime`（`timeZone: Asia/Tokyo`）。`allDay: true` は `date`（保存値が既に「開始日 0:00 〜 最終日翌日 0:00」の排他的境界なのでそのまま日付へ変換） |
| `description` | カテゴリ名・参加メンバーの表示名・コラボ相手（いずれも値がある場合のみ）、`description` 本文（Markdown のまま）、末尾に注意書き（決定事項 7） |
| `extendedProperties.private.risukeruScheduleId` | `scheduleId` |
| `reminders` | `{ useDefault: false, overrides: [] }` |

### 保持する状態

`users/{uid}` に次を追加する（正本: `docs/仕様・計画/user/model.md`）。

```
googleCalendarExports: {
  [teamId]: { calendarId: string, exportedAt: timestamp | null }
}
```

- `calendarId`: 再書き出し時に同じ専用副カレンダーへ書き込むために使う。アクセストークンを保存しない方式のため、Firestore に持たないと別の端末・ブラウザから再書き出ししたときに書き出し先を特定できず、副カレンダーが重複して作られる
- `exportedAt`: スケジュール画面の最終書き出し日時の表示に使う（自動同期しないので、いつの時点の内容が Google 側にあるかを利用者が判断する手がかりになる）。副カレンダーを作っただけで一度も書き出しが完了していない間は `null`
- 書き込みは本人のみ
- アカウント削除（ゴースト化）時に除去する（`deleteAccount` が `users/{uid}` をゴースト用の項目だけで置き換えるため、追加の処理は不要）。Google 側の副カレンダーは消さない（ユーザーの持ち物）
- チーム退出時も Google 側の副カレンダーは残る。不要ならユーザーが Google カレンダー上で削除する

### UI

画面モックは [Issue #208 のコメント](https://github.com/risuda-ze/RisukeruGG/issues/208#issuecomment-6962192267) にある（①〜⑪）。

- PC: カレンダーヘッダーの旧「メンバーの予定」ボタンの位置に「Google カレンダーに書き出す」ボタンを置く。書き出し済みならボタンの左に最終書き出し日時を出す
- モバイル: ⋯ メニューの「Googleカレンダーを接続 / 再接続」を「Google カレンダーに書き出す」に置き換える。書き出し済みなら項目の下段に最終書き出し日時を出す
- 「メンバーの予定」ボタン／メニュー項目、メンバー予定の詳細モーダル、Google 未接続バナー・認証切れバナーは削除する
- 書き出し中はボタンを無効にして進行表示（処理済み件数 / 全件数）を出し、二重実行を防ぐ。モバイルはヘッダーにボタンが無いので、ヘッダー直下に進行表示を出す
- 予定・カテゴリ・メンバーの読み込みが終わるまではボタンを無効にする（読み込み途中の一覧で書き出して Google 側の予定を消したり、説明からカテゴリ・参加メンバーが抜けたりしないため）
- 完了・失敗はカレンダーヘッダー直下のバナーで表示する（× で閉じる）。一部失敗・失敗時は最終書き出し日時を更新しない
- 書き出し中に別の画面へ移動しても書き出しは続け、スケジュール画面に戻ったときに進行または結果を表示する。結果は書き出したチームを表示しているときだけ出す（チームを切り替えると出さない）

| 状況 | 表示 | 再実行 |
| ---- | ---- | ------ |
| すべて成功 | Google カレンダー「{カレンダー名}」に書き出しました（追加 N・更新 N・削除 N） | なし |
| 一部失敗 | N 件中 M 件を書き出せませんでした。もう一度お試しください。 | あり |
| 同意の拒否・ポップアップを閉じた・Google 側で権限が無い（401 / 403） | Google カレンダーへのアクセスが許可されなかったため、書き出しを中止しました。 | なし |
| ログイン中と別の Google アカウントを選んだ | ログイン中のアカウント（{メールアドレス}）とは別の Google アカウントが選ばれました。同じアカウントでやり直してください。 | なし |
| ブラウザがポップアップを止めた | ポップアップがブロックされました。ブラウザでポップアップを許可してから、もう一度お試しください。 | あり |
| それ以外（通信・API エラー、状態の保存失敗） | Google カレンダーへの書き出しに失敗しました。時間をおいてもう一度お試しください。 | あり |

## 廃止・片付け

- 型・リポジトリ: `MemberCalendarEvent`、`src/lib/repositories/memberCalendars.ts`、`src/lib/googleCalendar.ts` の読み取り処理（`fetchGCalEvents`、`source: 'google'`）
- 認証: `src/stores/auth.ts` のログイン時 `calendar` スコープ要求、`gcal_token` の localStorage 保存・復元、ログイン時・チーム切り替え時のミラー保存、`googleAccessToken` ステート
- 画面: `schedule/page.tsx`・`MonthCalendar`・`WeekCalendar` のメンバー予定／Google 予定の表示
- AI: `src/lib/ai/systemPrompt.ts` と `AIChatPage.tsx` の「メンバーの予定」コンテキスト
- Functions: `syncGoogleCalendar`（常に空振りしている死んだコード）と `functions/src/index.ts` の export、`onUserCreate` の `googleCalendar` 初期化
- Firestore ルール: `memberCalendars` と `collectionGroup('events')` の定義
- データ: 既存の `teams/{teamId}/memberCalendars/**` と `users/{uid}.googleCalendar` を一度きりのスクリプトで削除し、適用後にスクリプトを除去する（既存方針）

## 実装計画

ブランチは `develop` 起点の `feature/`、マージ先は `develop`。各段階の後に `pnpm typecheck` / `pnpm lint` / `pnpm test` を実行する。

1. **廃止**: 上記「廃止・片付け」のコード・ルール・Functions を削除する。ログイン時のカレンダースコープ要求を外す。この時点でアプリはカレンダー連携なしで動作する
2. **書き出し**: 認可ポップアップでのトークン取得、専用カレンダーの作成、突き合わせと書き込み、`googleCalendarExports` の保存、UI（ボタン・進行表示・結果／エラー表示）。突き合わせ（追加・更新・削除の判定）と予定 → Google イベント変換は純関数にしてユニットテストを付ける
3. **データ削除**: 本番デプロイ後に `scripts/delete-member-calendars.mjs` を適用し、スクリプトを除去する（手順は `scripts/migration-runbook.md`）
4. **公開前対応**: プライバシーポリシー追記、OAuth 同意画面のスコープ差し替え

### 実装で決めたこと

- トークン取得は Firebase Auth の `reauthenticateWithPopup`（`GoogleAuthProvider` に `calendar.app.created` を `addScope`、`login_hint` にログイン中のメールアドレス）
- 使う Google カレンダー API は `calendars.insert`・`events.list`・`events.insert`・`events.update`（全体置き換え）・`events.delete`。カレンダーの実在確認は `events.list` の 404 / 410 で行う
- 追加・更新・削除は並列化せず 1 件ずつ送る。予定が数百件を超えて待ち時間が問題になったら、レート制限内で並列化する

### 本番の Google アカウントでの確認が必要なこと

実装時の確認はユニットテスト（Google API を代役に置き換え）までで、実際の Google カレンダーへの書き出しは未確認。公開前に次を確認する。

- `calendar.app.created` スコープで上記 5 つの API がすべて通ること。通らない操作があれば `calendar.events` 等への変更をこの仕様に戻して判断する
- 表示確認チェックリストの「Google カレンダー側」の各項目
