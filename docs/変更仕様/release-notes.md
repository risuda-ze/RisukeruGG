# バージョン表示とリリースノート画面 変更仕様

**作成日**: 2026-11-18
**状態**: 設計確定・未実装（Issue #216）
**正本**: [docs/仕様・計画/platform/](../仕様・計画/platform/README.md)（PF-004〜PF-011）

## 背景・目的

Web アプリは利用者が気づかないうちに更新される。いま動いているバージョンと、何が変わったかを利用者が確認できるようにする。

Issue #216 で決まっていること:

- アプリ内にバージョン情報を表示し、クリックするとリリースノートのページへ遷移する
- リリースノートは誰にでも公開できる内容とする（未ログインでも読める公開ページ）

## 仮決定

Issue に無い点は、最小の案を仮に選んだ。レビューで覆す場合は正本と本書を直す。

## スコープ外

次は作らない。必要になった時点で別 Issue とする。

- 「新着あり」バッジ、既読管理
- 更新の通知（Discord・メール・アプリ内）
- 多言語対応
- RSS / Atom フィード
- 管理画面からの編集、Firestore・CMS・GitHub API からの取得
- 過去バージョンの検索・絞り込み・ページ分割
- git タグ・GitHub Releases の作成、リリース作業の自動化

## リリース時の運用手順

リリース（`develop` → `main`）ごとに次を行う。利用者に見える変更が無いリリースでは 1〜3 を省く。

1. `develop` から `feature/release-v{version}` を切る
2. `package.json` の `version` を上げる（仮決定 #11）
3. `src/lib/releaseNotes.ts` の先頭に 1 件追加する。`date` は `main` へマージする予定日（JST）。原稿は下のテンプレートに従う
4. `pnpm test` が通ることを確認し、`develop` へ PR を出してマージする
5. `develop` → `main` のリリース PR を作る（merge commit）

リリース前に追加の変更が `develop` に入った場合は、未公開の先頭 1 件に追記してよい。公開済みの原稿は、誤記の訂正を除いて書き換えない。

### 原稿のテンプレート

```ts
{
  version: '0.2.0',
  date: '2026-12-01',
  summary: 'リリースノートを見られるようにしました。', // 任意
  added: ['個人設定の「アプリ情報」から、これまでの更新内容を確認できるようになりました。'],
  changed: [],
  fixed: [],
}
```

- 追加: 新しくできるようになったこと
- 変更: これまでの動きや見た目が変わったこと
- 修正: 不具合を直したこと（利用者から見えた症状で書く）
