# バージョン表示とリリースノート画面 変更仕様

**作成日**: 2026-11-18（2026-11-20 更新: 下書きは GitHub Releases、公開する原稿はコード内に持つ形に変更）
**状態**: 設計確定・未実装（Issue #216）
**正本**: [docs/仕様・計画/platform/](../仕様・計画/platform/README.md)（PF-004〜PF-011）

## 背景・目的

Web アプリは利用者が気づかないうちに更新される。いま動いているバージョンと、何が変わったかを利用者が確認できるようにする。

Issue #216 で決まっていること:

- アプリ内にバージョン情報を表示し、クリックするとリリースノートのページへ遷移する
- リリースノートは誰にでも公開できる内容とする（未ログインでも読める公開ページ）

## スコープ外

次は作らない。必要になった時点で別 Issue とする。

- 「新着あり」バッジ、既読管理
- 更新の通知（Discord・メール・アプリ内）
- 多言語対応
- RSS / Atom フィード
- 管理画面からの編集、Firestore・CMS・GitHub API からの取得
- 過去バージョンの検索・絞り込み・ページ分割
- リリース作業の自動化（下書きから原稿への自動転記、Release の自動作成・自動公開）

## リリース時の運用手順

### 変更を `develop` へマージしたとき（随時）

リリースノートに載せる変更（仮決定 #10）を `develop` へマージしたら、下書き Release に 1 行足す。

1. GitHub の Releases に下書きが無ければ作る（「Draft a new release」→ タイトル「次回リリース」→「Save draft」。タグは公開時に決めるので仮のままでよい）
2. 下のテンプレートの該当する見出しの下に 1 行足して「Save draft」

### リリースするとき（`develop` → `main`）

リリースノートに載せる変更が無いリリース（下書きが無い・空）では 1〜4 と 6 を省く。

1. `develop` から `feature/release-v{version}` を切る
2. `package.json` の `version` を上げる（仮決定 #11）
3. `src/lib/releaseNotes.ts` の先頭に 1 件追加する。`body` に下書き Release の本文を貼り、文体（仮決定 #9）を整える。`date` は `main` へマージする予定日（JST）
4. `pnpm test` が通ることを確認し、`develop` へ PR を出してマージする
5. `develop` → `main` のリリース PR を作ってマージする（merge commit）。このデプロイでリリースノートも出る
6. 下書き Release を開き、本文を 3 で整えた内容に合わせ、タグを `v{version}`、Target を `main`、タイトルを `v{version}` にして「Publish release」

### 原稿のテンプレート

下書き Release の本文と、コード内の `body` に共通。

```markdown
リリースノートを見られるようにしました。

### 追加

- 個人設定の「アプリ情報」から、これまでの更新内容を確認できるようになりました。

### 変更

- …

### 修正

- …

### セキュリティ

- …
```

- 冒頭の 1 文（ひとこと）は任意
- 追加: 新しくできるようになったこと
- 変更: これまでの動きや見た目が変わったこと
- 修正: 不具合を直したこと（利用者から見えた症状で書く。見えない不具合は「〜の不具合を修正しました」程度にとどめる）
- セキュリティ: セキュリティに関する変更（例: 「セキュリティに関する更新を行いました。」。脆弱性の具体的な内容や対象の部品名は書かない）
- 該当が無い見出しは消す

コード内では次の形で持つ。

```ts
{
  version: '0.2.0',
  date: '2026-12-01',
  body: `
リリースノートを見られるようにしました。

### 追加

- 個人設定の「アプリ情報」から、これまでの更新内容を確認できるようになりました。
`,
}
```

## 完了条件

- 未ログインで `/release-notes` が開ける。クローズドベータ中（`NEXT_PUBLIC_CLOSED_BETA=true`）でも待機画面にならない
