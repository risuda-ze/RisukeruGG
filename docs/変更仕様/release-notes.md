# バージョン表示とリリースノート画面 変更仕様

**作成日**: 2026-11-18（2026-11-20 更新: 原稿の置き場を GitHub Releases に変更）
**状態**: 設計確定・未実装（Issue #216）
**正本**: [docs/仕様・計画/platform/](../仕様・計画/platform/README.md)（PF-004〜PF-011）

## 背景・目的

Web アプリは利用者が気づかないうちに更新される。いま動いているバージョンと、何が変わったかを利用者が確認できるようにする。

Issue #216 で決まっていること:

- アプリ内にバージョン情報を表示し、クリックするとリリースノートのページへ遷移する
- リリースノートは誰にでも公開できる内容とする（未ログインでも読める公開ページ）

### レビューでの変更（2026-11-20）

初版は「原稿をリポジトリ内の TS 定数（`src/lib/releaseNotes.ts`）で持ち、ビルド時に静的生成する。git タグ・GitHub Releases は作らない」としていた。PR #224 のレビューで GitHub の Release 機能を使う方針になったため、次を入れ替えた。

| 初版 | 変更後 |
| --- | --- |
| 原稿は TS 定数。型で「追加」「変更」「修正」を強制 | 原稿は Release の本文（Markdown）。区分はテンプレートで揃える |
| ビルド時に静的生成。外部への通信なし | サーバー側で GitHub API から取得し、1 時間ごとに再生成。トークンが要る |
| 原稿の先頭 = `package.json` の `version` をユニットテストで保証 | 手順で合わせる。テストは応答の変換だけ |
| 原稿の変更は PR レビューを通る | GitHub の画面で直接編集する（レビューは通らない） |
| git タグ・GitHub Releases は作らない | Release の公開時に `v{version}` タグができる |

## スコープ外

次は作らない。必要になった時点で別 Issue とする。

- 「新着あり」バッジ、既読管理
- 更新の通知（Discord・メール・アプリ内）
- 多言語対応
- RSS / Atom フィード
- アプリ内の管理画面からの編集
- 過去バージョンの検索・絞り込み・ページ分割
- リリース作業の自動化（Release の自動作成、原稿の自動生成、Webhook による即時反映）

## リリース時の運用手順

### 変更を `develop` へマージしたとき（随時）

利用者に見える変更（仮決定 #10）を `develop` へマージしたら、下書き Release に 1 行足す。

1. GitHub の Releases に下書きが無ければ作る（「Draft a new release」→ タイトル「次回リリース」→「Save draft」。タグは公開時に決めるので仮のままでよい）
2. 下のテンプレートの該当する見出しの下に 1 行足して「Save draft」

### リリースするとき（`develop` → `main`）

利用者に見える変更が無いリリース（下書きが無い・空）では 1〜2 と 4 を省く。

1. `develop` から `feature/release-v{version}` を切り、`package.json` の `version` を上げる（仮決定 #11）
2. `develop` へ PR を出してマージする
3. `develop` → `main` のリリース PR を作ってマージする（merge commit）
4. 下書き Release を開き、タグを `v{version}`（`package.json` と同じ番号）、Target を `main`、タイトルを `v{version}` にして「Publish release」
5. 1 時間以内に `/release-notes` へ出ることを確認する

### 原稿のテンプレート

```markdown
リリースノートを見られるようにしました。

### 追加

- 個人設定の「アプリ情報」から、これまでの更新内容を確認できるようになりました。

### 変更

- …

### 修正

- …
```

- 冒頭の 1 文（ひとこと）は任意
- 追加: 新しくできるようになったこと
- 変更: これまでの動きや見た目が変わったこと
- 修正: 不具合を直したこと（利用者から見えた症状で書く）
- 該当が無い見出しは消す

### トークンの準備（初回と更新時）

1. GitHub の Settings → Developer settings → Fine-grained tokens で作る。Repository access は `risuda-ze/RisukeruGG` のみ、Permissions は Contents: Read-only のみ
2. Vercel の環境変数 `GITHUB_RELEASES_TOKEN`（Production）に設定し、再デプロイする
3. 有効期限を付けた場合は期限前に作り直す。期限が切れるとページは前回の内容のまま更新されなくなり、Vercel のログに取得失敗が出る
