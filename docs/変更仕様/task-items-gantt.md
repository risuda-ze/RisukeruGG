## 変更名

新タスク構造（親子タスク）の導入と、ガントチャート(β)画面の追加

## 目的

配信チームが、複数の動画・配信の作業が「いつからいつまで」重なっているかを 1 画面で見られるようにする。

現行は単発の作業をカンバン（`/tasks`）、動画 1 本の作業をブリーフと工程（`/briefs`）で別々に持ち、どちらも開始日を持たない。親子にできる 1 つのタスク構造へまとめ、その上にガントチャートを置く。

## 対象範囲

本書は段階の 1 つ目（β）を扱う。β では新しいコレクションに新しい画面から作ったタスクだけを扱い、既存の画面とデータには触れない。

- 含む
  - 新タスク構造（コレクション `taskItems`、コメント、変更の記録）と操作層
  - 進め方（プレイブック）からの親子タスクの一括生成
  - ガントチャート(β)画面（PC・モバイル）、タスクの作成、タスク詳細ドロワー
  - 進め方の工程定義への所要日数・カテゴリ既定値の追加
- 含まない（別 Issue）
  - ブリーフ機能の新タスク構造への置き換え（Discord スレッド・通知・ダイジェスト、AI ツール、`/team/[uid]` の「担当中の工程」）
  - 既存データ（`tasks`、`briefs`、`steps`）の移行と、旧画面（`/tasks`、`/briefs`）の削除
  - カレンダーの終日の持ち方をタスクに揃える修正
  - 一覧画面の機能向上、ダッシュボードの完了率の切り替え
  - 正本仕様・共通用語の全面更新

## 設計

### データモデル

#### `teams/{teamId}/taskItems/{itemId}`（新規）

型は `src/types/taskItems.ts` に新規に定義する。

| フィールド                       | 型                              | 用途                                                                        |
| -------------------------------- | ------------------------------- | --------------------------------------------------------------------------- |
| `id`                             | string                          | ドキュメント ID                                                             |
| `title`                          | string                          | タスク名（1〜100 文字）                                                     |
| `columnId`                       | string                          | 状態。`TaskStatus.id` を参照する                                            |
| `categoryId`                     | string \| null                  | カテゴリ。ガントでアイコン表示と検索に使う                                  |
| `description`                    | string \| null                  | 説明                                                                        |
| `assigneeId`                     | string \| null                  | 担当者の UID                                                                |
| `startAt`                        | timestamp \| null               | 開始日時。バーの始点                                                        |
| `dueAt`                          | timestamp \| null               | 締切日時。バーの終点                                                        |
| `parentId`                       | string \| null                  | 直近の親。最上位は null                                                     |
| `ancestorIds`                    | string[]                        | 最上位から直近の親までの ID。配下全体の取得と、祖先の日時を広げる処理に使う |
| `order`                          | number                          | 兄弟の中での並び順                                                          |
| `playbookId` / `playbookVersion` | string \| null / number \| null | 生成元の進め方と版。進め方から生成した親だけが持つ                          |
| `linkedScheduleId`               | string \| null                  | 関連するスケジュール                                                        |
| `createdBy`                      | string                          | 作成者の UID                                                                |
| `createdAt` / `updatedAt`        | timestamp                       |                                                                             |

制約

- `startAt` と `dueAt` は両方 null か、両方値を持つ。`startAt <= dueAt`
- 秒未満は 0 に切り捨てて保存する
- 親が日時を持つとき、日時を持つ子はすべて親の `startAt` 〜 `dueAt` の内側にある
- `ancestorIds` に自分の ID を含めない。親に選べるのは、自分と自分の配下以外のタスク
- 1 つの最上位タスクの配下は 200 件まで

#### `teams/{teamId}/taskItems/{itemId}/comments/{commentId}`（新規）

`StepComment` と同じ項目（`authorId` / `authorName` / `body` / `source` / `discordMessageId` / `createdAt`）。β では `source` は `web` のみ。

#### `teams/{teamId}/taskItemEvents/{eventId}`（新規）

変更の記録。タスクを削除しても記録が残るよう、タスクの配下ではなくチーム直下に置く。

| フィールド         | 型                                     | 用途                                                                                                                                                                              |
| ------------------ | -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `itemId`           | string                                 | 対象のタスク                                                                                                                                                                      |
| `rootId`           | string                                 | 対象の最上位タスク。親単位でまとめて読むために使う                                                                                                                                |
| `type`             | string                                 | `item.created` / `item.title_changed` / `item.status_changed` / `item.assignee_changed` / `item.dates_changed` / `item.category_changed` / `item.parent_changed` / `item.removed` |
| `before` / `after` | unknown                                | 変更前後                                                                                                                                                                          |
| `actorId`          | string \| null                         | 操作者の UID                                                                                                                                                                      |
| `source`           | `web` \| `discord` \| `system` \| `ai` | β では `web` のみ                                                                                                                                                                 |
| `createdAt`        | timestamp                              |                                                                                                                                                                                   |

追記のみ。親が自動で広がったときは、親に対する `item.dates_changed` も記録する。

#### `StepDef`（進め方の工程定義。既存に追加）

| フィールド          | 型                     | 用途                                                          |
| ------------------- | ---------------------- | ------------------------------------------------------------- |
| `durationDays`      | number（任意、1〜365） | 所要日数。生成する子の開始日時を決める。未設定は 1 として扱う |
| `defaultCategoryId` | string \| null（任意） | 生成する子のカテゴリ                                          |

既存の進め方は書き換えない。生成時に存在しないカテゴリは null にする。

#### 既存データの移行

不要（β は新しいコレクションだけを使う）。

### アクセス制御

`firestore.rules` に追加する。権限はクライアントの操作層と rules の両方で確認する。

| パス                                      | 読み取り       | 書き込み                                                        |
| ----------------------------------------- | -------------- | --------------------------------------------------------------- |
| `taskItems/{itemId}`                      | `isTeamMember` | `isOwnerOrEditor`                                               |
| `taskItems/{itemId}/comments/{commentId}` | `isTeamMember` | 作成は `isOwnerOrEditor`。更新・削除は `isTeamOwner` または本人 |
| `taskItemEvents/{eventId}`                | `isTeamMember` | 作成は `isOwnerOrEditor`。更新・削除は不可                      |

### インデックス

`firestore.indexes.json` に追加する。

| コレクション     | フィールド                      | 使うクエリ                                                                       |
| ---------------- | ------------------------------- | -------------------------------------------------------------------------------- |
| `taskItems`      | `startAt` 昇順、`dueAt` 昇順    | 表示範囲と交わるタスク（`startAt <= 範囲の終わり` かつ `dueAt >= 範囲の始まり`） |
| `taskItemEvents` | `itemId` 昇順、`createdAt` 降順 | タスク詳細の変更の記録                                                           |

2 フィールドの不等号を 1 クエリで使えることを、実装の最初に Emulator で確認する。使えない場合は `dueAt >= 範囲の始まり` だけをクエリにし、`startAt` の条件は画面側で絞る。

日時がないタスクは `dueAt == null` で取得する。配下の取得は `ancestorIds array-contains` を使う（単一フィールドの自動索引で足りる）。

### 処理の流れ

すべての書き込みは新しい操作層（`src/lib/taskItems/operations`）を通す。1 操作は「権限判定 → 読み込み → 計画 → 変更の記録 → commit」の順で、1 つの `writeBatch` にまとめる。commit が失敗したら何も保存せず、画面にエラーを表示する。

1. **作成**: 状態は `TaskStatus` の先頭（`order` 最小）、`order` は兄弟の末尾。親を指定した場合は `ancestorIds` を親から作る
2. **日時の変更**
   1. 片方だけ入力された場合は、もう片方を同じ日で補完する
   2. `startAt > dueAt` なら保存しない
   3. 子を持つタスクを、日時を持つ子より狭い範囲にする変更は保存しない
   4. 変更後の範囲が親からはみ出す場合、はみ出した側だけ親を広げる。さらに上の祖先からもはみ出すなら、同じように広げる
   5. 親を広げる場合は、保存前に確認ダイアログを出す。キャンセルなら何も保存しない
   6. タスクと、広げた祖先を同じ `writeBatch` で更新する
3. **状態の変更**: 対象と配下全員の `columnId` を同じ `writeBatch` で更新する
4. **親の付け替え**: 対象と配下全員の `parentId` / `ancestorIds` を更新する。新しい親からはみ出す場合は 2-4 と同じく広げる。付け替え後の最上位の配下が 200 件を超える場合は保存しない
5. **削除**: 対象・配下・それらのコメントを同じ `writeBatch` で削除する
6. **進め方から生成**
   1. 入力は、親のタイトル・親の締切・進め方
   2. 進め方の `leadDays` の最小値を `m` とする。各子の締切は「親の締切の日 −（`leadDays` − `m`）日」の 23:59:59
   3. 各子の開始は「締切の日 −（`durationDays` − 1）日」の 00:00:00
   4. 子の担当は `defaultAssigneeId`、カテゴリは `defaultCategoryId`、`order` は進め方の順
   5. 親の開始は子の開始の最小値、親の締切は入力値
   6. 親と子を同じ `writeBatch` で作成する
7. **カテゴリの削除**: 既存の `deleteCategory` に `taskItems` の `categoryId` を null にする処理を足す
8. **状態の削除**: 既存の `deleteColumn` に、その状態の `taskItems` を移行先の状態へ移す処理を足す

### ガント画面

- ルートは `/gantt`。サイドバー「メイン」に「ガントチャート(β)」を追加する
- PC
  - 左にタスクの列（タイトル・状態・開始日・締切、担当者のアバター、カテゴリのアイコン）、右に日単位の時間軸
  - 行は最上位のタスクと、その下に `order` 順の子。親の行で開閉できる
  - バーは `startAt` の日から `dueAt` の日まで。色は `TaskStatus.color`
  - 今日の位置に縦線を引く
  - 列見出しのクリックで昇順、もう一度で降順に並び替える
- モバイル（`md` 未満）
  - 縦が日付、横がタスク。タスク 1 件が 1 列になり、バーは縦に伸びる
  - 親の列の右に子の列を並べる。親の見出しのタップで子の列を開閉する
- 読み込み
  - 初回は当日の前後 1 か月。時間軸の端まで来たら、その方向に 1 か月広げる
  - 読み込み済みの範囲全体を 1 本の購読で取り、範囲が広がるたびに張り替える
- 検索は読み込み済みのデータを画面側で絞る
- 行（モバイルでは列の見出し）のクリックでタスク詳細ドロワーを開く
- 「タスクを追加」から、単発タスクの作成と、進め方からの生成を選べる

### タスク詳細ドロワー

タイトル、状態、カテゴリ、担当者、開始・締切（終日ボタン付き）、説明、親タスク（付け替え）、子タスクの一覧と追加、コメント、変更の記録、削除。

### 再利用

- `TaskStatus` / `Category` の購読とストア（`src/stores/` の既存のもの）
- 日付入力、アバター、ドロワーなどの共通コンポーネント（`src/components/ui/`）
- 進め方の購読と編集画面（`src/lib/repositories/briefs.ts`、`src/components/briefs/PlaybookEditor.tsx`）
- `date-fns`（JST の日付計算）

新規に作るもの: `taskItems` の型・Zod・リポジトリ・操作層・ストア、ガントの表示用の純関数（行の並び、バーの位置、検索）とコンポーネント。旧カンバン（`src/components/kanban/`、`src/lib/repositories/tasks.ts`）とブリーフ（`src/lib/briefs/`）のコードは import しない。進め方の読み取りだけは既存を使い、置き換えの Issue で移す。

### 互換性

- `/tasks`、`/briefs`、ダッシュボード、Discord 連携、AI チャットの動作とデータは変わらない
- 進め方に足す 2 項目は任意で、旧ブリーフの生成は無視する
- カテゴリ削除・状態削除は、対象のコレクションが 1 つ増える
- 段階リリース: β として公開する。旧画面は残す

## 制約・注意

- 日時は JST 基準で計算し、演算は `date-fns` を使う（NFR-010）
- 本番反映時に rules と索引のデプロイが要る。Functions の再デプロイは不要
- β の新タスクは Discord に連携せず、締切のリマインドも届かない。画面上で β であることを示す
- LIGHT プランの月次のタスク作成数に、β の新タスクは数えない（仮決定 17）
- カレンダーは終日の終わりを翌日 00:00:00（排他）で持ち、タスクは 23:59:59 で持つ。揃える修正は別 Issue

## ユーザーへの質問

根拠は Issue #211 のコメント（1 周目と、3〜6 周目のまとめ）。仮決定一覧のうち、特に確認したいものを挙げる。

1. **日時がないタスクの見せ方（仮決定 8）。** 以前の案は「ガントに出さず一覧にだけ出す」だったが、β には一覧画面がない。ガントに「日時未設定」として出す案にした。これでよいか
2. **親の状態変更の範囲（仮決定 10）。** 親を「作業中」に変えると、完了済みの子も「作業中」に戻る。完了にしたときだけ子へ反映する案もある
3. **プラン制限（仮決定 17）。** β の間、LIGHT の「タスク作成は当月 5 件」に新タスクを数えない。数える場合は、作成を Functions 経由にする必要がある
4. **Discord・リマインド（仮決定 24）。** β の新タスクは Discord に連携しない。β の間に通知が要るなら、置き換えの Issue を先に進める
5. **配下の件数の上限（仮決定 15）。** 1 つの最上位タスクの配下を 200 件までにする
6. **コレクション名（仮決定 1）。** `taskItems` でよいか
