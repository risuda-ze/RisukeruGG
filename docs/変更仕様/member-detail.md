# メンバー詳細（チーム管理画面の改良） 変更仕様

**作成日**: 2026-11-18
**状態**: 実装済み（仮決定を含む）（Issue #212。#204 から分離）
**正本**: [docs/仕様・計画/team/](../仕様・計画/team/README.md)（TE-014〜TE-017）

## 背景・目的

`/team` は 1 画面にメンバー一覧・チームの基本情報・危険ゾーン・別チーム参加が縦に並び、メンバーについて分かるのは名前・ロール・Discord 名だけになっている。「誰が何を担当している人か」「いま何の工程を抱えているか」を 1 か所で見られるようにする。

Issue #212 の「検討事項（1 周目）」はすべて未回答のため、**推奨案で仮決定**して本書に書く。仮決定は「仮決定一覧」に代替案とともに列挙し、レビューで覆す場合は正本と本書を直す。

## 全体方針

- **最小で作る（YAGNI）。** 追加する保存項目は 2 つだけ。新コレクション・新 Functions・新しい購読は作らない
- **プライベートな情報は出さない。** `User` 側の情報（`email` など）は表示しない。本人だけに見える項目も作らない
- **動的情報は既存データの絞り込みで出す。** 担当中の工程は既存の工程購読を担当者で絞るだけにする
- **仕様の詳細は正本に書く。** 本書は経緯・仮決定・実装の分割を管理し、要件・モデル・フローは正本を参照する

## 前提・依存

- **#219（権限ロールの置換。別 PR で設計中）に依存する。** #219 は権限ロールを「メンバー（全権限・保存値 `operator`）/ スタッフ（CRUD 可・管理不可・保存値 `staff`）」の 2 種類に置換し、`rom`（閲覧専用）を廃止する仮決定をしている
- 本書の以下の節では、管理権限を持つロールを設計時の名前 **オペレーター（`operator`）**、所属する全員を「メンバー」と書いている
- **#219 確定後の読み替え（2026-11-21）**: 正本と画面は #219 の用語に合わせた。管理権限ロール（保存値 `operator`、変更なし）は「メンバー」、所属する全員は仕様書で「所属者」、画面で「メンバー・スタッフ」と書く。画面名・タブ名も同じ（仮決定 15 を確定）。ロールバッジとロール変更の選択肢の表示名（オペレーター / ROM専）は #219 の実装 PR で変える
- #219 がどちらに決まっても本設計の権限は変わらない: 閲覧は所属する全ロール、編集は本人またはオペレーター
- #210（対応不可時間）は未実装。本設計は #210 の実装後にリンクを 1 本置くだけで、#210 を待たずに実装できる

## 各 PR の作業内容

ファイルの置き場所は既存の構成に合わせた目安で、実装時に調整してよい。

### PR A: 土台

- `TeamMember` に `duties: MemberDuty[]` / `note: string | null` を追加（`src/types/entities.ts`）。`toTeamMember` は旧ドキュメントを `[]` / `null` として読み、候補にない値は捨てる
- 担当分野の候補（コード値と表示名）と Zod スキーマを `src/lib/validations/team.ts` に追加
- `updateMemberProfile(teamId, memberId, { duties, note })` を `src/lib/repositories/teams.ts` に追加（`updateMemberDiscordUsername` と同じ形）
- `firestore.rules` の `members/{memberId}` に 2 項目の検証を追加（[model](../仕様・計画/team/model.md) の「Security Rules」）
- ユニットテスト: Zod（候補外・重複・101 字・改行）、ルール（本人 / オペレーター / 他人、候補外、長さ超過）

### PR B: タブと絞り込み

- `/team` を「メンバー」「チーム」の 2 タブに分ける。既存の各カードとダイアログはそのまま移す
- メンバータブに絞り込み（テキスト + 担当分野チップ）を追加
- メンバーカードに担当分野のチップと、詳細への遷移を追加
- チーム未参加時の表示は変更しない

### PR C: メンバー詳細

- `/team/[uid]` のページ（静的情報、担当中の工程、編集ダイアログ、見つからない場合の表示）
- 担当中の工程は `/briefs/mine` の絞り込み・並び替えを、対象 uid を引数に取る関数へ切り出して共用する
- Emulator のシードに担当分野・ひとことを追加、E2E

## E2E

1. `/team` を開くとメンバー・スタッフタブが出る。チームタブに切り替えると基本情報が出る
2. 担当分野のチップで絞り込むと、該当する所属者だけが残る
3. 一覧の行から詳細へ遷移し、担当分野・ひとこと・担当中の工程が出る
4. 自分の詳細で担当分野とひとことを編集して保存すると、詳細と一覧の行に反映される
5. メンバー（`operator`）以外で他人の詳細を開くと、編集ボタンが出ない

## 本番反映時の注意

- PR A のマージ後に `firebase deploy --only firestore:rules` が必要。未デプロイでも保存はできるが、値の検証が効かない
- インデックスの追加、Functions の再デプロイ、データ移行はない
