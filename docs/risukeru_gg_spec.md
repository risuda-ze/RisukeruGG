## 1. プロダクト概要

**アプリ名**: リスケるGG  
**キャッチコピー**: 撮影も、コラボも、編集もGGなスケジュールを  
**サブコピー**: 配信スケジュール、もうリスケしない。

ゲーム配信者（Twitch・YouTube）およびその制作チームを対象とした、**配信者特化型チームスケジュール管理アプリ**。配信枠の管理・コラボ調整・編集タスク管理を一元化し、配信者が本業（配信）に集中できる環境を提供する。

---

## 2. 解決すべき課題

### 2.1 現状の問題

| # | 課題 | 影響 |
|---|------|------|
| 1 | 配信スケジュールがチーム内で共有されていない | スタッフが配信日時を把握できず、作業の優先順位がつけられない |
| 2 | コラボ調整がDMや口頭で行われ、記録が残らない | 日程ミスや重複が発生しやすい |
| 3 | 動画編集・サムネ作成などの制作タスクが管理されていない | 締切漏れや手戻りが頻発する |
| 4 | ファンへの配信告知が手動で各プラットフォームに投稿される | 告知忘れ・投稿ミスが起きる |
| 5 | 汎用カレンダーツール（Googleカレンダー等）は配信業務に最適化されていない | 配信特有の情報（同時配信先、コラボ相手、アーカイブURL等）が管理できない |

### 2.2 リスケるGGが解決すること

- 配信スケジュールをチーム全員がリアルタイムで把握できる単一の情報源を提供する
- コラボ打診・日程調整・確定までのフローをアプリ内で完結させる
- 撮影・編集・サムネ・告知などの制作タスクをカンバン形式で可視化する
- 配信告知をワンクリックで複数プラットフォームに展開できる仕組みを提供する

## 3. ターゲットユーザー

### プライマリ

- **ゲーム配信者**（Twitch / YouTube）
- 登録者数 1,000〜100,000人規模（個人〜小規模チーム）
- スタッフ（編集者・マネージャー・台本ライター）を1〜5名抱えている

### セカンダリ

- 将来的にVtuber・雑談・エンタメ系配信者にも展開可能な設計とする

## 5. 機能一覧

### 5.1 MVP（フェーズ1）に含める機能

#### 認証・ユーザー管理

- Googleアカウントによるソーシャルログイン
- メールアドレス・パスワード認証
- チームへの招待（メールリンク）
- ロール設定（オーナー / 編集者 / 閲覧者）

#### スケジュール管理

- 配信枠の作成・編集・削除
  - 入力項目: タイトル・日時・配信先（YouTube / Twitch / 両方）・概要・タグ
- 週カレンダービュー・月カレンダービュー切り替え
- チーム全員がリアルタイムで予定を閲覧できる共有カレンダー
- 配信枠のステータス管理（予定 / LIVE中 / 終了 / キャンセル）

#### コラボ調整

- コラボ打診の送受信（アプリ内通知）
- 候補日程の提示と返答（OK / NG / 日程調整）
- 確定したコラボ枠の自動カレンダー登録

#### タスク管理（カンバン）

- カンバンボード（TODO / 進行中 / 完了）
- タスク作成: タイトル・担当者・締切・カテゴリ（撮影 / 編集 / サムネ / 告知 / その他）
- タスクへのメンバーアサイン
- タスクのドラッグ&ドロップによるステータス変更（PCのみ、スマホはボタン操作）

#### チーム管理

- メンバー一覧と稼働ステータス表示
- メンバーごとのタスク確認
- チーム招待・ロール変更・削除

#### 通知

| 通知種別 | LIGHTプラン | PARTYプラン |
|----------|-------------|-------------|
| LIVEリマインダー（システム通知） | ✓ あり | ✓ あり |
| コラボ返答通知 | ✕ なし | ✓ あり |
| タスク更新通知 | ✕ なし | ✓ あり |
| プッシュ通知（PWA） | ✕ なし | ✓ あり |

### 5.2 料金プラン

#### LIGHTプラン（無料）

| 機能 | 内容 |
|------|------|
| 料金 | ¥0 / 月（永続無料） |
| メンバー数 | 2人まで |
| スケジュール登録 | 無制限 |
| タスク管理 | 月5件まで |
| コラボ調整 | 月3件まで |
| 通知 | LIVEリマインダーのみ（システム通知） |
| バナー広告 | あり |

#### PARTYプラン（有料）

| 機能 | 内容 |
|------|------|
| 料金 | ¥1,500 / 人・月（メンバー各自が個別決済） |
| メンバー数 | 無制限 |
| スケジュール登録 | 無制限 |
| タスク管理 | 無制限 |
| コラボ調整 | 無制限 |
| 通知 | 全種類（LIVEリマインダー・コラボ返答・タスク更新） |
| バナー広告 | なし |
| 無料トライアル | 14日間 |

#### 決済方式

- メンバー個別シート課金（Stripe使用予定）
- チームオーナーが招待 → 各メンバーが自分のカードで支払い
- 支払い済みメンバーのみPARTYプランの機能を利用可能
- 未払いメンバーはLIGHTプランとして扱う

### 5.3 フェーズ2以降に追加予定の機能

- YouTube / Twitch API 連携（配信枠の自動取得・同期）

## 6. 技術スタック

### 6.1 フロントエンド

| 項目 | 選定技術 | 理由 |
|------|----------|------|
| フレームワーク | **Next.js 14（App Router）** | PC・Android 両対応をPWA1本で実現。SSRによるSEO対応も可能 |
| 言語 | TypeScript | 型安全性の確保・チーム開発での保守性向上 |
| スタイリング | Tailwind CSS | ユーティリティクラスで高速UI実装。デザイントークンとの親和性が高い |
| 状態管理 | Zustand | 軽量でボイラープレートが少ない。Firestoreリアルタイム同期との相性が良い |
| カレンダーUI | react-big-calendar | 週・月表示の実績あるライブラリ |
| カンバンUI | @hello-pangea/dnd | react-beautiful-dndの後継。ドラッグ&ドロップ対応 |
| PWA対応 | next-pwa | Service Worker・ホーム画面追加・プッシュ通知を実現 |

### 6.2 バックエンド（BaaS）

| 項目 | 選定技術 | 理由 |
|------|----------|------|
| 認証 | **Firebase Authentication** | Google / メール認証を最小工数で実装。無料枠内で運用可能 |
| データベース | **Cloud Firestore** | リアルタイム同期でチーム全員の予定が即時反映される。サーバー不要 |
| ファイルストレージ | Firebase Storage | アバター画像・サムネイルプレビュー等の保存（無料枠5GB） |
| サーバーレス処理 | Firebase Cloud Functions | 通知送信・コラボ打診フロー等のサーバーサイド処理 |
| プッシュ通知 | Firebase Cloud Messaging（FCM） | PWAプッシュ通知の配信 |

### 6.3 インフラ・デプロイ

| 項目 | 選定技術 |
|------|----------|
| ホスティング | Vercel（Next.js最適化） |
| ドメイン | 未定（独自ドメイン取得予定） |
| CI/CD | GitHub Actions（lint / build / deploy） |
| バージョン管理 | GitHub |

### 6.4 開発ツール

| 項目 | 選定技術 |
|------|----------|
| パッケージマネージャー | pnpm |
| Linter / Formatter | ESLint + Prettier |
| テスト | Vitest（ユニット）・Playwright（E2E） |
| 環境変数管理 | `.env.local`（Vercel Environment Variables） |

## 7. 最低要件（動作環境）

### 7.1 対応プラットフォーム

| プラットフォーム | 対応方法 | 優先度 |
|-----------------|----------|--------|
| PC（ブラウザ） | Next.js Webアプリ | 最優先 |
| Android（ブラウザ） | レスポンシブ対応 | 最優先 |
| Android（アプリ的利用） | PWA（ホーム画面追加）| 最優先 |
| iOS（Safari） | PWA対応（一部制限あり） | フェーズ2 |
| iOS ネイティブアプリ | React Native / Expo移行 | フェーズ3以降 |
| Android ネイティブアプリ | React Native / Expo移行 | フェーズ3以降 |

### 7.2 ブラウザ対応

| ブラウザ | 対応バージョン |
|----------|---------------|
| Google Chrome | 最新2バージョン |
| Microsoft Edge | 最新2バージョン |
| Firefox | 最新2バージョン |
| Safari（iOS） | 16以上（フェーズ2） |
| Android Chrome | 最新2バージョン |

### 7.3 レスポンシブ対応ブレークポイント

| ブレークポイント | 対象 | レイアウト |
|-----------------|------|------------|
| `< 640px` | スマートフォン | シングルカラム・ボトムナビゲーション |
| `640px〜1024px` | タブレット | 2カラム・サイドバー折りたたみ |
| `> 1024px` | PC | フルダッシュボード・サイドバー常時表示 |

### 7.4 パフォーマンス要件

- **初回表示（LCP）**: 3秒以内（モバイル4G回線）
- **インタラクション応答（FID/INP）**: 100ms以内
- **Firestore リアルタイム更新の反映**: 1秒以内
- **オフライン対応**: PWA Service Workerによる直近データのキャッシュ表示

### 7.5 セキュリティ要件

- Firebase Security Rules によるデータアクセス制御
  - チームメンバーのみ自チームのデータを読み書きできる
  - ロール（オーナー / 編集者 / 閲覧者）に応じた書き込み権限
- HTTPS通信の強制（Vercel デフォルト対応）
- 認証トークンの自動リフレッシュ（Firebase SDK標準機能）

## 8. データモデル（概要）

### Firestoreコレクション構造

```
teams/
  {teamId}/
    name: string
    ownerId: string
    createdAt: timestamp

    members/
      {userId}/
        role: "owner" | "editor" | "viewer"
        displayName: string
        avatarUrl: string
        status: "online" | "offline"

    schedules/
      {scheduleId}/
        title: string
        startAt: timestamp
        endAt: timestamp
        platform: "youtube" | "twitch" | "both"
        status: "planned" | "live" | "ended" | "cancelled"
        description: string
        tags: string[]
        createdBy: string
        collaborators: string[]   // userId[]

    tasks/
      {taskId}/
        title: string
        status: "todo" | "in_progress" | "done"
        category: "shooting" | "editing" | "thumbnail" | "announcement" | "other"
        assigneeId: string
        dueDate: timestamp
        createdBy: string
        createdAt: timestamp

    collabs/
      {collabId}/
        fromUserId: string
        toTeamId: string
        proposedDates: timestamp[]
        status: "pending" | "accepted" | "declined" | "rescheduling"
        confirmedDate: timestamp | null
        note: string

users/
  {userId}/
    displayName: string
    email: string
    avatarUrl: string
    teamIds: string[]
```

## 11. 非機能要件

### 可用性

- 目標稼働率: 99.5%以上（Vercel / Firebase のSLA準拠）
- 計画メンテナンスは深夜帯（JST 3:00〜5:00）に実施

### スケーラビリティ

- Firestoreはオートスケール対応のため、ユーザー増加に対してバックエンドのスケール対応は不要
- フェーズ1のFirebase無料枠（Sparkプラン）で最大数百チームまで運用可能と想定
- ユーザー増加に応じてBlaze（従量課金）プランへ移行

### アクセシビリティ

- WCAG 2.1 AA 準拠を目標
- キーボード操作によるナビゲーション対応
- スクリーンリーダー向けaria属性の付与

### 国際化（将来対応）

- フェーズ1は日本語のみ
- フェーズ2以降に `next-intl` による多言語対応（英語）を検討
