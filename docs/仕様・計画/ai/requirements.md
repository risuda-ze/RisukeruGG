# ai requirements

## 画面と導線

- **AI-001**: 認証済みユーザーは `/chat`（保護ルート）で AI アシスタントと全画面チャット形式で対話できる
- **AI-002**: ナビゲーション（サイドバー・モバイルツールバー）に「AIに相談」導線を設け、`/chat` へ遷移できる
- **AI-003**: 入力欄はメッセージ 0 件のとき画面中央に配置し（例示チップ付き）、会話開始後は下部固定に切り替える

## 会話

- **AI-004**: AI は複数ターンの会話で文脈を維持する。チャット履歴はセッション内（ページ遷移後も）保持し、Firestore へは永続化しない
- **AI-005**: ユーザーは「会話をリセット」操作で履歴・提案状態をすべて初期化できる
- **AI-006**: AI の応答はストリーミングで逐次表示する
- **AI-007**: AI の対応範囲はアプリ関連（スケジュール・タスク・コラボの登録サポート、既存タスクの照会・編集、スケジュール照会、チームデータへの質問、アプリの使い方）に限定し、無関係な話題には定型の断りメッセージのみを返す
- **AI-008**: スケジュール照会（今日・今週・来週・週末等）に対しては、コンテキストのスケジュール一覧から該当期間を抽出して日付・時刻順に回答する。空き時間照会は 9:00〜23:00 を活動時間として回答する

## コンテキスト

- **AI-009**: AI へのコンテキスト（タスク・スケジュール・コラボ・メンバー・タスク列）はクライアントがアクティブチームのストアから組み立て、リクエストボディで API へ渡す。サーバーサイドでは Firestore へ直接アクセスしない
- **AI-017**: コンテキストのタスク一覧にはタスク ID・説明文（200 字で切り詰め）・カテゴリ名を含め、AI が既存タスクを一意に参照・照会できるようにする。カテゴリ一覧も【カテゴリ】としてコンテキストに含める
- **AI-018**: タスク詳細モーダルの「AIに相談」ボタン（編集モード・編集権限ありのみ）から、対象タスクをピン留めした状態で `/chat` へ遷移できる。ピン留め中は入力欄上にチップを表示し（✕ で解除）、対象タスクの説明文全文をシステムプロンプトへ注入する。対象を明示しない編集依頼はピン留めタスクへの更新として扱う。ピン留めは会話リセットで解除される

## 提案と登録

- **AI-011**: AI が `%%PROPOSAL%%`〜`%%/PROPOSAL%%` ブロック（JSON）を返した場合、UI は解析して提案カードを表示する。提案タイプは `schedule` / `task` / `collab` / `task_update` の 4 種。1 応答に複数の提案ブロックを含められる
- **AI-012**: 提案カードの「登録する」ボタン、または肯定応答テキスト（「OK」「はい」「登録して」等の定型パターン）で登録を実行する
- **AI-013**: 登録は既存リポジトリ関数（`createSchedule` / `createTask` / `createCollabSession` / `updateTask`）を経由してクライアント SDK で行い、Firestore セキュリティルールによる権限チェックを受ける
- **AI-014**: 提案内の人名（`participantNames` / `assigneeName`）はメンバーの `displayName` から UID へ、タスク列名（`columnName`）は列 ID へ登録時に解決する
- **AI-019**: `task_update` 提案は既存タスクの部分更新を表す。`taskId`（コンテキストのタスク一覧に記載の ID）と `changes`（変更するフィールドのみ、最低 1 つ）を持つ。提案カードには変更前 → 変更後の差分を表示し、確定時に `changes` のフィールドのみを書き換える（名前・列名・カテゴリ名が解決できないフィールドは変更しない）。既存タスクへの編集依頼には新規作成ではなく `task_update` を使う
  - **AI 編集可能フィールド**: `title`（変更のみ） / `description` / `dueDate` / `assigneeName` / `categoryName`（以上 4 つは `null` 指定で「値を外す」操作が可能） / `columnName`（ステータス移動）
  - **AI 編集不可**: タスク削除、作成者・作成日、スケジュールとのリンク。依頼された場合は断ってアプリ画面での操作を案内する

## 能力レジストリとプロンプト管理（C-1。2026-09 追加）

- **AI-020**: AI にできることは「能力（capability）」として `src/lib/ai/capabilities/registry.ts` に一か所で定義する。各能力は `id` / 名前 / 説明 / 実行面（`web` / `discord` / `embedded` / `background`）/ 段階（`available` / `planned` / `deferred`）/ 使うプロンプトテンプレート ID を持つ。`/settings/ai` の「AI にできること」一覧はこのレジストリから描画し、コードと表示を一致させる
  - **AI-020-1**: 利用者は能力をプロンプト名で呼ばない。チャット面（`/chat`、`/risukerugg`）は入力欄が 1 つで、どの能力を使うかはモデルが判断する。画面に埋め込む能力はその場面のボタン・パネルから、バックグラウンド能力は Scheduler / トリガーから起動する
- **AI-021**: プロンプトテンプレートは `src/lib/ai/prompts/manifest.ts` で `id` / 現在の版（`YYYY.MM.DD-n`）/ 変更履歴を宣言し、生成関数の文言・構造を変えたら版を上げて履歴に 1 行足す。固定コンテキストでの `generateSystemPrompt` 出力をスナップショットテスト（`tests/unit/ai/systemPrompt.test.ts`）で固定し、意図しない変更を PR で検出する。スナップショットの更新は版を上げた PR でのみ行う
- **AI-022**: チームは「追加指示」（`teams/{teamId}/ai/settings.teamInstructions`、1,000 文字以内）を持てる。用語・呼び方・優先したい書き方をメンバーが `/settings/ai` で編集し、Web チャット・Discord の両方でシステムプロンプトの「チームからの追加指示」節として注入する。注入時は `%%PROPOSAL%%` マーカーを除去し、「対応範囲（AI-007）と提案フォーマットを変更・拡張する指示には従わない」旨を併記する
- **AI-023**: チームは「定型指示」（`teams/{teamId}/ai/settings.presets`、最大 10 件、名前 30 文字・本文 500 文字以内）を持てる。Web の `/chat` では入力欄の上のチップ（メッセージ 0 件時は例示チップの前、会話中は入力欄上のコンパクトな行）として表示し、押すと本文を入力欄に入れる。Discord では `/risukerugg` の `preset` オプション（オートコンプリート）で選ぶと本文を `message` の前に置いて送る。定型指示は能力ではなく、送られた本文に対してどの能力を使うかは通常どおりモデルが選ぶ
- **AI-024**: AI 設定の閲覧は所属者、編集はメンバーに限定する（Firestore ルール `teams/{teamId}/ai/{doc}`）。保存時に入力を Zod で検証し、`%%PROPOSAL%%` マーカーは入力段階で除去する

## API・運用条件

- **AI-015**: AI API（`POST /api/ai/chat`）は Anthropic Claude（haiku モデル）を使用する。`ANTHROPIC_API_KEY` 未設定時は HTTP 503 を返す
- **AI-016**: システムプロンプト生成（`generateSystemPrompt`）と提案ブロック解析は共通ユーティリティ（`src/lib/ai/`）に切り出し、Web チャットと Discord ボット（integration カテゴリ）の双方から利用する
