# ai flows

## 会話フロー

1. ユーザーがナビゲーションの「AIに相談」から `/chat` を開く
2. メッセージ 0 件の場合は中央配置の入力欄と例示チップを表示する
3. ユーザーがメッセージを送信すると、クライアントはアクティブチームのストアからコンテキスト（タスク・スケジュール・コラボ・メンバー・タスク列・メンバーの予定）を組み立て、会話履歴とともに `POST /api/ai/chat` へ送信する
4. API はシステムプロンプト（今日の日付・チームデータ入り）を生成し、Claude haiku のストリーミング応答を返す
5. クライアントは応答チャンクを逐次アシスタントメッセージへ追記して表示する
6. 会話開始後は入力欄を下部固定に切り替える

## 提案・登録フロー

1. AI 応答に `%%PROPOSAL%%` ブロックが含まれる場合、クライアントは JSON を解析して提案カード（タイトル・日時・担当等の詳細）を表示する。`task_update` の場合は対象タスクの現在値と比較した変更前 → 変更後の差分を表示する
2. ユーザーが「登録する」ボタンを押す、または肯定応答テキスト（「OK」「はい」等）を送信すると登録を実行する
3. 登録は提案タイプに応じて `createSchedule` / `createTask` / `createCollabSession` / `updateTask`（`task_update`）を呼び出す。人名は `displayName` から UID へ、列名は列 ID へ解決する。`task_update` は `changes` に含まれるフィールドのみ部分更新する
4. 複数提案がある場合はすべてを登録する
5. 成功時は提案カードを完了状態にし、失敗時はエラー状態を表示する

## タスク照会・編集フロー

1. ユーザーが既存タスクについて質問する（「このタスクどうなってる？」等）と、AI はコンテキストのタスク一覧（ID・ステータス・担当・期限・カテゴリ・説明文・直近コメント）から現状を回答する
2. ユーザーが既存タスクの編集を依頼する（「詳細をこう書き換えて」「期限を変えて」「担当を外して」「完了にして」等）と、AI は対象タスクの ID を指定した `task_update` 提案を返す。対象が曖昧な場合は提案前にどのタスクか確認する
3. 編集可能フィールドは AI-019 の定義に従う。コメント追加等の編集不可の操作を依頼された場合、AI は断ってアプリ画面での操作を案内する

## タスクピン留めフロー（タスク詳細から相談）

1. タスク詳細モーダルの「AIに相談」ボタン（編集モード・編集権限ありのみ）を押すと、対象タスクをピン留めした状態で `/chat` へ遷移する
2. ピン留め中は入力欄の上にタスク名チップを表示する。チップの ✕ で解除できる
3. ピン留め中はそのタスクの説明文全文をシステムプロンプトに注入し、対象を明示しない編集依頼はピン留めタスクへの `task_update` として扱う
4. ピン留めは会話リセットでも解除される

## リセットフロー

1. ユーザーが「会話をリセット」操作を行う
2. 会話履歴・提案状態・ローディング状態をすべて初期化する

## 範囲外質問の拒否フロー

1. ユーザーがアプリと無関係な話題（雑談・一般質問等）を送信する
2. AI はシステムプロンプトの対応範囲ルールに従い、定型の断りメッセージのみを返す
