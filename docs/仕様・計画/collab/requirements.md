# collab requirements

## コラボ日程調整

### コア機能

- **CO-001**: メンバーはコラボ日程調整セッションを作成可能。セッションにはタイトル・コラボ相手名（フリーテキスト）・候補日程（最低 1 件・最大 5 件）・有効期限（1〜30 日）を含む
- **CO-002**: セッション作成時に共有 URL を自動生成する。共有は Discord 等の SNS で手動実施し、メール自動送信は行わない
- **CO-003**: 共有 URL にアクセスしたコラボ相手は認証なしで各候補日時に対して OK / NG / 代替日提案を記録可能
- **CO-004**: 有効期限切れの共有 URL は「期限切れ」ページを表示する
- **CO-005**: 日程確定時に共有 URL は即時無効化され、打診側チームのカレンダーにコラボスケジュールエントリを自動登録する
- **CO-006**: コラボセッションのステータスは `open`（回答受付中）/ `confirmed`（確定）/ `expired`（期限切れ）/ `cancelled`（キャンセル）で管理する
- **CO-007**: メンバーはいつでもコラボセッションをキャンセル可能。共有 URL は無効化され、確定済みの場合はカレンダーエントリも削除する

### 表示・入力品質改善

- **CO-008**: コラボ詳細画面の候補日程は日時の昇順でソートして表示する
- **CO-009**: 公開送信フォームの候補日程も日時の昇順で表示する
- **CO-010**: `CollabForm` の `proposedDates` は ISO 8601 UTC 文字列に変換してから Cloud Function へ渡す
- **CO-011**: `CollabResponseForm` の `alternativeDate` も ISO 8601 UTC 文字列に変換してから送信する
- **CO-012**: 公開コラボ送信フォームは 375px 幅のビューポートで横スクロールなしに表示・操作可能
- **CO-013**: 送信フォームでメモを入力して送信した場合、`respondToCollab` Cloud Function がそのメモを回答コメントとして `comments` 配列に追記する。追記は Cloud Function だけが行い、公開フォームのクライアントからは `comments` を書き込まない
- **CO-014**: 候補日程に編集・削除ボタンを表示する（`isOpen && canEdit` 時のみ）。削除時は `participantResponses` を再インデックスし、候補が 1 件の場合は削除ボタンを無効化する

### 再調整・複製

- **CO-015**: 確定済み（`confirmed`）コラボ詳細画面に「再調整する」ボタンを表示する
- **CO-016**: 「再調整する」実行前に確認ダイアログを表示する
- **CO-017**: 再調整実行時はステータスを `confirmed -> open`、`confirmedDate` を null、`linkedScheduleId` を null に変更し、確定時に自動作成されたスケジュールを削除する
- **CO-018**: 再調整後も候補日程・参加者・タイトル・内容・回答コメントを保持する
- **CO-019**: 確定済みコラボ詳細画面に「コピーして新規作成」ボタンを表示する
- **CO-020**: 「コピーして新規作成」では、タイトル・パートナー名・有効期限を引き継いだコラボ作成フォームを開く。元のコラボのステータスは変更しない

### コラボ調整画面 UI

- **CO-021**: TopBar の subtitle から件数テキストを削除し、「受信・送信したコラボ調整」見出し横に受信 / 送信件数を表示する
- **CO-022**: `collabs/page.tsx` の中央カラムに open セッションと confirmed セッションの両セクションを縦配置し、右サイドバーに新規作成フォームを配置する
- **CO-023**: 予定確定セクションの各カードに確定日時と「再調整する」ボタンを表示する
- **CO-024**: `CollabDetailModal` のオーバーレイ onClick 誤発火を mousedown ターゲット追跡で修正する
- **CO-025**: 公開コラボ送信フォームを Step1（名前入力）・Step2（日程回答）・Step3（コメント）の 3 ステップ構成に変更する
- **CO-026**: PC（768px 以上）では 3 ステップを横並びレイアウトで表示する
- **CO-027**: 回答完了後の画面に「このページを再度開くと回答を修正できます」旨のアナウンスを表示する
- **CO-028**: 公開フォームから「○○さんからの」テキストを削除する
- **CO-029**: コラボ詳細画面は、「候補日程」の下に「回答」の欄を置き、回答者（`participantResponses` のキー）ごとに 1 行で、回答者名、候補日程ごとの回答（OK / NG / 未定。日時の昇順）、その回答者の回答コメント（投稿日時と本文。古い順）を表示する。行は回答者名の昇順に並べる。回答コメントが無い回答者は回答だけを表示し、回答者が 1 人もいないときは「まだ回答はありません」と表示する。回答後に追加された候補日程など回答の無い候補日程と、`ok` / `ng` / `pending` 以外の値は「—」と表示する。「候補日程」の集計と「回答」の欄は、どちらも詳細画面を開いた時点の回答と回答コメントを表示し、開いている間に届いた回答は開き直したときに表示する。新規作成中は表示しない
- **CO-030**: コラボ詳細画面に、コメントの一覧・入力欄・返信の操作は置かない。チーム内のやり取りは Discord で行い、残しておく内容はコラボの内容（`content`）に書く。`comments` のうち、`authorId` が `participantResponses` のキーに無い要素は表示しない
- **CO-031**: コラボ調整画面の一覧の各行の削除ボタンは、メンバーのときだけ表示する。一覧の削除が失敗したときはトーストで理由を表示する。コラボ詳細画面の保存・調整を確定・削除・再調整、コラボ詳細ページの確定・キャンセルが失敗したときは、その画面に理由を表示し、画面は閉じない
- **CO-032**: コラボ詳細画面の保存（調整を確定の前に行う保存を含む）は、タイトル・内容・アイコンを毎回書き、参加者・候補日程・回答（`participantResponses`）は変更したときだけ書く。候補日程か回答（`proposedDates` / `participantResponses`）を書く保存は、文書の `updatedAt` が詳細画面を開いた時点と違えば保存せず、開き直すよう表示する。`updatedAt` の無い文書は、開いた時点にも無いときだけ一致とみなす。調整を確定の前の保存で止まったときは確定しない。保存が済んで確定だけが失敗したときは、保存したことと確定の失敗を表示し、開き直してから確定するよう表示する。候補日程を変えていない保存は `updatedAt` を比べず、開いている間に届いた回答・代替日程を上書きしない。保存の失敗の文言は、競合以外は「保存に失敗しました。時間をおいて再度お試しください」とする

## 注記

- 001 の基底仕様に従い、共有 URL は外部相手との日程調整専用であり、相手側のアカウント登録は前提にしない
- 001 の基底仕様に従い、日程確定後に共有 URL を再訪した場合は回答受付を再開せず、確定済みとして扱う
- コラボ作成数の月次上限判定は plan カテゴリの責務
