# schedule requirements

## 権限

- チーム権限名は `operator` / `member` / `rom` のコード値で表記する
- **SC-001**: `operator`・`member` はスケジュールエントリを CRUD できる
- **SC-002**: `rom` はスケジュールエントリを閲覧のみとし、CUD はできない

## エントリデータと保存

- **SC-003**: スケジュールエントリの必須項目: タイトル・開始日時・終了日時・配信プラットフォーム（YouTube/Twitch/両方）・説明・参加メンバー・コラボ相手（任意）
- **SC-004**: 動画投稿予定エントリには紐付くタスクの進捗フィールドを追加
- **SC-005**: スケジュールエントリの保存後、チームの全メンバーに 1 秒以内に反映
- **SC-010**: スケジュール作成フォームは「終日」ボタンを提供し、`allDay: true` フラグで開始・終了を同日の 00:00:00 に統一保存する
- **SC-011**: 開始日時入力時、終了日時が未設定の場合は自動的に 2 時間後を設定する
- **SC-013**: フォームを「確定」以外の操作で閉じた場合、入力内容を自動保存し次回起動時に復元する

## カレンダー表示

- **SC-006**: カレンダーは週ビューと月ビューを切り替えて表示
- **SC-006-1**: 週ビュー・月ビューは日曜始まり（spec 003 追加）
- **SC-007**: 同時間帯に複数エントリが存在する場合は視覚的に重複を示す（ブロックはしない）

## Google カレンダー書き出し

- **SC-008**: チームメンバー（`operator` / `member` / `rom`）は、スケジュール画面の「Google カレンダーに書き出す」操作で、アクティブチームの予定を自分の Google カレンダーへ書き出せる。方向はチーム → 個人の一方向で、一回限りの書き出しとする（以後の変更は再書き出しで反映する。自動同期はしない）
- **SC-008-1**: 書き出しの失敗（同意の拒否・トークン取得失敗・API エラー）は画面上にエラー表示する。一部の予定だけ失敗した場合は失敗件数を表示し再実行を促す。サイレント失敗は不可
- **SC-008-2**: カレンダー権限はログイン時には要求せず、書き出し操作時にのみ要求する。スコープは `calendar.app.created`（アプリが作成したカレンダーのみ）とし、取得したアクセストークンは保存しない
- **SC-008-3**: 書き出し先はチームごとの専用副カレンダー「RisukeruGG - {チーム名}」とし、ユーザーの primary カレンダーには書き込まない
- **SC-008-4**: 書き出し対象はチームの全予定のうち、書き出し当日 0:00（JST）以降に終了するものとする。ブリーフの公開予定日・工程締切は対象外
- **SC-008-5**: 再書き出しは冪等とし、専用カレンダー上の対象期間のイベントを追加・上書き・削除して現在のチーム予定と一致させる。Google 側での編集は取り込まず上書きする。利用者が Google 側で専用カレンダーに追加したイベントと、当日より前に終了したイベントには触れない。書き出した予定の説明文には RisukeruGG で編集する旨を記載する
- **SC-008-6**: 書き出した予定には Google カレンダー側の通知を設定しない
- **SC-008-7**: 書き出し済みの場合、最終書き出し日時を表示する
- **SC-008-8**: RisukeruGG のカレンダーにはチームの予定だけを表示する。ユーザー個人や他メンバーの Google カレンダー予定は読み取らない・表示しない

## 詳細 UI と入力コンポーネント

- **SC-012**: スケジュールの説明フィールドはマークダウン記法をサポート。閲覧時は `MarkdownView` でレンダリング、編集時は `Textarea` コンポーネントを使用（spec 003 追加 / spec 007 更新）
- **SC-014**: `DateTimeInput` は `type="date"` と `type="time"` の 2 input に分割してブラウザ非依存を実現（spec 007 更新）

## スケジュール複製新規作成

- **SC-015**: `operator`・`member` はスケジュール詳細モーダルから既存スケジュールを参照して複製し、新規スケジュール作成を開始できる
- **SC-016**: 複製開始時は `title`、`startAt`、`endAt`、`allDay`、`platform`、`description`、`participantIds` を新規作成フォームの初期値として引き継ぐ
- **SC-017**: 複製保存時は新しい `scheduleId` を発行し、`id` と `version` は新規スケジュールとして再生成する。参照元 ID を保持する恒久的なフィールドは追加しない
- **SC-018**: 複製新規作成で開いたフォームは参照元の初期値を優先し、通常の作成・編集フローで保持している未確定下書きはそのまま上書きしない

## カレンダー UI 改善

- **C-1**: スケジュールページの TopBar 内「予定を追加」ボタンを削除（日付クリックによる新規作成は維持）
- **C-2**: MonthCalendar の曜日ヘッダー行高さを `py-2 → py-1` に縮小し、ナビバーの `border-b` を除去してシームレスに表示
- **C-3**: 日付番号エリア（`DATE_H`）の高さを縮小し、イベントカードの表示領域を拡大
- **C-4**: 単日カード（`text-[10px]`）・複数日バー（`text-[11px]`）のフォントサイズを 1〜2 段階拡大
- **C-5**: 複数日イベントバーのタイトルを `text-center → text-left` に変更
- **C-6**: 詳細モーダルの説明フィールドから MarkdownEditor（プレビュー/編集切替）を廃止し `Textarea` + `MarkdownView` に分離
- **C-7**: 詳細モーダルをドラッグで移動・右下コーナーのリサイズハンドルでリサイズ可能（PC のみ）。モーダルを開くたびに画面中央にリセット
- **F-1**: 複数日イベントバーに単日カードと同等の余白（`px-1`）を適用
- **F-2**: `DateTimeInput` の `datetime-local` を `date` + `time` の 2 input に分割（Edge 互換性問題の根本解決）
- **F-3**: 複数日イベントバーの日付（`MM/dd`）表示を削除し、時間とタイトルのみ表示
- **F-4**: `MAX_TRACKS = 2` を超えた複数日イベントを「+n件」バッジで表示（クリック不可）
- **F-5**: ホバーツールチップのパネル幅を 240 → 360 に拡大。Y 座標が画面下半分なら上向き、上半分なら下向きに表示
- **A-1**: MonthCalendar のグリッドコンテナ背景を `bg-surface`（#11112a）→ `bg-bg`（#0a0a18）に変更
- **A-2**: リサイズハンドルに SVG グリップ記号（2 本の斜線）を表示
- **A-3**: 詳細モーダルの閲覧時説明を `MarkdownView` によるレンダリングに変更
