# ui requirements

## サイドバー

- **UI-001**: サイドバーはトグルボタンで 260px（展開）↔ 72px（折りたたみ）を切り替える
- **UI-002**: サイドバーの「メイン」「チーム管理」「各種連携」の各セクションはクリックで展開 / 収納できる
- **UI-003**: サイドバーの折りたたみ状態は localStorage に永続化し、リロード後も維持する
- **UI-004**: サイドバーのナビゲーションアイコンは Google Material Icons を使用する
- **UI-005**: サイドバーのアプリロゴアイコンをクリックすると `/dashboard` に遷移する
- **UI-012**: サイドバーのアクティブ状態は現在のパスに最も長く一致する 1 項目のみを対象にする。`/settings/profile` 表示時に `/settings` と `/settings/profile` を同時にアクティブ表示してはならない
- **UI-027**: サイドバー「メイン」の「タスク管理」の直下に「タスク管理 v2」（`/briefs`）を置き、β バッジを添える。モバイルの「その他」ドロワーにも同項目を置く。ナビ項目は任意で `badge` 文字列を持てる
- **UI-028**: サイドバー「設定」の「カテゴリ設定」の直下に「AI設定」（`/settings/ai`）を置く。モバイルの「その他」ドロワーにも同項目を置く

## TopBar・通知導線

- **UI-010**: TopBar の通知ベルをクリックすると通知ドロップダウンを表示する
- **UI-011**: 通知ドロップダウンはドロップダウン外クリックで閉じる
- **UI-013**: 通知ドロップダウンは最大 4 件の通知プレビューを表示する
- **UI-014**: 未読通知がある場合、TopBar の通知ベルに未読件数バッジを表示する
- **UI-015**: 設定/通知画面では未削除の通知履歴を一覧表示する
- **UI-016**: 設定/通知画面では通知 1 件ごとの削除操作を提供する
- **UI-017**: 設定/通知画面では通知全件削除操作を提供する
- **UI-018**: 通知ドロップダウンには「すべて見る」によるページ遷移導線を設けない

## ページレイアウト規約（デザイン統一・T7）

デザインシステムは `src/app/globals.css` のデザイントークン（`--color-*` / `--primary-*` / `--radius-*` / `--shadow-*` ほか）とコンポーネントクラス（`.btn` / `.ds-card` / `.ds-badge` / `.navlink` 等）を正とする。全画面はこれに準拠し、独自スタイルを持たない。

- **UI-019（ページヘッダー）**: 保護ルート配下の各ページ上部には `TopBar`（`src/components/layout/TopBar.tsx`）を用いる。`title` を必須、画面の補足がある場合のみ `subtitle` を指定し、画面固有アクションは `children` に渡す。ページ独自のヘッダー実装を作らない。
- **UI-020（ページコンテナ）**: ページは外枠 `flex flex-col flex-1 overflow-hidden`、内側にスクロール領域 `flex-1 overflow-y-auto px-4 py-6 md:px-7` を置く。コンテンツ最大幅は用途に応じ `max-w-lg`（フォーム・オンボーディング）/ `max-w-2xl`（単一列一覧）/ `max-w-3xl`（設定）から選び、ボード系全幅画面（タスク・スケジュール）では最大幅を設けない。独自のページ余白（`p-6` 等）を使わない。
- **UI-021（余白スケール）**: 余白は Tailwind の 4px グリッド（`gap-*` / `space-y-*` / `p-*`）に統一する。セクション間は `space-y-4`〜`space-y-6`、カード内の見出しと本文は `mb-1`〜`mb-5` を基準とする。ピクセル直値（`px-[18px]` 等）は既存のカード内パディング規約に合わせる場合のみ許可する。
- **UI-022（カード規格の統一）**: カードは `Card` コンポーネント（`.ds-card`）に必須で統一する。標準 padding は 16px、角丸は `--radius-lg`（radius-lg）を用いる。カード外枠を画面ローカルのCSS（`.mcbcard` 等）や `bg-card`+`border`+`rounded-[*]` の手書きで再実装することは禁止する。カード間の差分は `Card` の明示的 props（`accent`＝左3pxステータスレール `primary`/`success`/`warning`/`danger` ・ `interactive`＝クリック可能ホバー ・ `raised` ・ `noPadding` ・ `hover`）のみで表現し、「2規格」を作らない。タイトル付きセクションは `CardHeader` を用いる。トースト・ポップオーバー・モーダル・ドロップダウンなどカードでない小要素は対象外。ドラッグ＆ドロップ等の制約で `Card` への載せ替えが高リスクな要素（タスクの `.tcard`、コラボ一覧の `.cbrow` 等）は、外枠の数値（radius-lg・padding 16px・border トークン・左レール3px）だけを `Card` 規格に一致させる。
- **UI-023（色トークン）**: 色は必ずデザイントークン（`var(--*)` または対応する Tailwind ユーティリティ `bg-surface` / `text-muted` / `border-border` 等）で指定する。ブランド・セマンティックカラーの生値（`#7F77DD` 等の旧ブランド紫、`rgba(226,53,57,...)` 等の旧ダンジャー赤）をハードコードしない。透過ティントはトークンの `*-dim` か `color-mix(in oklab, var(--token) N%, transparent)` で表現する。例外はモーダルのスクリム（近黒オーバーレイ）と第三者ブランド色（Discord `#5865F2` 等）およびユーザーが選択するカテゴリカラーのパレット値。
- **UI-024（角丸・ボタン・バッジ）**: 角丸は半径トークン（`--radius-sm 6px` / `--radius-md 10-12px` / `--radius-lg 16-18px`）のスケールに沿う。ボタンは `.btn`（または `Button`）、バッジは `.ds-badge`（または `Badge`）を用い、独自ボタン・独自バッジを実装しない。
- **UI-025（モーダル規約）**: ダイアログは `Modal`（`src/components/ui/Modal.tsx`）を用いる。フッターは右寄せで「キャンセル（secondary）→ 主アクション（primary/danger）」の順とする。全画面・大型の専用モーダル（タスク詳細・スケジュール・コラボ）は `globals.css` の `.task-modal` / `.smodal` / `.collab-modal` の各レスポンシブ規約に従う。
- **UI-026（タップターゲット）**: タップ可能なコントロールは 44px 以上の当たり判定を確保する（`.btn` は `min-height:44px` を既定で満たす）。375px 幅で主要操作のタップターゲットが 44px を下回らないこと。
