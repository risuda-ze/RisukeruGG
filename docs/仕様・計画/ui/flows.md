# ui flows

## サイドバー操作フロー

1. ユーザーが保護画面を開く
2. システムが `SidebarState` の `collapsed` を読み込み、展開状態または折りたたみ状態を復元する
3. 現在の `pathname` と `NavItem.href` 一覧から、最長一致ルールで `activeHref` を算出する
4. 対応するセクションを開き、該当する 1 項目だけをアクティブ表示する
5. ユーザーがトグルボタンを押すと、サイドバー幅を 260px ↔ 72px に切り替える
6. 新しい `collapsed` 状態を localStorage に保存する

## サイドバーセクション開閉フロー

1. ユーザーがサイドバーのセクションヘッダーをクリックする
2. 対象セクションが `openSections` に含まれているか判定する
3. 含まれていれば収納し、含まれていなければ展開する
4. 展開状態に応じて子ナビゲーション項目を表示または非表示にする

## サイドバーロゴ遷移フロー

1. ユーザーがサイドバー上部のアプリロゴアイコンをクリックする
2. システムが `/dashboard` へ遷移する
3. ダッシュボードを現在のアクティブ項目として表示する

## 通知ドロップダウンフロー

1. ユーザーが TopBar の通知ベルをクリックする
2. システムが通知ドロップダウンを開き、最大 4 件の通知プレビューを表示する
3. 未読通知がある場合は通知ベルに未読件数バッジを表示する
4. ユーザーがドロップダウン外をクリックすると、ドロップダウンを閉じる

## 設定/通知画面閲覧フロー

1. ユーザーが設定/通知画面を開く
2. システムが未削除の通知履歴を読み込み、一覧として表示する
3. システムが各通知の既読状態と時刻を表示する
4. ユーザーが対象通知を選択した場合は notification カテゴリのルールに従って既読化や詳細遷移を行う

## 設定/通知画面での通知 1 件削除フロー

1. ユーザーが設定/通知画面で自分の通知 1 件を選ぶ
2. ユーザーが削除操作を実行する
3. システムが対象通知を一覧から除外し、未読件数表示を再計算する

## 設定/通知画面での通知全件削除フロー

1. ユーザーが設定/通知画面で全件削除操作を実行する
2. システムが表示中の通知一覧を空状態へ更新する
3. システムが未読件数表示を 0 に再計算する
