# platform requirements

## PWA・オフライン

- **PF-001**: アプリは PWA として Android のホーム画面に追加でき、インストールプロンプトが表示される
- **PF-002**: Service Worker は直近のスケジュールデータをキャッシュし、オフライン時でも閲覧可能
- **PF-003**: オフライン時に書き込み操作を試みたユーザーには接続を要求するメッセージを表示

## バージョン表示・リリースノート（未実装）

- **PF-004**: アプリのバージョン番号は `package.json` の `version` を唯一の出どころとし、ビルド時に埋め込む。環境変数や実行時の取得は使わない
- **PF-005**: 個人設定（`/settings/profile`）の「アプリ情報」タブの「バージョン」行は `v{version}` を表示し、クリックすると `/release-notes` を別タブで開く。PC・モバイル共通でアプリ内の入口はこの 1 か所とする
- **PF-006**: `/release-notes` は未ログインでも閲覧できる公開ページとし、認証ガードと BetaGate の対象外とする（`(protected)` の外に置く）。LP フッターにリンクを置き、`sitemap.xml` に含める
- **PF-007**: リリースノートの原稿はリポジトリ内の `src/lib/releaseNotes.ts` に持ち、ビルド時に静的生成する。ビルド時・実行時とも GitHub を含む外部からの取得は行わず、取得用のトークンを持たない
- **PF-008**: リリースノートは全バージョンを 1 ページに新しい順で並べ、各バージョンに `#v{version}` のアンカーを付ける。1 件はバージョン・公開日・本文を表示する。本文は Markdown として描画し、生の HTML は描画しない
- **PF-009**: 原稿は誰にでも公開できる内容とする。利用者に見える変更だけを利用者向けの「です・ます」で「追加」「変更」「修正」の見出しに分けて書き、PR 番号・内部の名称・脆弱性の詳細・画像は載せない
- **PF-010**: 次回分の原稿の下書きは本リポジトリの GitHub Releases に下書き（draft）として 1 件だけ持ち、利用者に見える変更を `develop` へマージするたびに書き足す。リリース時は `develop` → `main` のリリース前に、`develop` 向けの PR で `version` を上げ、下書きの本文を原稿へ移す。`0.x` の間は追加・変更を含むリリースで minor、修正のみで patch を上げ、利用者に見える変更が無いリリースでは上げない。下書きは `main` へのマージ後にタグ `v{version}` で公開する
- **PF-011**: 原稿の先頭のバージョンが `package.json` の `version` と一致すること、バージョンが重複しないことをユニットテストで保証する
