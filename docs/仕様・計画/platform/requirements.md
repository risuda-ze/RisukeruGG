# platform requirements

## PWA・オフライン

- **PF-001**: アプリは PWA として Android のホーム画面に追加でき、インストールプロンプトが表示される
- **PF-002**: Service Worker は直近のスケジュールデータをキャッシュし、オフライン時でも閲覧可能
- **PF-003**: オフライン時に書き込み操作を試みたユーザーには接続を要求するメッセージを表示

## バージョン表示・リリースノート（未実装）

- **PF-004**: アプリのバージョン番号は `package.json` の `version` を唯一の出どころとし、ビルド時に埋め込む。環境変数や実行時の取得は使わない
- **PF-005**: 個人設定（`/settings/profile`）の「アプリ情報」タブの「バージョン」行は `v{version}` を表示し、クリックすると `/release-notes` を別タブで開く。PC・モバイル共通でアプリ内の入口はこの 1 か所とする
- **PF-006**: `/release-notes` は未ログインでも閲覧できる公開ページとし、認証ガードと BetaGate の対象外とする（`(protected)` の外に置く）。LP フッターにリンクを置き、`sitemap.xml` に含める
- **PF-007**: リリースノートの原稿は本リポジトリの GitHub Releases に置く。サーバー側で GitHub REST API から取得し、ページを 1 時間ごとに再生成する。ブラウザから GitHub は呼ばない。取得にはサーバー専用の環境変数 `GITHUB_RELEASES_TOKEN`（本リポジトリのみ・Contents の Read-only）を使う
- **PF-008**: リリースノートは公開済みの Release（下書き・プレリリースを除く。先頭 100 件まで）を 1 ページに新しい順で並べ、各バージョンに `#v{version}` のアンカーを付ける。1 件はバージョン・公開日（JST）・本文を表示する。本文は Markdown として描画し、生の HTML は描画しない
- **PF-009**: 原稿は誰にでも公開できる内容とする。利用者に見える変更だけを利用者向けの「です・ます」で「追加」「変更」「修正」の見出しに分けて書き、PR 番号・内部の名称・脆弱性の詳細・画像は載せない。GitHub の自動生成ノートは使わない
- **PF-010**: `version` は `develop` → `main` のリリース前に `develop` 向けの PR で上げる。Release は `main` へのマージ後に、タグ `v{version}`（`package.json` と同じ番号）・Target `main` で公開する。`0.x` の間は追加・変更を含むリリースで minor、修正のみで patch を上げ、利用者に見える変更が無いリリースでは上げず Release も作らない
- **PF-011**: `GITHUB_RELEASES_TOKEN` が未設定の環境では取得を行わず「リリースノートはまだありません」を表示する。設定済みで取得に失敗した場合は空表示にせずエラーとする（再生成の失敗時は前回の内容を表示し続ける）
