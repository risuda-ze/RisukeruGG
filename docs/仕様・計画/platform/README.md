# platform

PWA・オフラインカテゴリの詳細仕様です。

このディレクトリを、PWA 配布・ホーム画面追加・Service Worker・オフライン閲覧・接続断時の扱い・バージョン表示とリリースノートに関する唯一の詳細仕様として扱います。

## 対象範囲

- PWA 配布
- ホーム画面追加
- Service Worker
- オフライン閲覧
- 接続断時のユーザー通知
- バージョン表示とリリースノート（公開ページ `/release-notes`、コード内に持つ原稿、GitHub Releases に置く下書き、バージョンの上げ方）
- リリース時の Firebase へのデプロイとデータ移行（手順は [flows.md](./flows.md)、スクリプトの実行手順は `scripts/migration-runbook.md`）
- リリース時のキーの入れ替え（対象の一覧は [requirements.md](./requirements.md)、手順は [flows.md](./flows.md)）
- リリース時の開発環境の片付け（対象の一覧は [requirements.md](./requirements.md)）

## 対象外

- 認証方式やセッション維持
- タスク / スケジュール / コラボ各データの業務ルール
- 画面ごとの見た目やナビゲーション構造

## 他カテゴリとの境界

### user との境界

- platform は認証状態を保持せず、セッション状態や外部連携用の認証情報は user を参照する

### task / schedule / collab との境界

- platform は各データの業務意味や更新ルールを決めず、オフライン時の取得・表示・制御だけを扱う

### ui との境界

- platform はオフライン関連の動作前提を定義し、バナーやプロンプトの具体的な見た目は ui を参照する
- リリースノートを開くリンクは、個人設定「アプリ情報」のバージョン表示と LP フッターの 2 か所に置く。この 2 か所は platform で定義する。サイドバーやモバイルのメニューにはリリースノートの項目を追加しないため、ui のナビゲーション仕様は変わらない

## 読む順番

1. この README: platform カテゴリの責務と他カテゴリとの境界を把握する
2. [requirements.md](./requirements.md): PWA・オフラインの規範要件を確認する
3. [model.md](./model.md): キャッシュ対象や端末側状態の保持方針を確認する
4. [flows.md](./flows.md): インストール、オフライン閲覧、書き込み制御の流れを確認する

## 採用する後続仕様

- 現時点で platform カテゴリ固有の後続仕様分割はない
- 後続仕様が追加されるまでは、このディレクトリ内の最新記述を正とする
- PWA とオフラインの実装差分は platform カテゴリの最新記述を優先する
