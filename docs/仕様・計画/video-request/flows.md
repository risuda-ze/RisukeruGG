# 動画依頼の操作フロー

| 操作                   | 依頼カード・タスク                                             | Discord                                                                        |
| ---------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Discordへ送信          | 依頼と対象タスクを一括作成し、設定された送信待ち列へ配置       | Botが送信待ちを取得                                                            |
| スレッド作成成功       | 対象タスクを設定された制作中列へ移動                           | 編集は送信先チャンネルごとに1スレッド、サムネ有効時は専用チャンネルに1スレッド |
| 動画またはサムネを納品 | 対象だけ確認待ちになり、タスクが設定された納品確認待ち列へ移動 | 対象スレッドにお礼を投稿                                                       |
| 修正を依頼             | 対象だけ作業中へ戻る                                           | 対象スレッドに担当者メンション、修正内容、再納品ボタンを投稿                   |
| 承認                   | 対象だけ完了。完了列は状態名ではなく `role=done` で特定        | 対象スレッドに担当者メンションと承認メッセージを投稿                           |

編集の初回投稿には編集内容・プロマネ・共有事項と納品ボタンが載る。編集内容の直下には編集開始日・初稿納期・完パケ納期を箇条書きで載せる。サムネの初回投稿には仮タイトル・完パケ納期・編集スレッドへのリンクが載る。

### 動画の納品

「納品URLを追加・再納品」でURL（必須、最大1,000文字）と共有事項（任意、最大2,000文字）を送信する。表示はギガファイル便だが、入力判定はHTTP／HTTPSで始まるかどうか。カードには異なるURLが「納品ファイル1」「納品ファイル2」…と並ぶ。オーナー用の共有資料は別枠で、追加しても納品扱いにならない。

初回のお礼は「初稿の納品完了丸！ありがとうございます！」「確認しますのでお待ちください！」。2回目以降は「修正ファイルの納品ありがとうございます！」「さっそく確認します！」に変わる。どちらも納品URLと入力済みの共有事項を添える。カードには「納品ファイル1」「納品ファイル2」…としてURLを表示する。動画の納品結果には担当者メンションを付けず、修正依頼・承認通知は担当者をメンションする。

### サムネの納品

画像をスレッドに直接投稿し、投稿した本人が「サムネを納品」を押す。Botは直近100投稿から、押したボタンの投稿より後に本人が添付した画像を探す。対応スレッド・作業中の依頼に限り受け付け、再納品には前回より新しい画像投稿が必要。カードは最新のDiscord投稿へのリンクを保持する。

お礼の宛先は動画形式に設定されたサムネ担当者。**Aさんが画像を投稿してボタンを押し、担当者がBさんなら、Bさんにメンションする。** 初回は「サムネの納品ありがとう！」、前回の納品記録があれば「修正ありがとう！」。いずれも次の行は「確認するので待っててクレヨン」。確認待ちの間にもう一度押しても二重納品しない。

「サムネを承認して完了」は制作中（修正作業中を含む）と確認待ちで使える。画像の納品前でもサムネタスクを完了にし、専用スレッドへ承認を通知する。サムネの修正依頼は確認待ちのときだけ可能で、本文は1〜1,500文字。動画側は未完了時に修正・承認の操作を表示し、完了後は以前のボタンからの再納品を受け付けない。

## 送信後の編集と削除

スレッド作成済みの依頼を編集すると、変更した項目を対象ごとにまとめて既存スレッドへ投稿する。変更がゼロなら通知を作らない。

| 送信先             | 変更項目                                                                   |
| ------------------ | -------------------------------------------------------------------------- |
| 編集とサムネの両方 | タイトル、完パケ納期。タイトル変更時はスレッド名も更新                     |
| 編集のみ           | 担当編集者、動画の種類、編集内容、プロマネ、共有事項、編集開始日、初稿納期 |
| サムネのみ         | タイトル案（仮）                                                           |

担当変更時も既存の編集スレッドを使用する。通常のタスク削除で動画タスクを消すと、依頼カードと関連サムネタスクも削除する。サムネタスクだけを消すと、依頼とのサムネの紐付けを外して動画側を残す。Discordスレッドの削除は行わない。

## Discord連携の設定

1. チーム管理者がDiscord連携画面でリスケるGG Botを対象サーバーに接続する。動画依頼のカテゴリ設定で編集・サムネのチャンネルID、必要な担当者IDとタスク列を保存する。
2. Webの既存Interactions EndpointとFunctionsが同じDiscordアプリに接続する。Functionsは既存の `DISCORD_BOT_TOKEN` シークレットを使う。Web側でも同じBotのトークン、公開鍵、アプリIDを設定する。Botには対象チャンネルでの閲覧・公開スレッド作成・スレッド内の投稿・履歴閲覧を許可し、画像納品にはMessage Content Intentを有効にする。
3. 新規依頼の作成・編集・修正・承認をFirestoreトリガーで配送する。納品ボタン・入力フォームは既存の署名検証を通し、連携サーバーと依頼スレッドの一致を確認する。新規依頼は自宅PCを停止しても処理できる。

### Discord送信失敗と再送信

スレッド作成や初回投稿に失敗した場合、依頼カードに「送信失敗」、失敗理由、作成済みスレッド数を表示する。オペレーターはカードの「Discordへ再送信」から再実行できる。再送信ではFirestoreに保存済みのスレッドを再利用し、未作成のスレッドと未投稿の初回依頼だけを処理する。成功時は依頼を制作中へ移動し、失敗時は既存の理由を更新する。
