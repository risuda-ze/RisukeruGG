# team model

## モデル方針

Team は共同作業単位を表す。TeamMember はユーザーとチームの所属関係を表す。

このカテゴリでは、チーム管理とロール制御に直接関係する項目だけを正本化する。チーム参加可否の判定ルールは plan、初回ソロチームの起点となる認証フローは user カテゴリを参照する。

## Team

| フィールド    | 型 / 例   | 意味                                             |
| ------------- | --------- | ------------------------------------------------ |
| `id`          | string    | Firestore ドキュメント ID（自動生成）            |
| `name`        | string    | チーム名                                         |
| `teamCode`    | string    | チーム参加に使用する固有英数字コード             |
| `createdAt`   | timestamp | チーム作成日時                                   |

## TeamMember

| フィールド    | 型 / 例                         | 意味              |
| ------------- | ------------------------------- | ----------------- |
| `userId`      | string                          | Firebase Auth UID        |
| `teamId`      | string                          | 所属チームの ID          |
| `role`        | `member` \| `staff`             | チーム内ロール（`member` = メンバー、`staff` = スタッフ） |
| `displayName` | string                          | UI 表示に使う名前        |
| `avatarUrl`   | string \| null                  | アイコン画像 URL         |
| `plan`        | `light` \| `party`              | この所属者の現在プラン |
| `joinedAt`    | timestamp                       | チーム参加日時           |
| `discordUsername` | string \| null              | Discord のユーザー名（`@` の後ろの一意な名前）。メンション用に本人またはメンバーが任意登録（TE-012）。旧ドキュメントには存在せず null 扱い |
| `discordUserId`   | string \| null              | `discordUsername` をサーバー内検索で解決した Discord ユーザー ID のキャッシュ。Bot（Admin SDK）が書き込み、ユーザー名変更時にクライアントが null に戻す |
| `duties`          | string[]                    | 担当分野のコード値の配列（重複なし）。旧ドキュメントには存在せず `[]` 扱い。候補にない値は読み取り時に捨てる |
| `note`            | string \| null              | ひとこと（100 字以内・改行なし）。旧ドキュメントには存在せず null 扱い |

### 担当分野の候補（TE-014-1）

固定で、チームごとの追加・変更はできない。工程の「担当」（`Step.assigneeId`）や進め方の「役割」（`StepDef.roleLabel`）とは連動しない。

| コード値     | UI 表示名    |
| ------------ | ------------ |
| `cast`       | 出演         |
| `planning`   | 企画         |
| `edit`       | 編集         |
| `thumbnail`  | サムネ       |
| `moderation` | 配信サポート |
| `other`      | その他       |

### Security Rules（TE-014-3）

クライアントは更新の許可リスト（下記「業務ルール」）で `duties` / `note` を書ける。更新時に次の値を検証する。

- `duties` がある場合: list で、要素は候補のコード値のみ（`hasOnly`）、件数は 6 以下
- `note` がある場合: null、または 100 字以下の string

## ロール定義

| ロール   | コード値 | UI 表示名 | 権限                                                         |
| -------- | -------- | --------- | ------------------------------------------------------------ |
| メンバー | `member` | メンバー  | チームの全権限（設定・所属者管理・すべてのコンテンツの作成・編集・削除） |
| スタッフ | `staff`  | スタッフ  | スケジュールとブリーフの作成、自分が作成したものの編集・削除、担当する工程の完了。タスク・コラボ・進め方・カテゴリ・チーム設定は不可 |

- 閲覧専用のロールは持たない
- ロールを問わないチーム所属ユーザーの総称は「所属者」（`TeamMember`、`members` コレクション）。コード値 `member` はロール名であり、所属者の総称ではない

## 権限

「作成者」は `createdBy` が自分の uid と一致すること。Discord 経由（`'discord-bot'`）・システム作成・退会済み・記録なしは誰にも一致せず、メンバーのみが扱える。

| 対象 | 閲覧 | 作成 | 編集 | 削除 |
| --- | --- | --- | --- | --- |
| チーム設定・解散・チームコードのリセット・ロール変更・Kick | 所属者 | メンバー | メンバー | メンバー |
| Discord 連携 | メンバー | メンバー | メンバー | メンバー |
| AI 設定 | 所属者 | メンバー | メンバー | メンバー |
| 進め方（playbooks） | 所属者 | メンバー | メンバー | メンバー |
| カテゴリ・カンバン列 | 所属者 | メンバー | メンバー | メンバー |
| タスク | 所属者 | メンバー | メンバー | メンバー |
| コラボ（確定・取消を含む） | 所属者・外部参加者（URL トークン） | メンバー | メンバー | メンバー |
| スケジュール | 所属者 | 所属者 | メンバー、または作成者 | メンバー、または作成者 |
| ブリーフ | 所属者 | 所属者 | メンバー、または作成者 | メンバーのみ（配下の工程・差分・工程コメントも削除） |
| 工程（steps） | 所属者 | ブリーフの作成者、またはメンバー | ブリーフの作成者、またはメンバー。完了・状態変更は担当者本人も可 | ブリーフの作成者、またはメンバー |
| 工程コメント | 所属者 | 所属者 | 本人、またはメンバー | 本人、またはメンバー |
| 対応不可時間（unavailability） | 所属者 | 本人 | 本人 | 本人 |
| 対応不可コメント | 所属者 | 所属者 | 投稿者本人 | 投稿者本人、またはメンバー（退出したユーザーのコメントはメンバーのみ） |

- Discord 由来の操作（作成・コメント・工程ボタン）はロールを見ない
- 自分の Discord ユーザー名の登録とチームからの退出は、全ロールが本人分を行える

### 後方互換

`role` が `member` 以外の値（旧値・未知の値）は、読み取り時に `staff` として扱う（管理者にしない）。書き込みは常に `member` / `staff` を使用する。

## Firestore コレクション配置

```
teams/{teamId}                    ← Team ドキュメント
teams/{teamId}/members/{uid}      ← TeamMember ドキュメント
teamCodes/{teamCode}              ← チームコード → teamId の逆引きドキュメント
```

## 共通フィールド

ユーザーが作るドキュメント（`schedules` / `tasks` / `collabSessions` / `briefs` / `steps` / `playbooks` / `categories` / `taskStatuses`）は、次のフィールドを持つ。

| フィールド  | 型               | 意味                                                                                       |
| ----------- | ---------------- | ------------------------------------------------------------------------------------------ |
| `createdBy` | string \| null  | 作成者の uid。Discord 経由は `'discord-bot'`、システム作成は `'system'`。記録の無い既存データは未設定（null 扱い） |
| `createdAt` | timestamp        | 作成日時                                                                                   |
| `updatedAt` | timestamp        | 最終更新日時                                                                               |
| `updatedBy` | string \| null  | 最終更新者の uid                                                                           |

- クライアントからの作成は `createdBy` に本人の uid を必須とし、作成後の変更は禁止する
- 退会・アカウント削除で `createdBy` は書き換えない（認証できない uid は誰にも一致しないため、結果として作成者なしの扱いになる）

## 制約

- チームには少なくとも 1 人のメンバー（`member`）が必要（複数も可）。「最後のメンバー」の判定は `members` の `role` から求め、非正規化した UID リストは持たない
- `TeamMember` の作成・削除と `role` / `plan` の変更は Callable Function（Admin SDK）だけが行う。クライアントが直接更新できるのは `displayName` / `avatarUrl` / `discordUsername` / `discordUserId` / `duties` / `note` のみで、対象は本人のドキュメント（メンバーは全所属者）。Security Rules の許可リストで強制する（`scripts/check-member-rules.mjs` で検証）
- 所属者が 1 人（自分のみ）のチームをソロチームと呼ぶ
- ソロチームのメンバーが退出した場合、チームドキュメントとチームコードドキュメントは自動削除される
- `removeTeamMember` で削除後に所属者数が 0 になった場合も同様に自動削除される（防御的処理）

## ロール遷移

```text
なし → member   （チーム作成時）
なし → staff    （チームコードで参加時）
staff → member  （メンバーによる昇格）
member → staff  （メンバーによる降格）
```

制約: `member` は少なくとも 1 人維持が必要。最後の 1 人の `member` を `staff` へ降格させる操作は禁止。自分自身のロールは変更できない。

## 関連する隣接モデル

### user 側で管理するもの

- `currentTeamId`
- `teamIds`（複数チーム所属対応）

### plan 側で管理するもの

- チームへの参加可否判定（所属者数の上限）
- プラン別制限値
