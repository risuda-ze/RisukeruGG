# team

チーム管理カテゴリの詳細仕様です。

このディレクトリを、チーム作成・参加・ロール管理・退出・複数チーム所属・アクティブチーム切り替えに関する唯一の詳細仕様として扱います。

> **実装状況**: ロールを「メンバー / スタッフ」の 2 種類にする仕様は**未実装**。requirements / model / flows は実装前の設計（仮決定を含む）を先に反映しており、現行実装は 3 ロール（`operator` / `member` / `rom`）のまま。仮決定・移行手順は変更仕様 [two-roles.md](../../変更仕様/two-roles.md) を参照。他カテゴリの正本は実装時に同期するまで旧ロールの表記が残る。

## 用語

- **メンバー** / **スタッフ**: ロール名（保存値は `member` / `staff`）。メンバーはチームの全権限、スタッフは自分が作ったスケジュール・ブリーフの管理と、担当する工程の完了ができる
- **所属者**: ロールを問わず、チームに所属するユーザーの総称（データ上は `TeamMember`）
- **作成者**: ドキュメントの `createdBy` が自分の uid と一致するユーザー。Discord 経由・システム作成・退会済み・記録なしは、誰にも一致しない（メンバーのみが扱える）

## 対象範囲

- チーム作成
- チームコード参加
- ロール管理
- 所属と退出
- アクティブチーム切り替え
- メンバー・スタッフの詳細（担当分野・ひとこと、`/team` のタブ構成、`/team/[uid]`）

## 対象外

- Google ログイン自体の認証方式とセッション維持
- プラン制限値やアップグレード条件
- メンバー削除やロール変更に伴う通知配送の詳細

## 他カテゴリとの境界

### user との境界

- team は所属とロールを扱うが、ログイン方式や認証セッション本体は user を参照する
- team は `currentTeamId` や `teamIds` を利用する場合があるが、その保持主体は user を参照する

### plan との境界

- team は参加時にプラン判定結果を利用するが、人数制限の基準値や課金状態は plan を参照する

### notification との境界

- team は通知対象イベントを持つが、配送実装や既読管理は notification を参照する
