# team requirements

## チーム管理

- 「メンバー」「スタッフ」はロール名、「所属者」はロールを問わない総称として書く（[README](./README.md) の用語を参照）
- **TE-001**: 認証済みユーザーはチームを作成でき、自動的にメンバーロールが付与される
- **TE-002**: チームには固有のチームコードが自動生成。メンバーはいつでもリセット可能。旧コードは即時無効化
- **TE-003**: ユーザーは設定画面でチームコードを入力してチームに参加。プラン制限を超える場合は参加をブロック
- **TE-004**: チームコードで参加したユーザーにはスタッフロールが付与。メンバーがその後ロールを変更可能
- **TE-005**: 2 つのロール: メンバー（全権限）、スタッフ（スケジュールとブリーフの作成、自分が作成したものの編集・削除、担当する工程の完了）。閲覧専用のロールは持たない。チーム内に複数のメンバーが共存可能。コンテンツごとの権限は [model.md](./model.md) の権限表を正とする
- **TE-006**: メンバーは他の所属者のロールをメンバー・スタッフの間で変更可能。自分自身のロールは変更できない。変更後もチームにメンバーが 1 人以上いることが必要
- **TE-007**: メンバーは所属者をチームから Kick 可能（自分自身を除く）
- **TE-008**: チームから削除された所属者はチームのデータに一切アクセス不可
- **TE-009**: 所属者の削除時、未完タスクは「未アサイン」に移行する。完了済みタスク・過去スケジュールは保持（作成者名は「元メンバー」表示）
- **TE-010**: 1 ユーザーが複数チームに同時所属できる
- **TE-010-1**: 初回 Google ログイン時、ユーザーは自動的にソロチームのメンバーとして登録
- **TE-010-2**: ユーザーはいつでも特定チームから退出可能。ロールとチーム状態により挙動が異なる:
  - **スタッフ**: 制限なく退出できる
  - **メンバーで、所属者が自分のみ（ソロチーム）**: チームを自動削除して退出できる（**spec 008 追加**）
  - **メンバーで、自分以外にメンバーが存在する場合**: そのまま退出できる
  - **メンバーで、自分が唯一のメンバーかつ所属者が 2 人以上の場合**: 別の所属者をメンバーに昇格させてから退出
- **TE-011**: チームスイッチャーで任意のチームをアクティブチームに切り替え可能（spec 003 追加）
- **TE-012**: 所属者は Discord のユーザー名（`discordUsername`）をチームごとに任意で登録できる。登録は本人（`/settings/profile`）またはメンバー（`/team` の所属者の行）が行い、Firestore ルール上は既存の更新権限（本人またはメンバー）で制御する。ログイン連携（OAuth）は行わない
  - **TE-012-1**: 保存前に先頭の `@`・前後空白を除去し小文字化する。形式は 2〜32 文字、英小文字・数字・`_`・`.` のみ、`.` の連続不可。空で保存した場合は未設定（null）に戻す
  - **TE-012-2**: ユーザー名を変更・解除した場合は解決済み ID のキャッシュ（`discordUserId`）を null に戻す。ID の解決と保存は Discord 連携側（integration IN-015）が行う
  - **TE-012-3**: 取得するのはユーザー名と解決した ID のみで、Discord の認証情報やメッセージ本文は保持しない。値は同一チームの所属者のみ閲覧でき、アカウント削除時に所属情報とともに消える
- **TE-013**: ロールの保存値は `member`（メンバー）と `staff`（スタッフ）の 2 つとする。これ以外の値は読み取り時に `staff` として扱い、書き込みには使わない（[model.md](./model.md) の後方互換を参照）

## メンバー・スタッフの詳細

> ここでの「所属者」はチームに所属する全員（`TeamMember`）を指し、画面では「メンバー・スタッフ」と表記する。「メンバー」は管理権限を持つロール（保存値 `member`）を指す。

- **TE-014**: 所属者はチームごとに「担当分野」（`duties`）と「ひとこと」（`note`）を任意で持てる。編集は本人またはメンバーが行う（TE-012 と同じ権限）
  - **TE-014-1**: 担当分野は固定候補（出演 / 企画 / 編集 / サムネ / 配信サポート / その他）からの複数選択とする。候補の追加・自由記述はできない。未選択も可
  - **TE-014-2**: ひとことは 100 字以内・改行なしのプレーンテキストとする。保存前に前後空白を除去し、空なら未設定（null）に戻す
  - **TE-014-3**: 値はクライアントの Zod と Firestore ルールの両方で検証する（型・候補・件数・長さ）
  - **TE-014-4**: 値は同一チームの所属者のみ閲覧でき、退出・Kick・アカウント削除時に所属者の情報とともに消える。変更の通知・履歴は持たない
- **TE-015**: `/team` は「メンバー・スタッフ」「チーム」の 2 タブで構成する。既定はメンバー・スタッフタブで、`/team?tab=team` でチームタブを開く。チーム未参加時はタブを出さず、参加 / 作成の案内だけを表示する
  - **TE-015-1**: メンバー・スタッフタブには所属者の一覧を置く。各行にアバター・表示名・ロール・担当分野・Discord 名を表示し、行から詳細へ遷移できる。ロール変更・Kick・Discord 名の編集は行の上で行う
  - **TE-015-2**: チームタブにはチームの基本情報（チーム名・チームコード）、別チームへの参加、現在のチームからの退出、危険ゾーン（メンバーのみ）を置く
- **TE-016**: メンバー・スタッフタブで所属者を絞り込める。テキストは表示名・Discord 名の部分一致（大文字小文字を区別しない）、担当分野はチップの複数選択（いずれかを持つ所属者）。両方を指定した場合は両方を満たす所属者を表示する。専用の検索画面は持たない
- **TE-017**: `/team/{uid}` はアクティブチームの所属者の詳細を表示する。チームに所属する全ロールが、他人の詳細も閲覧できる
  - **TE-017-1**: 表示する項目はアバター・表示名・ロール・参加日・Discord 名・担当分野・ひとこととする。`email` など `User` 側の情報と `plan` は表示しない。本人だけに見える項目は持たない
  - **TE-017-2**: 担当中の工程を一覧で表示する。対象は `assigneeId` がその所属者で、未完了（完了・スキップ以外）、かつブリーフがアーカイブ済みでない工程。並び順と各行の表示は `/briefs/mine`（PD-004）と同じで、各行から 1枚紙の該当工程へ遷移できる。新しい購読・コレクションは追加しない
  - **TE-017-3**: 本人またはメンバーには「編集」を表示し、担当分野とひとことを保存できる。それ以外には表示しない
  - **TE-017-4**: `uid` がアクティブチームの現在の所属者でない場合（退出・Kick 済み、他チームの所属者、不正な値）は「メンバー・スタッフが見つかりません」と `/team` への導線を表示する。元の所属者の詳細は持たない
  - **TE-017-5**: 対応不可時間（unavailability）の画面へのリンクを表示する。詳細画面に対応不可時間は埋め込まない

## 作成者と権限

- **TE-018**: スケジュール・タスク・コラボ・ブリーフ・工程・進め方・カテゴリ・カンバン列は、作成者（`createdBy`）、作成日時、最終更新日時、最終更新者（`updatedBy`）を持つ。`createdBy` はクライアントからの作成時に本人の uid を必須とし、作成後は変更できない
- **TE-019**: スタッフが編集・削除できるのは、自分が作成したスケジュールとブリーフ（配下の工程を含む）に限る。メンバーはチーム内のすべてを編集・削除できる
- **TE-020**: Discord 経由・システムによる作成、退会・アカウント削除で作成者が存在しないもの、作成者の記録が無いものは、メンバーのみが編集・削除できる。作成者が同じ uid で再参加した場合は、ロールを問わず再び作成者として扱う
- **TE-021**: タスクとコラボの作成・編集・削除、進め方・カテゴリ・カンバン列の作成・編集・削除、Discord 連携・AI 設定の変更は、メンバーのみ
- **TE-022**: ブリーフの削除はメンバーのみ。削除すると配下の工程・差分・工程コメントも削除する
- **TE-023**: 工程の完了・状態変更は、担当者本人も行える。担当・締切・入力項目の変更と工程の追加・削除は、ブリーフの作成者かメンバーのみ
- **TE-024**: 工程コメントの作成は所属者全員。編集・削除は本人（`authorId`）かメンバーのみ
- **TE-025**: Discord 由来の操作（作成・コメント・工程ボタン）は、ロールを問わず許可される
