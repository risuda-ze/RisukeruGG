# team requirements

## チーム管理

- **TE-001**: 認証済みユーザーはチームを作成でき、自動的にオペレーターロールが付与される
- **TE-002**: チームには固有のチームコードが自動生成。オペレーターはいつでもリセット可能。旧コードは即時無効化
- **TE-003**: ユーザーは設定画面でチームコードを入力してチームに参加。プラン制限を超える場合は参加をブロック
- **TE-004**: チームコードで参加したユーザーには ROM専ロールが付与。オペレーターがその後ロールを変更可能
- **TE-005**: 3 つのロール: オペレーター（全権限）、メンバー（スケジュール・タスクの作成・編集）、ROM専（閲覧のみ）。チーム内に複数のオペレーターが共存可能
- **TE-006**: オペレーターはメンバーのロールをオペレーター・メンバー・ROM専 の間で変更可能。ただし変更後もチームにオペレーターが 1 人以上いることが必要
- **TE-007**: オペレーターはメンバーをチームから Kick 可能（オペレーター自身を除く）
- **TE-008**: チームから削除されたメンバーはチームのデータに一切アクセス不可
- **TE-009**: メンバー削除時、未完タスクは「未アサイン」に移行しオペレーターに通知。完了済みタスク・過去スケジュールは保持（作成者名は「元メンバー」表示）
- **TE-010**: 1 ユーザーが複数チームに同時所属できる
- **TE-010-1**: 初回 Google ログイン時、ユーザーは自動的にソロチームのオペレーターとして登録
- **TE-010-2**: ユーザーはいつでも特定チームから退出可能。ロールとチーム状態により挙動が異なる:
  - **メンバー・ROM専**: 制限なく退出できる
  - **オペレーターで、メンバーが自分のみ（ソロチーム）**: チームを自動削除して退出できる（**spec 008 追加**）
  - **オペレーターで、自分以外にオペレーターが存在する場合**: そのまま退出できる
  - **オペレーターで、自分が唯一のオペレーターかつメンバーが 2 人以上の場合**: 別メンバーをオペレーターに昇格させてから退出
- **TE-011**: チームスイッチャーで任意のチームをアクティブチームに切り替え可能（spec 003 追加）
- **TE-012**: メンバーは Discord のユーザー名（`discordUsername`）をチームごとに任意で登録できる。登録は本人（`/settings/profile`）またはオペレーター（`/team` のメンバー行）が行い、Firestore ルール上は既存のメンバー更新権限（本人またはオペレーター）で制御する。ログイン連携（OAuth）は行わない
  - **TE-012-1**: 保存前に先頭の `@`・前後空白を除去し小文字化する。形式は 2〜32 文字、英小文字・数字・`_`・`.` のみ、`.` の連続不可。空で保存した場合は未設定（null）に戻す
  - **TE-012-2**: ユーザー名を変更・解除した場合は解決済み ID のキャッシュ（`discordUserId`）を null に戻す。ID の解決と保存は Discord 連携側（integration IN-015）が行う
  - **TE-012-3**: 取得するのはユーザー名と解決した ID のみで、Discord の認証情報やメッセージ本文は保持しない。値は同一チームのメンバーのみ閲覧でき、アカウント削除時にメンバー情報とともに消える

## メンバー詳細（未実装）

> 未実装（2026-11-18 時点、Issue #212）。仮決定を含む。経緯と仮決定一覧は変更仕様 [member-detail.md](../../変更仕様/member-detail.md) を参照する。
> ここでの「メンバー」はチームに所属する全員（`TeamMember`）を指す。「オペレーター」は管理権限を持つロール（保存値 `operator`）で、#219 が確定すれば表示名を読み替える。

- **TE-014**: メンバーはチームごとに「担当分野」（`duties`）と「ひとこと」（`note`）を任意で持てる。編集は本人またはオペレーターが行う（TE-012 と同じ権限）
  - **TE-014-1**: 担当分野は固定候補（出演 / 企画 / 編集 / サムネ / 配信サポート / その他）からの複数選択とする。候補の追加・自由記述はできない。未選択も可
  - **TE-014-2**: ひとことは 100 字以内・改行なしのプレーンテキストとする。保存前に前後空白を除去し、空なら未設定（null）に戻す
  - **TE-014-3**: 値はクライアントの Zod と Firestore ルールの両方で検証する（型・候補・件数・長さ）
  - **TE-014-4**: 値は同一チームのメンバーのみ閲覧でき、退出・Kick・アカウント削除時にメンバー情報とともに消える。変更の通知・履歴は持たない
- **TE-015**: `/team` は「メンバー」「チーム」の 2 タブで構成する。既定はメンバータブで、`/team?tab=team` でチームタブを開く。チーム未参加時はタブを出さず、参加 / 作成の案内だけを表示する
  - **TE-015-1**: メンバータブにはメンバー一覧を置く。各カードにアバター・表示名・ロール・Discord 名・担当分野を表示し、カードからメンバー詳細へ遷移できる。ロール変更・Kick・Discord 名の編集はカード上で行う
  - **TE-015-2**: チームタブにはチームの基本情報（チーム名・チームコード）、現在のチームからの退出、別チームへの参加、危険ゾーン（オペレーターのみ）を置く
- **TE-016**: メンバータブでメンバーを絞り込める。テキストは表示名・Discord 名の部分一致（大文字小文字を区別しない）、担当分野はチップの複数選択（いずれかを持つメンバー）。両方を指定した場合は両方を満たすメンバーを表示する。専用の検索画面は持たない
- **TE-017**: `/team/{uid}` はアクティブチームのメンバー詳細を表示する。チームに所属する全ロールが、他人の詳細も閲覧できる
  - **TE-017-1**: 表示する項目はアバター・表示名・ロール・参加日・Discord 名・担当分野・ひとこととする。`email` など `User` 側の情報と `plan` は表示しない。本人だけに見える項目は持たない
  - **TE-017-2**: 担当中の工程を一覧で表示する。対象は `assigneeId` がそのメンバーで、未完了（完了・スキップ以外）、かつブリーフがアーカイブ済みでない工程。並び順と各行の表示は `/briefs/mine`（PD-004）と同じで、各行から 1枚紙の該当工程へ遷移できる。新しい購読・コレクションは追加しない
  - **TE-017-3**: 本人またはオペレーターには「編集」を表示し、担当分野とひとことを保存できる。それ以外には表示しない
  - **TE-017-4**: `uid` がアクティブチームの現メンバーでない場合（元メンバー・他チームのメンバー・不正な値）は「メンバーが見つかりません」と `/team` への導線を表示する。元メンバーの詳細は持たない
  - **TE-017-5**: 対応不可時間（unavailability）の実装後は、対応不可時間の画面へのリンクを表示する。詳細画面に対応不可時間は埋め込まない
