# team flows

## 初回ソロチーム生成フロー

このフローは user カテゴリの初回ログインフローから委譲される。

1. user カテゴリの初回ログインフローが完了し、User アカウントが作成される
2. システムがソロチームを自動作成する（name: displayName のチーム, operatorUids: [作成者 uid], teamCode, createdAt）
3. 作成者をオペレーターとして `teams/{teamId}/members/{uid}` に登録する
4. チームコードを自動生成して `teamCodes/{code}` に保存する
5. User の `currentTeamId` と `teamIds` をソロチームで初期化する

## チーム作成フロー

1. 認証済みユーザーが設定/チーム管理画面のチームタブでチーム名を入力する
2. チームドキュメントを新規作成する（name: 入力名, operatorUids: [作成者 uid], teamCode, createdAt）
3. 作成者をオペレーターとして `teams/{teamId}/members/{uid}` に登録する
4. 固有のチームコードを生成して `teamCodes/{code}` に保存する
5. User の `teamIds` に新チームを追加し、`currentTeamId` を新チームに更新する

## チームコード参加フロー

1. ユーザーが設定画面でチームコードを入力して「参加する」を押す
2. `teamCodes/{code}` を照合してチーム ID を取得する（存在しない場合は「無効なチームコードです」エラー）
3. plan カテゴリのメンバー上限チェックを行う（上限超過の場合は参加ブロックし全 LIGHT メンバーに通知）
4. ユーザーを ROM専ロールで `teams/{teamId}/members/{uid}` に登録する
5. User の `teamIds` に参加チームを追加し、`currentTeamId` を参加チームに更新する

## チーム退出フロー

1. ユーザーが「現在のチームから退出する」を選択する
2. ロールとチームのメンバー数を確認する
3. **メンバー・ROM専の場合**:
   - `teams/{teamId}/members/{uid}` を削除する
   - User の `teamIds` から退出チームを除去し、`currentTeamId` を別チームに更新する
4. **オペレーターで、メンバーが自分のみ（ソロチーム）の場合**:
   - `teams/{teamId}` ドキュメントを削除する
   - `teams/{teamId}/members/{uid}` を削除する
   - `teamCodes/{teamCode}` ドキュメントを削除する
   - User の `teamIds` から退出チームを除去し、`currentTeamId` を別チームに更新する
5. **オペレーターで、自分以外にオペレーターが存在する場合**:
   - `teams/{teamId}/members/{uid}` を削除する
   - `teams/{teamId}` の `operatorUids` から自分を除去する
   - 残りのオペレーター全員に「メンバーが脱退しました」通知を送る
   - User の `teamIds` から退出チームを除去し、`currentTeamId` を別チームに更新する
6. **オペレーターで、自分が唯一のオペレーターかつメンバーが 2 人以上の場合**:
   - エラー: 「先に別のメンバーをオペレーターに指名してください」を表示してブロックする

## ロール変更フロー

1. オペレーターがメンバー一覧から対象を選択してロールを変更する
2. 変更後もチームにオペレーターが 1 人以上いることを確認する（最後のオペレーターは降格不可）
3. `teams/{teamId}/members/{uid}` の `role` を更新する。オペレーターへの昇格の場合は `teams/{teamId}` の `operatorUids` にも追加する。オペレーターからの降格の場合は `operatorUids` から除去する
4. 変更されたメンバーにシステム通知を送る

## メンバー削除（Kick）フロー

1. オペレーターがメンバー一覧から対象を選択して「チームから削除」を実行する
2. 削除対象がオペレーター自身でないことを確認する
3. `teams/{teamId}/members/{uid}` を削除する
4. 削除対象メンバーが持つ未完タスクをすべて「未アサイン」状態に移行する
5. オペレーターにタスク移行の通知を送る（システム通知カテゴリ）
6. User の `teamIds` から対象チームを除去し、`currentTeamId` を更新する

## チームスイッチャーフロー

1. ユーザーがサイドバーのチームスイッチャーから切り替え先チームを選択する
2. User の `currentTeamId` を選択したチームに更新する
3. UI がアクティブチームのデータ（スケジュール・タスク・メンバー）を再読み込みする

## メンバー絞り込みフロー（未実装・TE-015）

1. ユーザーが `/team` のメンバータブを開く。購読済みのメンバー全件を表示する
2. テキストを入力する、または担当分野のチップを選ぶ
3. 画面側で、表示名・Discord 名の部分一致と、選択した担当分野のいずれかを持つことの両方を満たすメンバーに絞る（サーバーへの問い合わせはしない）
4. 該当者がいない場合は「該当するメンバーがいません」を表示する

## メンバー詳細の閲覧フロー（未実装・TE-016）

1. ユーザーがメンバータブのカードを選び、`/team/{uid}` へ遷移する
2. 購読済みのメンバーから `uid` を探す。いなければ「メンバーが見つかりません」と `/team` への導線を表示して終了する
3. メンバーの項目（アバター・表示名・ロール・参加日・Discord 名・担当分野・ひとこと）を表示する
4. 既存の工程購読（チームの全工程）を、`assigneeId` が対象メンバー・未完了・ブリーフが未アーカイブで絞り、締切順に表示する
5. 工程の行を選ぶと 1枚紙の該当工程へ遷移する

## 担当分野・ひとことの編集フロー（未実装・TE-013）

1. 本人またはオペレーターがメンバー詳細の「編集」を押す
2. 担当分野を候補から選び、ひとことを入力する
3. Zod で検証する（候補外・重複・100 字超・改行はエラー）。ひとことは前後空白を除去し、空なら null にする
4. `teams/{teamId}/members/{uid}` の `duties` と `note` を更新する。Firestore ルールが権限と値を検証する
5. 購読経由でメンバー詳細とメンバーカードに反映される。通知は送らない
