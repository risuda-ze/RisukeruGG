# team flows

## 初回ソロチーム生成フロー

このフローは user カテゴリの初回ログインフローから委譲される。

1. user カテゴリの初回ログインフローが完了し、User アカウントが作成される
2. システムがソロチームを自動作成する（name: displayName のチーム, teamCode, createdAt）
3. 作成者をメンバー（`member`）として `teams/{teamId}/members/{uid}` に登録する
4. チームコードを自動生成して `teamCodes/{code}` に保存する
5. User の `currentTeamId` と `teamIds` をソロチームで初期化する

## チーム作成フロー

1. 認証済みユーザーが設定/チーム管理画面のチームタブでチーム名を入力する
2. チームドキュメントを新規作成する（name: 入力名, teamCode, createdAt）
3. 作成者をメンバー（`member`）として `teams/{teamId}/members/{uid}` に登録する
4. 固有のチームコードを生成して `teamCodes/{code}` に保存する
5. User の `teamIds` に新チームを追加し、`currentTeamId` を新チームに更新する

## チームコード参加フロー

1. ユーザーが設定画面でチームコードを入力して「参加する」を押す
2. `teamCodes/{code}` を照合してチーム ID を取得する（存在しない場合は「無効なチームコードです」エラー）
3. plan カテゴリの所属者数の上限チェックを行う（上限超過の場合は参加ブロックし、LIGHT プランの全所属者に通知）
4. ユーザーをスタッフロール（`staff`）で `teams/{teamId}/members/{uid}` に登録する
5. User の `teamIds` に参加チームを追加し、`currentTeamId` を参加チームに更新する

## チーム退出フロー

1. ユーザーが「現在のチームから退出する」を選択する
2. ロールとチームの所属者数を確認する
3. **スタッフの場合**:
   - `teams/{teamId}/members/{uid}` を削除する
   - User の `teamIds` から退出チームを除去し、`currentTeamId` を別チームに更新する
4. **メンバーで、所属者が自分のみ（ソロチーム）の場合**:
   - `teams/{teamId}` ドキュメントを削除する
   - `teams/{teamId}/members/{uid}` を削除する
   - `teamCodes/{teamCode}` ドキュメントを削除する
   - User の `teamIds` から退出チームを除去し、`currentTeamId` を別チームに更新する
5. **メンバーで、自分以外にメンバーが存在する場合**:
   - `teams/{teamId}/members/{uid}` を削除する
   - 残りのメンバー全員に脱退の通知を送る
   - User の `teamIds` から退出チームを除去し、`currentTeamId` を別チームに更新する
6. **メンバーで、自分が唯一のメンバーかつ所属者が 2 人以上の場合**:
   - エラーを表示してブロックする（先に別の所属者をメンバーへ昇格させる必要がある旨）
7. 退出が成立したら、退出したユーザーのそのチームの対応不可と対応不可コメントを削除する（[unavailability/flows.md](../unavailability/flows.md)）。削除に失敗しても退出は成立させる

## ロール変更フロー

1. メンバーが所属者の一覧から自分以外の対象を選択し、ロールを「メンバー / スタッフ」のどちらかに変更する
2. 変更後もチームにメンバーが 1 人以上いることを確認する（最後のメンバーは降格不可）
3. `teams/{teamId}/members/{uid}` の `role` を更新する
4. 変更された所属者にシステム通知を送る

## 所属者の削除（Kick）フロー

1. メンバーが所属者の一覧から対象を選択して「チームから削除」を実行する
2. 削除対象が自分自身でないことを確認する
3. `teams/{teamId}/members/{uid}` を削除する
4. 削除対象の所属者が持つ未完タスクをすべて「未アサイン」状態に移行する
5. メンバーにタスク移行の通知を送る（システム通知カテゴリ）
6. User の `teamIds` から対象チームを除去し、`currentTeamId` を更新する
7. 削除対象の所属者のそのチームの対応不可と対応不可コメントを削除する（[unavailability/flows.md](../unavailability/flows.md)）。削除に失敗しても Kick は成立させる

## チームスイッチャーフロー

1. ユーザーがサイドバーのチームスイッチャーから切り替え先チームを選択する
2. User の `currentTeamId` を選択したチームに更新する
3. UI がアクティブチームのデータ（スケジュール・タスク・所属者）を再読み込みする

## メンバー・スタッフの絞り込みフロー（TE-016）

1. ユーザーが `/team` のメンバー・スタッフタブを開く。購読済みの所属者全員を表示する
2. テキストを入力する、または担当分野のチップを選ぶ（複数選べる）
3. 画面側で、表示名・Discord 名の部分一致と、選択した担当分野のいずれかを持つことの両方を満たす所属者に絞る（サーバーへの問い合わせはしない）
4. 該当者がいない場合は「条件に合うメンバー・スタッフはいません」を表示する

## メンバー・スタッフの詳細の閲覧フロー（TE-017）

1. ユーザーがメンバー・スタッフタブの行を選び、`/team/{uid}` へ遷移する
2. 購読済みの所属者から `uid` を探す。いなければ「メンバー・スタッフが見つかりません」と `/team` への導線を表示して終了する
3. 所属者の項目（アバター・表示名・ロール・参加日・Discord 名・担当分野・ひとこと）を表示する
4. 既存の工程購読（チームの全工程）を、`assigneeId` が対象の所属者・未完了・ブリーフが未アーカイブで絞り、締切順に表示する
5. 工程の行を選ぶと 1枚紙の該当工程へ遷移する

## 担当分野・ひとことの編集フロー（TE-014）

1. 本人またはメンバーが詳細画面の「編集」を押す
2. 担当分野を候補から選び、ひとことを入力する
3. Zod で検証する（候補外・重複・100 字超・改行はエラー）。ひとことは前後空白を除去し、空なら null にする
4. `teams/{teamId}/members/{uid}` の `duties` と `note` を更新する。Firestore ルールが権限と値を検証する
5. 購読経由で詳細画面と一覧の行に反映される。通知は送らない
