# plan

プラン管理カテゴリの詳細仕様です。

このディレクトリを、LIGHT / PARTY プランの定義、月次利用上限、参加可否判定、アップグレード導線、広告表示条件に関する唯一の詳細仕様として扱います。

## 対象範囲

- LIGHT / PARTY の 2 プラン定義
- タスク / コラボの月次上限制御
- 3 人以上のチーム参加時のプラン判定
- PARTY アップグレード CTA の表示条件
- LIGHT 向けバナー広告の表示方針

## 対象外

- Google ログインと初回ユーザー作成自体の認証方式
- チーム作成、チームコード参加、ロール管理の詳細
- タスクやコラボを実際に作成・編集する UI フロー

## 他カテゴリとの境界

### user との境界

- plan は `users/{uid}` に同居するプラン関連フィールドを正本化するが、認証プロフィール本体は user を参照する

### team との境界

- plan は参加可否の判定基準だけを扱い、チーム作成・参加・ロール変更の操作フロー自体は team を参照する

### task / collab との境界

- plan は作成可否と月次カウント増減条件を扱い、個別フォームや作成操作の詳細は task / collab を参照する

### ui との境界

- plan は制限到達時の表示条件を定義し、具体的な見た目は ui を参照する

## 読む順番

1. この README: プランカテゴリが持つ判定責務と境界を把握する
2. [requirements.md](./requirements.md): プラン管理の規範要件を確認する
3. [model.md](./model.md): プラン状態と月次カウントの保持方針を確認する
4. [flows.md](./flows.md): 初期付与、上限制御、参加判定、月次リセットの流れを確認する

## 採用する後続仕様

- 001 のプラン基本要件を統合済み
- 実装上の保持項目（`plan`, `planUpdatedAt`, `monthlyTaskCount`, `monthlyCollabCount`, `countResetAt`）を反映済み
- `PlanStatus` は現在ユーザーの実データからプランを判定する前提に合わせる
- 旧仕様と実装で表現が異なる場合は、現行コードで強制しているバックエンド制約を優先する
- 以後、プラン管理の更新はこのディレクトリを起点に行う
