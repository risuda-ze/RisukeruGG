# plan flows

## 初回プラン付与フロー

1. 新規ユーザー作成時に、プラン初期化処理を開始する
2. 対象ユーザーの `users/{uid}` ドキュメントを初期化対象として特定する
3. `plan` を `light`、`planUpdatedAt` を現在時刻で保存する
4. `monthlyTaskCount` と `monthlyCollabCount` を 0 で初期化する
5. `countResetAt` を現在時刻で保存する

## タスク / コラボ作成時の上限制御フロー

1. 認証済みユーザーがタスクまたはコラボを作成しようとする
2. Cloud Function が `users/{uid}` の `plan` を取得する
3. `plan === 'party'` なら上限チェックなしで続行する
4. `plan === 'light'` なら対象の月次カウントを確認する
5. 上限未満なら作成を許可し、対応する月次カウントを 1 増やす
6. 上限到達済みなら作成をブロックし、PARTY へのアップグレード導線を表示する

## 3 人以上チーム参加時のプラン判定フロー

1. ユーザーがチームコードで既存チームに参加しようとする
2. 参加後のチーム人数が 3 名以上になるか判定する
3. 2 名以下なら通常の team 参加フローへ進む
4. 3 名以上になる場合、参加者を含む全所属者の `plan` を確認する
5. 全員が `party` なら参加を許可する
6. 1 人でも `light` が含まれる場合は参加をブロックする
7. 既存の LIGHT プランの所属者へシステム通知を送る

## 月次リセットフロー

1. 毎月 1 日 0:00 JST にスケジュール実行を開始する
2. `plan === 'light'` のユーザーを取得する
3. `monthlyTaskCount` と `monthlyCollabCount` を 0 に更新する
4. `countResetAt` を実行時刻に更新する
5. 次回の上限制御判定から新しい月次カウントを使用する

## アップグレード導線表示フロー

1. LIGHT ユーザーが設定画面や上限制限画面を表示する
2. `NEXT_PUBLIC_PARTY_SIGNUP_URL` が設定されているか確認する
3. URL が設定されていれば「PARTYプランにアップグレード」CTA を表示する
4. URL 未設定なら CTA を表示しない
5. LIGHT ユーザーにはバナー広告プレースホルダーを表示し、PARTY ユーザーには表示しない
