# unavailability flows

## 一覧表示フロー

1. 所属者がサイドバー「メイン」の「対応不可時間」（モバイルは「その他」ドロワー）から `/unavailability` を開く
2. システムがチームの所属者一覧と、当月の月ドキュメント（`month` 等価条件の 1 クエリ）を購読する
3. 行＝所属者、列＝日の一覧を描画する。自分の行を最上段に置き、当日の週が中心に来る位置へ横スクロールする
4. 各セルは、その日のマスクが 0 でなければ × を表示する。日ごとに不可の人数、所属者行に「最終更新 ○日前 / 未入力」を表示する
5. 横スクロールが前月・翌月の端に近づいたら、その月の購読を足す。まだ読み込んでいない月のセルと不可人数は「…」と表示する（空白＝対応可能と読ませない）
6. ヘッダーは折り畳んだ状態で表示する
7. 購読に失敗した場合は、一覧を表示せずエラーを表示する
8. ヘルプボタンを押すと、画面ヘルプ（注意事項）をダイアログで表示する

## 絞り込み・時間帯フィルタフロー

1. 所属者がヘッダーを開く
2. 所属者を複数選択すると、選んだ所属者の行だけを表示する。自分が含まれていれば最上段のままにする。日ごとの不可人数は表示中の所属者で数え直す
3. 期間を指定すると、その期間へ横スクロールする
4. 時間帯（開始時〜終了時）を指定すると、表示中の所属者全員のマスクと時間帯マスクの AND が 0 になる日をハイライトする（日の見出しに「空き」を出し、その日の列・行を緑の淡い面にする）。開始時・終了時の片方だけ、または終了が開始以前のときはハイライトせず、その旨を示す。まだ読み込んでいない月の日はハイライトせず、その月を読み込んだ時点で判定する
5. 条件を解除すると、所属者・期間・時間帯の指定がすべて外れ、初期表示に戻る

## 所属者詳細表示フロー

1. 所属者が一覧のセルをクリックする
2. システムがその所属者の詳細を開く。タイトルに所属者名と最終更新を並べる。先頭行は、クリックした日が当日なら現在時刻の行、それ以外ならその日の 0:00 とし、いちばん上に見えている行と各日の 0:00 の行に日付を表示する
3. 縦の時間軸に対応不可の時間帯（赤。文言は書かない）とメモ（水色の吹き出し）を表示する。連続する対応不可は、日をまたぐ場合も含めて 1 つのブロックにつなげる。同じ時間帯のメモは横に並べる。吹き出しを押すと全文を表示する
4. 自分の詳細なら入力・メモ追加の操作を表示する。他人の詳細では表示しない
5. 「日単位で表示」に切り替えると、日ごとに不可の有無と時間数を 1 行で表示する。メモは表示しない
6. 開始日時〜終了日時を指定すると、その期間へ表示を移動する

## 対応不可の入力フロー

1. 本人が自分の詳細で、時刻の右にある対応不可の列をドラッグする。始点のセルが空なら範囲を塗り、不可なら範囲を消す。変更は未保存として破線で表示する
2. 日をまたいでドラッグした場合も、そのまま連続した範囲として扱う
3. 本人が「保存」を押す
4. システムが範囲を日付ごとに分割し、日マスクに変換する。前月 1 日〜翌月末日の外は入力させない
5. Zod で検証し、変更した日のキー、メモに未保存の変更があれば `notes`、`updatedAt` だけを該当する月ドキュメントへ書き込む（無ければ作成。マスクが 0 になった日はキーを削除）。書き込みは月ドキュメントごとに 1 回で、保存のための読み取りはしない（購読済みの内容に未保存の変更を当てて書く）
6. 購読を通じて、全所属者の一覧の ×・人数・最終更新が更新される
7. 保存に失敗した場合はトーストで知らせ、塗った内容と未保存のメモは画面に残す。複数の月に書く場合は、失敗した月の変更だけを残す
8. 書き込みが 10 秒たっても完了しない場合（通信が切れている等）は、通信を確認するよう表示し、確認のうえで詳細を閉じられるようにする。通信が戻ると保存は完了する
8. 未保存の変更があるまま詳細を閉じようとした場合は確認を出し、「編集に戻る」なら詳細に戻り、「破棄して閉じる」なら未保存の変更を捨てて閉じる

## メモ追加・編集・削除フロー

1. 本人が自分の詳細でメモ欄の時間の行を押すか、「メモを追加」を押して、メモ追加のフォームを開く
2. 日付・開始時・終了時・本文（1〜100 字）を入力する。日をまたぐ範囲は指定できない
3. その月のメモが、保存済みと未保存の追加を合わせて 200 件に達している場合は追加させず、上限に達した旨を表示する
4. 入力を確定すると、`id` を採番し、未保存のメモとして本人のブラウザ内に保持して詳細に表示する。この時点では Firestore に書き込まない
5. 自分のメモの吹き出しを押すと編集フォームが開く。変更または削除を選ぶと、`id` で対象を特定し、同じく未保存の変更として保持する
6. 1〜5 は続けて何件でも行える
7. 本人が「保存」を押すと、「対応不可の入力フロー」の 3 以降で、未保存の対応不可とメモをまとめて書き込む

## CSV 取り込みフロー

1. 本人が自分の詳細の「CSV・定期入力」から CSV を開き、必要なら CSV（自分の当月データ入り・BOM 付き UTF-8）をダウンロードする。詳細に未保存の変更がある間は開けず、先に保存するよう案内する
2. 本人が `date,start,end` 形式の CSV ファイルを選ぶ
3. システムがブラウザ内でファイルを読み、UTF-8 でなければその旨を表示して終了する。全行を検証し、不正な行が 1 つでもあれば取り込まず、行番号と理由を一覧で表示して終了する
4. すべて正しければ、各行を日付ごとのマスクに展開する（終日・翌日またぎを含む）
5. 「展開結果の保存フロー」へ進む

## 定期入力フロー

1. 本人が自分の詳細の「CSV・定期入力」から定期入力を開き、開始日・終了日・曜日（複数可）・開始時・終了時を入力する。詳細に未保存の変更がある間は開けない
2. システムが期間内の該当曜日を日付に展開し、各日のマスクを作る（終了時が開始時より前なら翌日へまたぐ）
3. 「展開結果の保存フロー」へ進む。パターンは保存しない

## 展開結果の保存フロー（CSV・定期入力共通）

1. システムが展開結果から、前月 1 日〜翌月末日の外にある日付を切り捨てる
2. プレビューに、対象日の一覧と切り捨てた件数を表示する
3. 本人が確定する
4. 月ドキュメントごとにトランザクションで読み、既存のマスクと OR して書き込む（既存の不可は消さない）
5. 保存した日数をトーストで知らせ、画面を閉じる。一部の月の保存に失敗した場合は、失敗した月をトーストで知らせ、プレビューを残す

## 月次削除フロー

1. 毎月 1 日 0:00 JST に Cloud Functions（スケジュール実行）が起動する
2. コレクショングループ `unavailability` から `month` が前月より前のドキュメントを取得する
3. バッチで削除し、削除件数をログに残す。失敗はエラーとして残す（次回の実行で再度対象になる）

## 退出・Kick・アカウント削除時の削除フロー

1. team の退出フロー（現在のチームからの退出・チームを指定した退出）/ Kick フロー、または user のアカウント削除フローが、所属者の所属を消す処理を完了する
2. 同じ Cloud Functions の中で、`teams/{teamId}/unavailability` から `userId` が対象ユーザーのドキュメントを取得して削除する。アカウント削除では所属していた全チームについて行う
3. 削除に失敗しても退出等は成立させ、エラーログに残す。残ったドキュメントは月次削除で消える
