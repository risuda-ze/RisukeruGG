# unavailability model

## モデル方針

対応不可は「1 人・1 ヶ月」を 1 ドキュメントにまとめて持つ。1 日は 24 ビットの整数 1 つで表し、追記・人数集計・時間帯フィルタをビット演算で済ませる。

メンバーの所属とロールは team、アカウントの状態は user を参照する。

## UnavailabilityMonth

Firestore コレクション配置: `teams/{teamId}/unavailability/{userId}_{yyyy-mm}`

| フィールド  | 型 / 例                        | 意味 |
| ----------- | ------------------------------ | ---- |
| `userId`    | string                         | 申告した本人の UID。ドキュメント ID の前半と一致する。ルールの本人確認と、退出時の削除（`userId` の等価条件）に使う |
| `month`     | string / `2026-11`             | 対象月（JST）。ドキュメント ID の後半と一致する。Firestore はドキュメント ID の後半で絞り込めないため、月単位の購読（等価条件）と月次削除（範囲条件）の検索キーとして持つ |
| `days`      | map / `{ "2026-11-14": 15728640 }` | 日ごとの対応不可マスク。キーは `month` に属する日（`yyyy-mm-dd`）、値は下記のビットマスク。対応不可が無い日はキーを持たない |
| `notes`     | UnavailabilityNote[]           | その月のメモ。最大 200 件 |
| `updatedAt` | timestamp                      | 対応不可またはメモを最後に保存した日時（サーバー時刻）。一覧の「最終更新」に使う |

ドキュメントが無いことは「その月は未入力」を表す。`days` / `notes` は、一度も保存していない側のフィールドを持たないことがあり、空として扱う。

### 日マスク

- 0〜16,777,215（2^24 − 1）の整数。ビット `h`（0〜23）が立っていれば、その日の `h:00`〜`h+1:00` が対応不可
- 例: 20:00〜24:00 が不可 → ビット 20〜23 → `0xF00000` = 15,728,640。終日不可 → `0xFFFFFF`
- 値が 0 になった日はキーを削除する（0 を保存しない）
- 演算: 追記（CSV・定期入力）は OR、その日に不可があるかは `!== 0`、時間数は立っているビット数、時間帯フィルタは対象時間帯のマスクとの AND が 0 かどうか

### UnavailabilityNote

| フィールド | 型 / 例               | 意味 |
| ---------- | --------------------- | ---- |
| `id`       | string                | メモの ID（クライアントで生成。月ドキュメント内で一意）。編集・削除の対象を特定する |
| `date`     | string / `2026-11-14` | 対象日。月ドキュメントの `month` に属する |
| `start`    | number / 0〜23        | 開始時（その時を含む） |
| `end`      | number / 1〜24        | 終了時（排他的境界）。`start < end` |
| `text`     | string                | 本文。1〜100 字 |

メモは対応不可マスクと独立で、同じ時間帯に複数あってよい。

## 制約

- 日付・時はすべて JST。日をまたぐ入力は保存前に日付ごとに分割し、月をまたぐ場合はそれぞれの月ドキュメントに書く
- 保存する月は「前月・当月・翌月」の 3 つまで。前々月以前は毎月 1 日 0:00 JST に Cloud Functions が削除する
- 通常の保存は、変更した日のキーだけを更新する（月ドキュメント全体を上書きしない）。メモに変更がある場合は `notes` を配列ごと書き込む。書き込めるのは本人だけなので、本人が複数の端末で同時にメモを編集した場合は後の保存が残る。CSV・定期入力の和集合保存は読んでから書くため、トランザクションで行う
- クライアントは月ドキュメントを消さない。対応不可をすべて消した月は `days` が空のまま残り、`updatedAt` で「入力済み」と分かる
- 1 ドキュメントは最大でも 31 日分のマスクとメモ 200 件（1 件 100 字）で、Firestore の 1 MiB 上限に収まる

## Firestore Security Rules

`teams/{teamId}/unavailability/{docId}` に次を定める（1 ブロック）。

| 操作 | 条件 |
| ---- | ---- |
| read | 同一チームのメンバー（`rom` を含む） |
| create / update | 同一チームのメンバー（ロール不問）かつ β ゲート通過。書き込み後の `userId` が本人の UID、`docId` が `{本人の UID}_{month}`、`month` が `yyyy-mm` 形式、フィールドが `userId` / `month` / `days` / `notes` / `updatedAt` のみ、`days` が map、`notes` が 200 件以下の配列、`updatedAt` がリクエスト時刻 |
| delete | 不可（削除は Admin SDK のみ） |

ルールは map・配列の中身を走査できないため、次はルールでは検証しない。

- 日マスクの範囲（0〜2^24 − 1）、`days` のキーが `month` に属すること
- メモ 1 件の形（`date` / `start` / `end` / `text` の値と 100 字上限）
- 入力できる範囲（翌月末日まで）

これらは書き込み前にクライアントの Zod スキーマで検証する。不正値を入れられるのは本人のドキュメントだけなので、読み取り側は同じ Zod スキーマで検証し、通らない日・メモは捨てて表示する（画面全体を落とさない）。

## 読み取り

- 一覧・詳細とも `teams/{teamId}/unavailability` を `month` の等価条件で購読する（1 クエリでチーム全員の 1 ヶ月分）。当月を先に購読し、前月・翌月はスクロールが端に近づいたときに購読を足す
- 一覧の「最終更新」は、そのメンバーの読み込み済み月ドキュメントの `updatedAt` のうち最新のもの。読み込み済みの月にドキュメントが 1 つも無ければ「未入力」

## インデックス

- 月次削除はコレクショングループ `unavailability` を `month` の範囲条件で引くため、`firestore.indexes.json` の `fieldOverrides` に `month` のコレクショングループスコープのインデックスを追加する
- 退出時の削除（`userId` の等価条件）と画面の購読（`month` の等価条件）は自動の単一フィールドインデックスで足りる
