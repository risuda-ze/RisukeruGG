# task flows

## タスク新規作成フロー

1. メンバーがボード上の新規作成導線からタスク作成を開始する
2. タイトル、所属列、カテゴリ、担当者、締切日、説明を入力する
3. 保存時に `teams/{teamId}/tasks/{taskId}` を作成し、ボード上の該当列へ反映する
4. 担当者が設定された場合は notification カテゴリのルールに従って通知する
5. `linkedScheduleId` が指定される場合は schedule カテゴリの動画投稿予定と関連付ける

## タスク複製新規作成フロー

1. メンバーが既存タスクの `TaskDetailModal` を開く
2. 詳細画面の複製新規作成導線から、新規タスク作成を開始する
3. 新規作成フォームに `title`、`columnId`、`categoryId`、`assigneeId`、`dueDate`、`description`、`linkedScheduleId` を初期値として引き継ぐ
4. ユーザーは必要な項目を編集し、保存を実行する
5. 保存時に新しい `taskId` で `teams/{teamId}/tasks/{taskId}` を作成し、`createdBy`、作成日時、更新日時は新規値として扱う
6. 担当者が設定された場合は通常の新規作成と同じルールで通知する
7. 参照元タスクとの恒久的なリンクは保持せず、ボード上の該当列へ新規タスクとして反映する

## タスク詳細編集フロー

1. ユーザーがタスクカード本体をクリックし、`TaskDetailModal` を開く
2. ステータス・カテゴリ・担当者・期限（`DateInput` 使用）・説明の変更はモーダル内のローカル状態のみを更新し、この時点では Firestore へ保存しない
3. フッターの保存ボタン押下時に、変更されたフィールドのみを 1 回の `updateTask` で一括保存する（楽観的ロック: モーダルを開いた時点の `updatedAt` と不一致の場合は保存せずエラーを表示する）
4. キャンセルまたはモーダルを閉じた場合、未保存の変更は破棄する
5. 保存により担当者が変更された場合は、必要なら担当者通知を送る
6. 複製新規作成導線から新規作成を開始した場合は、現在の編集対象ではなく別タスクの作成フローへ遷移する
7. 更新後、ボード表示、完了率、ダッシュボードプレビューを再計算する

## カラム移動フロー

1. PC ではドラッグ&ドロップ、モバイルではボタン操作で移動を開始する
2. 移動先の `TaskStatus` を判定し、対象タスクの `columnId` を更新する
3. 移動後、列内の並び順は締切優先ルールで再描画する
4. 移動先または移動元が完了列の場合、ダッシュボード完了率を再計算する
5. 他者操作の通知が必要な場合は notification カテゴリへ処理を委譲する

## カラム管理フロー

1. メンバーが設定画面の「列の管理」セクションを開く
2. カラム名、色、アイコン、表示順を追加・編集・削除・並び替えする
3. 完了列の設定で必要な数の列を `role: 'done'` にし、完了対象から外す列は `null` に戻す
4. 更新後、ボード表示順とダッシュボード完了率の基準列を再反映する

## カテゴリ管理フロー

1. メンバーが `/settings/categories`（カテゴリ設定画面）の「カテゴリの管理」セクションを開く
2. カテゴリ名、色、アイコン（任意）を追加または編集する。このカテゴリはタスクとスケジュール共通で利用される
3. カテゴリ削除時は、関連タスクおよび関連スケジュールの `categoryId` を一括で `null` に更新する
4. 更新後、タスクカード、タスク詳細モーダル、タスクのカテゴリ選択 UI、スケジュールカレンダー、スケジュール編集モーダルに反映する

## CSV エクスポートフロー

1. メンバーがタスクボードのエクスポート操作を実行する
2. 現在の tasks、columns、members、categories を取得する
3. 各タスクを所属列名、カテゴリ名、担当者名を含むエクスポート行へ整形する
4. 全タスクの全項目を CSV として出力する

## ダッシュボード完了率反映フロー

1. ダッシュボードが tasks と columns を読み込む
2. `role === 'done'` の列群を完了列として特定する
3. 完了列に属するタスク数と全タスク数から完了率を算出し、完了列が 0 件なら完了率は 0% とする
4. カラム名の文言には依存せず、列設定変更後も同じ基準で再計算する

## 動画依頼からの列移動

### 作成前の設定と入力条件

1. `operator` がカテゴリ設定の「動画依頼の設定」で、Discord送信待ち・制作中・納品確認待ちに対応するタスク列を選択する。3列は相互に異なる列とし、完了列は選択できない。
2. 移動先はチームの列IDで保存する。「未着手」「進行中」「見てくれぃ」などの表示名を判定条件にせず、列名を変更しても同じ列へ移動する。
3. Discordサーバーとの連携と動画編集の投稿先を設定する。「サムネ制作も依頼する」を有効にする場合はサムネの投稿先も設定する。設定が不足している場合や指定列が存在しない場合は、依頼とタスクの作成を中止する。
4. `operator` または `member` が動画依頼を作成する。横動画・ショート動画とも初稿納期と完パケ納期は必須、編集開始日は任意とする。編集開始日 ≦ 初稿納期 ≦ 完パケ納期を満たさない場合は該当欄にエラーを表示し、保存しない。同日は指定できる。

### タスク作成とDiscord送信

1. 依頼の保存時に動画編集タスクを作成する。サムネ制作が有効な場合は、同時にサムネイル制作タスクも作成する。依頼と対象タスクは一括で保存し、対応するタスクIDで関連付ける。
2. 作成したタスクは設定されたDiscord送信待ち列へ配置し、期限には完パケ納期を設定する。サムネ制作の有効・無効の変更は、新規依頼から適用する。
3. Botによる依頼スレッドの作成と初回投稿が成功したら、動画編集タスクと、作成している場合はサムネイル制作タスクを制作中列へ移動する。
4. Discord送信が未処理または失敗した場合は制作中へ進めず、送信待ち列に残す。失敗は依頼カードに表示する。

### 納品・修正・承認による列移動

| 操作 | 対象タスクと移動先 | 依頼カード・Discordへの反映 |
|---|---|---|
| 編集者が編集スレッドの納品ボタンからURLと任意の共有事項を送信 | 動画編集タスクのみを納品確認待ち列へ移動 | 動画を確認待ちにし、納品URLをカードに表示する。編集スレッドにお礼を投稿する。 |
| 制作者がサムネ専用スレッドに画像を投稿し、本人が「サムネを納品」を押す | サムネイル制作タスクのみを納品確認待ち列へ移動 | サムネを確認待ちにし、カードから画像投稿を開けるようにする。サムネスレッドにお礼を投稿する。 |
| 動画またはサムネの修正を依頼 | 修正対象のタスクのみを制作中列へ戻す | 対象を作業中にし、対応するスレッドに担当者メンション・修正内容・再納品ボタンを投稿する。サムネの修正依頼は確認待ちのときに行う。 |
| 動画またはサムネを承認して完了 | 承認対象のタスクのみをチームの完了列へ移動 | 対象を完了にし、対応するスレッドに担当者メンションと承認メッセージを投稿する。サムネは制作中でも承認でき、画像納品前の途中終了にも使える。 |

動画とサムネは独立して進行する。一方の納品・修正・承認によって、もう一方のタスク列は変更しない。承認先は表示名ではなく完了列の設定で特定する。オーナーが共有資料URLを追加しても納品とは扱わず、列を移動しない。

### 依頼編集とタスク削除

1. 依頼の完パケ納期を変更した場合は、動画編集タスクと関連サムネイル制作タスクの期限を更新する。編集時にも作成時と同じ日付の順序を検証する。
2. タスク管理から動画編集タスクを削除した場合は、対応する動画依頼カードと関連サムネイル制作タスクも削除する。
3. サムネイル制作タスクだけを削除した場合は、依頼とのサムネの関連付けを解除し、動画依頼カードと動画編集タスクは残す。
4. タスクや依頼を削除しても、作成済みのDiscordスレッドは削除しない。
