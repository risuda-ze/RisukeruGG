# notification requirements

## 通知

- **NO-001**: 通知カテゴリ（4 種類）:
  - **コラボ関係**: セッション作成・回答受信・日程確定・キャンセル
  - **タスク**: アサイン・カラム変更（他者による変更）
  - **予定リマインダー**: 全スケジュールエントリの開始 1 時間前・15 分前
  - **システム**: チーム参加・ロール変更・メンバー削除
- **NO-002**: PARTY ユーザーは設定ページで各カテゴリのアプリ内通知とプッシュ通知を個別 ON/OFF 可能（4 カテゴリ × 2 種類 = 最大 8 トグル）
- **NO-003**: LIGHT ユーザーはシステム通知カテゴリのアプリ内通知のみ受信可能。他カテゴリ設定変更時は PARTY プランへのアップグレード案内を表示
- **NO-004**: PARTY ユーザーは PWA のプッシュ通知を許可・拒否可能
- **NO-005**: プッシュ通知を許可した PARTY ユーザーには、アプリを閉じていてもユーザーが ON にしているカテゴリのイベントで OS 通知が届く
- **NO-006**: 通知は既読・未読を管理し、一覧ページで未削除の履歴を確認可能
- **NO-007**: 通知をクリック・タップすると、対象エントリの詳細ページに遷移
- **NO-008**: アプリ内通知は受信者ごとに 1 件ずつ生成し、`notifications/{notificationId}` に保存する
- **NO-009**: プッシュ通知の配送先は `users/{uid}/notificationEndpoints/{token}` に端末単位で保持する
- **NO-010**: 1 ユーザーは複数の NotificationEndpoint を持てるものとし、複数端末・複数ブラウザへの配信に対応する
- **NO-011**: NotificationEndpoint には `platform`, `clientType`, `browser`, `permission`, `lastSeenAt`, `invalidAt`, `invalidReason` を保持できる
- **NO-012**: 無効 token と判定した NotificationEndpoint は `invalidAt` と `invalidReason` を記録し、後続の配信対象から除外できる
- **NO-013**: 通知カテゴリごとの受信設定は `users/{uid}/notificationSettings/default` で管理する

## 補足

- 通知カスタマイズ粒度は 4 カテゴリ（コラボ関係 / タスク / 予定リマインダー / システム）ごとに、アプリ内通知とプッシュ通知を個別 ON/OFF する単位を指す

## 廃止済みルール

- 以下は通知削除仕様の変更前に採用していた旧ルールであり、履歴参照のために残す。現行仕様としては採用しない
- **OLD-NO-014**: ユーザーは自分が受信者である通知を 1 件ずつ手動で削除できる
- **OLD-NO-015**: ユーザーは自分が受信者である通知を一覧上から全件一括で削除できる
- **OLD-NO-016**: 未読通知も既読通知と同様に削除可能とする
- **OLD-NO-017**: 手動削除した通知は論理削除せず、`notifications/{notificationId}` から物理削除する
