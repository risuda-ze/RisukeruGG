## ユビキタス言語

| 用語                 | 定義                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------- |
| **LIGHTユーザー**    | LIGHTプラン（無料）を利用しているユーザー                                                   |
| **PARTYユーザー**    | PARTYプラン（有料）を利用しているユーザー                                                   |
| **チーム（TEAM）**   | ゲーム配信者グループ。チームコードを入力することでチームに参加できる                        |
| **チームコード**     | チームへの参加に使用する固有の英数字コード。Owner/Editor が設定画面から確認・リセットできる |
| **LIGHTプラン**      | 無料プラン。チームメンバー上限 2 名、タスク月 5 件、コラボ月 3 件等の制限あり               |
| **PARTYプラン**      | 有料プラン。全機能無制限、バナー広告なし                                                    |
| **Owner**            | チームの全権限を持つロール。チーム作成者が自動付与される                                    |
| **Editor**           | スケジュール・タスクの作成・編集ができるロール。チームコードで参加したユーザーに付与        |
| **Viewer**           | 閲覧のみ可能なロール。Owner が設定から変更できる                                            |
| **ソロチーム**       | 初回ログイン時に自動生成される自分だけのチーム                                              |
| **コラボセッション** | コラボ日程調整の単位。`open` / `confirmed` / `cancelled` / `expired` のステータスを持つ     |

## 概要

ゲーム配信者（Twitch・YouTube）およびその制作チームを対象とした、配信者特化型チームスケジュール管理 Web アプリ。配信枠の共有管理・コラボ日程調整・制作タスク管理を一元化し、配信者が本業（配信）に集中できる環境を提供する。

**技術スタック**: Next.js 14（App Router）/ TypeScript / Tailwind CSS / Zustand / Firebase（Auth・Firestore・Storage・Cloud Functions・FCM）/ Vercel / pnpm / ESLint+Prettier / Vitest / Playwright

## 機能要件

### 1. 認証・アカウント管理（spec 001）

- **FR-001**: 認証は Firebase Authentication の Google OAuth2 のみ。メールアドレス+パスワード認証は提供しない
- **FR-002**: 初回 Google ログイン時、ユーザーは自動的に LIGHT プランとして登録され、ソロチームの Owner となる
- **FR-003**: 認証セッションは自動リフレッシュ。不意なログアウトは発生しない
- **FR-004**: 未認証ユーザーが保護ページにアクセスした場合、ログインページへリダイレクト
- **FR-005**: Google OAuth2 で取得したトークンは Google カレンダー連携にも再利用（追加の OAuth フロー不要）

---

### 2. プラン管理（spec 001）

- **FR-P001**: LIGHT プラン（無料）と PARTY プラン（有料）の 2 プランを提供
- **FR-P002**: LIGHT プランの制限:
  - チームメンバー上限: 2 名（自分を含む）
  - スケジュール登録: 無制限
  - タスク登録: 月 5 件まで（当月作成数）
  - コラボ調整作成: 月 3 件まで（当月作成数）
  - 通知: システム通知カテゴリのアプリ内通知のみ（プッシュ通知・他カテゴリ不可）
  - バナー広告: あり（コンテンツ閲覧を妨げない位置）
- **FR-P003**: PARTY プランは全機能無制限・バナー広告なし
- **FR-P004**: プランはユーザーごとの個別課金。チーム Owner による代理課金は不可
- **FR-P005**: 3 名以上のチームへの参加には全メンバーの PARTY プランが必要。条件不満足時は参加をブロックし既存の全 LIGHT メンバーにシステム通知を送る
- **FR-P006**: LIGHT プランの月次上限到達時は操作をブロックし PARTY プランへのアップグレード案内を表示
- **FR-P006a**: LIGHT プランの月次カウント（タスク数・コラボ数）は毎月 1 日 0:00（JST）に自動リセット
- **FR-P007**: LIGHT プランのバナー広告はページ下部等のコンテンツを妨げない位置に表示
- **FR-P008**: フェーズ 1 の「PARTY プランへアップグレード」CTA は外部申し込みページ（Google Form 等）へ遷移。URL 未設定時はボタン非表示

### 3. チーム管理（spec 001 / 003）

- **FR-006**: 認証済みユーザーはチームを作成でき、自動的に Owner ロールが付与される
- **FR-007**: チームには固有のチームコードが自動生成。Owner はいつでもリセット可能。旧コードは即時無効化
- **FR-008**: ユーザーは設定画面でチームコードを入力してチームに参加。プラン制限を超える場合は参加をブロック
- **FR-009**: チームコードで参加したユーザーには Editor ロールが付与。Owner がその後ロールを変更可能
- **FR-010**: 3 つのロール: Owner（全権限）、Editor（スケジュール・タスクの作成・編集）、Viewer（閲覧のみ）
- **FR-011**: Owner はメンバーのロールを Editor・Viewer 間で変更可能
- **FR-012**: Owner はメンバーをチームから Kick 可能（Owner 自身を除く）
- **FR-013**: チームから削除されたメンバーはチームのデータに一切アクセス不可
- **FR-014**: メンバー削除時、未完タスクは「未アサイン」に移行し Owner に通知。完了済みタスク・過去スケジュールは保持（作成者名は「元メンバー」表示）
- **FR-015**: ~~1 ユーザーが同時に所属できるチームは 1 つのみ~~ → **spec 003 で変更**: 複数チームへの同時所属が可能
- **FR-015a**: 初回 Google ログイン時、ユーザーは自動的にソロチームの Owner として登録
- **FR-015b**: ユーザーはいつでも特定チームから退出可能。Owner が退出する場合は所有権移譲またはチーム解散が必要
- **FR-016**: チームスイッチャーで任意のチームをアクティブチームに切り替え可能（spec 003 追加）

### 4. スケジュール管理（spec 001 / 003 / 004 / 007）

- **FR-017**: Owner・Editor はスケジュールエントリを CRUD できる
- **FR-018**: Viewer はスケジュールエントリを閲覧のみ（CUD 不可）
- **FR-019**: スケジュールエントリの必須項目: タイトル・開始日時・終了日時・配信プラットフォーム（YouTube/Twitch/両方）・ステータス（予定/LIVE/終了/キャンセル）・説明・参加メンバー・コラボ相手（任意）
- **FR-020**: 動画投稿予定エントリには紐付くタスクの進捗フィールドを追加
- **FR-021**: スケジュールエントリの保存後、チームの全メンバーに 1 秒以内に反映
- **FR-022**: カレンダーは週ビューと月ビューを切り替えて表示
- **FR-022a**: 週ビュー・月ビューは日曜始まり（spec 003 追加）
- **FR-023**: 同時間帯に複数エントリが存在する場合は視覚的に重複を示す（ブロックはしない）
- **FR-024**: ユーザーは自分の Google カレンダーをリスケるGG カレンダーと双方向同期可能
- **FR-024a**: Google カレンダー同期失敗時は設定ページ上部にエラーバナーを表示し手動再同期ボタンを提供。サイレント失敗は不可
- **FR-024b**: Google カレンダー連携の認証切れ時はバナーに「再認証が必要です」と表示し再認証フローへ誘導
- **FR-025**: 配信ステータスが LIVE に変更されると視覚的に LIVE 表示（赤バッジ+パルスアニメーション）
- **FR-026**: スケジュール作成フォームは「終日」ボタンを提供し、`allDay: true` フラグで開始・終了を同日の 00:00:00 に統一保存（spec 004 更新）
- **FR-027**: 開始日時入力時、終了日時が未設定の場合は自動的に 2 時間後を設定（spec 003 追加）
- **FR-028**: スケジュールの説明フィールドはマークダウン記法をサポート。閲覧時は `MarkdownView` でレンダリング、編集時は `Textarea` コンポーネントを使用（spec 003 追加 / spec 007 更新）
- **FR-029**: フォームを「確定」以外の操作で閉じた場合、入力内容を自動保存し次回起動時に復元（spec 003 追加）
- **FR-030**: `DateTimeInput` は `type="date"` と `type="time"` の 2 input に分割してブラウザ非依存を実現（spec 007 更新）

### 6. コラボ日程調整（spec 001 / 004-collab-improvements / 005-collab-task-copy / 006）

#### コア機能

- **FR-C001**: Owner・Editor はコラボ日程調整セッションを作成可能。セッションには: タイトル・コラボ相手名（フリーテキスト）・候補日程（最低 1 件・最大 5 件）・有効期限（1〜30 日）を含む
- **FR-C002**: セッション作成時に共有 URL が自動生成。Discord 等の SNS で手動共有する前提（メール自動送信なし）
- **FR-C003**: 共有 URL にアクセスしたコラボ相手は認証なしで各候補日時に対して OK / NG / 代替日提案を記録可能
- **FR-C004**: 有効期限切れの共有 URL は「期限切れ」ページを表示
- **FR-C005**: 日程確定時に共有 URL は即時無効化。打診側チームのカレンダーにコラボスケジュールエントリが自動登録
- **FR-C006**: コラボセッションのステータスは `open`（回答受付中）/ `confirmed`（確定）/ `expired`（期限切れ）/ `cancelled`（キャンセル）で管理
- **FR-C007**: Owner・Editor はいつでもコラボセッションをキャンセル可能。共有 URL が無効になり確定済みの場合はカレンダーエントリも削除

### 7. 通知（spec 001）

- **FR-N001**: 通知カテゴリ（4 種類）:
  - **コラボ関係**: セッション作成・回答受信・日程確定・キャンセル
  - **タスク**: アサイン・カラム変更（他者による変更）
  - **予定リマインダー**: 全スケジュールエントリの開始 1 時間前・15 分前
  - **システム**: チーム参加・ロール変更・メンバー削除
- **FR-N002**: PARTY ユーザーは設定ページで各カテゴリのアプリ内通知とプッシュ通知を個別 ON/OFF 可能（4 カテゴリ × 2 種類 = 最大 8 トグル）
- **FR-N003**: LIGHT ユーザーはシステム通知カテゴリのアプリ内通知のみ受信可能。他カテゴリ設定変更時は PARTY プランへのアップグレード案内を表示
- **FR-N004**: PARTY ユーザーは PWA のプッシュ通知を許可・拒否可能
- **FR-N005**: プッシュ通知を許可した PARTY ユーザーには、アプリを閉じていてもユーザーが ON にしているカテゴリのイベントで OS 通知が届く
- **FR-N006**: 通知は既読・未読を管理し、一覧ページで全履歴を確認可能
- **FR-N007**: 通知をクリック・タップすると、対象エントリの詳細ページに遷移

- **FR-UI-010**: TopBar の通知ベルをクリックすると通知ドロップダウン（最大 4 件）を表示
- **FR-UI-011**: 通知ドロップダウンはドロップダウン外クリックで閉じる

### 9. PWA・オフライン（spec 001）

- **FR-PWA-001**: アプリは PWA として Android のホーム画面に追加でき、インストールプロンプトが表示される
- **FR-PWA-002**: Service Worker は直近のスケジュールデータをキャッシュし、オフライン時でも閲覧可能
- **FR-PWA-003**: オフライン時に書き込み操作を試みたユーザーには接続を要求するメッセージを表示

## 非機能要件（spec 001）

- **NFR-001**: 初回表示（LCP）は 4G 回線のモバイル端末で 3 秒以内
- **NFR-002**: インタラクション応答（INP）は 100ms 以内
- **NFR-003**: リアルタイムデータ更新は全チームメンバーに 1 秒以内に反映
- **NFR-004**: サービス稼働率 99.5% 以上
- **NFR-005**: チームメンバーのデータは自チームのデータのみ読み書き可能（クロスチームアクセス禁止）
- **NFR-006**: ロールに応じた書き込み権限制御はサーバーサイドで強制（クライアントのみの制御は不可）
- **NFR-007**: 全通信は HTTPS 経由
- **NFR-008**: PC（Chrome/Edge/Firefox 最新 2 バージョン）と Android Chrome（最新 2 バージョン）で動作
- **NFR-009**: UI は WCAG 2.1 AA 基準のアクセシビリティを満たす
- **NFR-010**: カレンダーと通知は JST（日本標準時）基準で表示（フェーズ 1）
- **NFR-011**: プランの月次制限値はバックエンドで強制（クライアント側のみの制御は不可）
- **NFR-012**: TypeScript strict モードでコンパイルエラーゼロ
- **NFR-013**: ソースコード内のコメントは日本語。変数名・コンポーネント名は英語
