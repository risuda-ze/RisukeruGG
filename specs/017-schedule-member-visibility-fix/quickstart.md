# Quickstart: メンバー予定表示バグ修正の検証

**Feature**: 017-schedule-member-visibility-fix | **Date**: 2026-06-27

## 前提

- 同一チームに所属する 2 アカウント（A・B）を用意する。
- アカウント A は Google カレンダー連携済みで、当日〜2 週間以内に少なくとも 1 件の予定がある。

## 実装後のデプロイ手順

```bash
# 1. ルール構文を検証
firebase firestore:rules:validate

# 2. ルールをデプロイ
firebase deploy --only firestore:rules

# 3. （failed-precondition が出た場合のみ）インデックスをデプロイ
firebase deploy --only firestore:indexes
```

## ローカル起動

```bash
pnpm dev          # http://localhost:3000
pnpm typecheck    # 型チェック
pnpm lint         # ESLint
pnpm test         # ユニットテスト（memberCalendarVisibility.test.ts を含む）
```

## 検証シナリオ（受け入れ基準対応）

### シナリオ 1: メンバー予定が表示される（AC-1）

1. アカウント A でログインする（ログイン時に Google 予定がチームへ同期される）。
2. ブラウザを切り替え、アカウント B でログインしスケジュール画面を開く。
3. 右上の「メンバーの予定」ボタンをクリックする。
4. **期待**: ボタンが「メンバー表示中」になり、カレンダーに A の予定（「{A の表示名} の予定」）が表示される。
5. **期待（修正前）**: ボタンは切り替わるが予定が表示されない。

### シナリオ 2: トグル OFF で非表示（AC-2）

1. 「メンバー表示中」ボタンを再クリックする。
2. **期待**: メンバー予定がカレンダーから消える。

### シナリオ 3: 詳細ポップアップ（AC-3）

1. トグル ON 状態で A のメンバー予定イベントをクリックする。
2. **期待**: 「メンバーの予定」ラベル付きの読み取り専用ポップアップが開き、タイトルと時間が表示される。

### シナリオ 4: 自分の予定の二重表示防止（AC-4）

1. アカウント A 自身がスケジュール画面で「メンバーの予定」を ON にする。
2. **期待**: A の Google カレンダー直接取得分とメンバー同期分が二重に表示されない（同期分が除外される）。

### シナリオ 5: 他チーム漏洩なし（AC-5）

1. A・B とは別チーム C のメンバーがログインし「メンバーの予定」を ON にする。
2. **期待**: A・B の予定は表示されない。

### シナリオ 6: エラーの可視化（AC-6）

1. （開発時）ルール未デプロイの状態でトグルを ON にする。
2. **期待**: ブラウザコンソールにメンバー予定購読の失敗エラーが記録される（サイレント握り潰しでない）。

### シナリオ 7: 回帰確認（AC-7）

1. チーム予定の作成・編集・削除が従来どおり動作する。
2. Google カレンダー個人予定が従来どおり表示される。
3. `pnpm test` が全件パスする。

## トラブルシュート

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| 依然として予定が出ない & コンソールに `permission-denied` | ルール未デプロイ／キャッシュ | `firebase deploy --only firestore:rules` を再実行 |
| コンソールに `failed-precondition`（index リンク付き） | コレクショングループ単一フィールドインデックス未整備 | リンクから作成するか `firestore.indexes.json` に `events.teamId` の collection-group 単一フィールドインデックスを追加してデプロイ |
| 他チームの予定まで見える | ルールの `teamId` 検証漏れ | `allow read: if isTeamMember(resource.data.teamId)` になっているか確認 |
