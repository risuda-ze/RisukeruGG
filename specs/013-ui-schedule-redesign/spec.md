## User Scenarios & Testing

### User Story 1 — サイドバーでナビゲーションする (Priority: P1)

ユーザーはサイドバーの大項目（メイン・設定・各種連携・お問い合わせ）と小項目から各画面に遷移できる。

**Acceptance Scenarios**:

1. **Given** アプリが表示されている, **When** 「メイン > AIに相談」をクリック, **Then** /chat に遷移する
2. **Given** アプリが表示されている, **When** 「メイン > スケジュール」をクリック, **Then** /schedule に遷移する
3. **Given** アプリが表示されている, **When** 「設定 > チーム管理」をクリック, **Then** /team に遷移する
4. **Given** アプリが表示されている, **When** 「お問い合わせ」をクリック, **Then** /settings/contact に遷移する（大項目として独立表示）
5. **Given** アプリが表示されている, **When** 「各種連携 > Discord連携」をクリック, **Then** 対応するページへ遷移する

---

### User Story 2 — トップバーでアカウント操作する (Priority: P1)

ユーザーはトップバー右端のアカウントアイコンをクリックし、チーム変更モーダル・個人設定・ログアウトを操作できる。

**Acceptance Scenarios**:

1. **Given** ログイン済み, **When** トップバーのアバターをクリック, **Then** アカウントドロップダウンが表示される（チーム変更・個人設定・ログアウトの3項目）
2. **Given** ドロップダウンが開いている, **When** 外側をクリック, **Then** ドロップダウンが閉じる
3. **Given** ドロップダウンが開いている, **When** 「ログアウト」をクリック, **Then** ログアウトが実行される
4. **Given** ドロップダウンが開いている, **When** 「チーム変更」をクリック, **Then** モーダルが開き、既存の TeamSwitcher UIでチームを切り替えられる

---

### User Story 3 — モバイルで下部ツールバーを使う (Priority: P1)

モバイル表示時、画面下部のツールバーからスケジュール・タスク・AIに相談・コラボ調整・その他に素早くアクセスできる。「その他」押下で右からドロワーが開く。

**Acceptance Scenarios**:

1. **Given** モバイル表示, **When** 画面を表示, **Then** 下部に5項目のツールバーが表示される（スケジュール・タスク・AIに相談・コラボ・その他）
2. **Given** モバイルツールバーが表示されている, **When** 「AIに相談」ボタンをタップ, **Then** ボタンが強調表示され /chat へ遷移する
3. **Given** モバイルツールバーが表示されている, **When** 「その他」をタップ, **Then** 右からドロワーが開き、設定・連携・お問い合わせ項目が表示される

---

### User Story 4 — スケジュール一覧を月/週表示で確認する (Priority: P1)

ユーザーはスケジュール画面で月表示/週表示を切り替え、予定カードを確認できる。

**Acceptance Scenarios**:

1. **Given** スケジュール画面が表示されている, **When** 「週」ボタンをクリック, **Then** 週表示に切り替わる
2. **Given** 月表示表示, **When** 「›」ボタンをクリック, **Then** 翌月が表示される
3. **Given** 別の月/週を表示中, **When** 「今日」ボタンをクリック, **Then** 当日の月/週に戻る
4. **Given** 月表示, **When** 日付の数字をクリック, **Then** その週の週表示に切り替わる
5. **Given** 月表示, **When** 日付の数字にホバー, **Then** その日の予定一覧がツールチップで表示される
6. **Given** 予定が存在する, **When** カレンダーが描画される, **Then** 予定カードがpop-scaleアニメーションで表示される

---

### User Story 5 — 予定を追加・編集・削除する (Priority: P1) ★ Updated

ユーザーは「予定追加ボタン」またはカレンダーセルクリックから**統一モーダル**を開き、予定を追加・編集・削除できる。追加と編集は同一UI（ScheduleModal）を使用する。

**Why updated**: 旧来の ScheduleForm（追加用）と ScheduleDetailModal（編集用）が2つに分かれており、デザイン仕様と異なる。統合することでコードを簡素化し、UXを統一する。

**Acceptance Scenarios**:

1. **Given** スケジュール画面, **When** 「予定追加」ボタンをクリック, **Then** 「予定を追加」ヘッダーの870px幅モーダルが開く
2. **Given** スケジュール画面, **When** 既存の予定カードをクリック, **Then** 「予定を編集」ヘッダーの870px幅モーダルが開き、既存データが入力されている
3. **Given** モーダルが開いている, **When** 日付フィールドのカレンダーアイコンをクリック, **Then** ミニカレンダーがポップアップする
4. **Given** 終日ボタンがOFF, **When** 終日トグルをクリック, **Then** 終日ONになり時刻入力が非表示になる
5. **Given** 終日ボタンがON, **When** 終日トグルを再度クリック, **Then** 終日OFFになり時刻入力が再表示される（**双方向トグル**）
6. **Given** タイトルを入力して「保存」をクリック, **When** 処理完了, **Then** モーダルが閉じ予定がカレンダーに表示される
7. **Given** 既存予定の編集モーダル, **When** 「削除」ボタンをクリック, **Then** 確認後に予定が削除される
8. **Given** 新規追加モーダル, **When** フッターを確認, **Then** 「削除」ボタンが表示されない（新規追加時は非表示）
9. **Given** 編集モーダルが開いている, **When** 説明欄を確認, **Then** マークダウン編集（プレビュー切替）が機能する
10. **Given** 編集モーダルのヘッダーをドラッグ, **When** マウスを動かす, **Then** モーダルが画面内で追従して移動する
11. **Given** 編集モーダルのコメント欄, **When** コメントを入力して送信, **Then** コメントスレッドに追加される

---

### User Story 6 — UIコンポーネントのホバー挙動がデザイン仕様に一致する (Priority: P2) ★ New

ユーザーがバッジ・アバター・ボタンにホバーすると、デザイン仕様（DESIGN.md）通りのアニメーションと色変化が起こる。

**Acceptance Scenarios**:

1. **Given** ページ上にバッジ（Badge）がある, **When** ホバー, **Then** `hop` アニメーション（上方向バウンス）が発火する
2. **Given** ページ上にアバター（Avatar）がある, **When** ホバー, **Then** `hop` アニメーションが発火する
3. **Given** Primary ボタンにホバー, **When** 確認, **Then** 背景色がピンク（#ec4f95）に変化しピンクグローが付く
4. **Given** Ghost ボタンにホバー, **When** 確認, **Then** ボーダー・テキストがピンク系に変化する

---

### User Story 7 — ハイライトカラー・色定義が DESIGN.md に準拠する (Priority: P2) ★ New

globals.css のカスタムプロパティが DESIGN.md の仕様と一致し、アプリ全体でデザインシステムが正しく適用される。

**Acceptance Scenarios**:

1. **Given** アプリを表示, **When** Primary ボタンを確認, **Then** 背景色が `--primary: #7f77dd`（パープル）である
2. **Given** アプリを表示, **When** DevTools で CSS 変数を確認, **Then** `--card-border`・`--glow-primary` などが DESIGN.md の値に一致する
3. **Given** アプリを表示, **When** 通知バッジを確認, **Then** `.ds-badge--primary` は `var(--primary-950)` 背景・`var(--primary-300)` テキストで表示される

---

### User Story 8 — ヒントバーを非表示にする (Priority: P3)

ユーザーはスケジュール画面のヒントバーを×で閉じられ、ヘッダーの「?」ボタンで再表示できる。

**Acceptance Scenarios**:

1. **Given** 初回表示, **When** スケジュール画面を開く, **Then** 操作説明ヒントバーが表示される
2. **Given** ヒントバーが表示されている, **When** 「×」をクリック, **Then** バーが閉じ、再読み込み後も非表示になる
3. **Given** ヒントバーを閉じた, **When** ヘッダーの「?」ボタンをクリック, **Then** ヒントバーが再表示される

---

### Edge Cases

- 予定が0件の月/週ではカレンダーが正しく表示される（空のグリッド）
- 複数日予定は日付行の下・単日予定の上に表示される（順序バグ防止）
- 1日セルに予定が4件以上ある場合、3件を表示し残りは「+N件」テキストで折りたたまれる
- モバイルドロワーを開いた状態でスクリムをタップするとドロワーが閉じる
- アカウントメニューはドロップダウン外クリックで自動的に閉じる
- 折りたたんだサイドバー状態でもナビゲーションが機能する
- 統合モーダルで「追加」と「編集」は同じフォームを共有するが、モーダルヘッダー文言が異なる
- 終日トグルはON→OFF→ONと何度でも切り替えられる

## Requirements

### Functional Requirements

- **FR-001**: サイドバーは「メイン」「設定」「お問い合わせ（大項目）」「各種連携」の4大項目を持つ
- **FR-002**: 「お問い合わせ」は大項目として設定/個人設定の下・各種連携の上に独立配置し、直遷移する
- **FR-003**: トップバーは左にタイトル+説明文、右にお問い合わせボタン+通知ベル+アカウントメニューを配置する。説明文（subtitle）は全画面で設定する
- **FR-004**: アカウントメニューはアバタークリックで開閉するドロップダウンで、ログアウト操作を含む
- **FR-005**: モバイル用ツールバーは スケジュール・タスク・AIに相談（強調）・コラボ調整・その他 の5項目を持つ
- **FR-006**: 「その他」ドロワーは右からスライドして開く
- **FR-007**: AIフローティングボタン（きらきらアイコン）を全画面右下に配置する
- **FR-008**: スケジュール画面ヘッダーは左に週/月トグル+YYYY年MM月、右に予定追加+メンバー表示切替+前後/今日ナビを配置する
- **FR-009**: 月表示のカレンダーは「日付行 → 複数日バー行 → 単日予定グリッド」の順に積む
- **FR-010**: 予定カードはpop-scaleアニメーションで出現し、左から「アイコン」「開始時間」「タイトル」を表示する
- **FR-011**: 複数日予定は関連する全日付セルに跨って表示し、単日予定より上（前）に並べる
- **FR-012**: 日付数字クリックで当日の週表示に切り替わる
- **FR-013**: 日付数字ホバーで当日の予定一覧ツールチップが表示される
- **FR-014**: スケジュール詳細はモーダル（幅870px）で開く。追加と編集は同一の `ScheduleModal` コンポーネントを使用する
- **FR-015** ★: 日付入力フィールドは「テキストボックス + カレンダーアイコン」形式で、アイコンクリックでミニカレンダーがポップアップする
- **FR-016** ★: 終日トグルは開始日時ラベルの横に右揃えで配置し、**双方向トグル**（ON→OFFも可能）とする
- **FR-017**: 詳細モーダルのフッターは右から「キャンセル」「削除（新規追加時非表示）」「保存」の順に配置する
- **FR-018**: 操作説明ヒントバーは×で閉じられ、localStorageで非表示状態を永続化し、?ボタンで再表示できる
- **FR-019**: 広告バナーは今回スコープ外（将来対応）
- **FR-020**: レスポンシブデザイン（md breakpoint でサイドバー↔ツールバー切替）に対応する
- **FR-021**: 1日セルに表示できる予定は最大3件（複数日バー含む）。4件目以降は「+N件」テキストで折りたたみ、クリックで当該日の週表示に切り替える
- **FR-022**: `MobileToolbar.tsx` 実装後、`BottomNav.tsx` を削除する
- **FR-023**: スケジュール・タスク管理・AIに相談・コラボ調整・チーム管理・通知管理・個人設定の全画面 TopBar に subtitle を追加する
- **FR-024** ★ New: 予定の新規追加と編集を単一の `ScheduleModal` コンポーネントに統合する（旧 ScheduleForm + ScheduleDetailModal → 新 ScheduleModal）。旧 ScheduleDetailModal が持つコメントスレッド・ドラッグ移動・マークダウン説明編集の3機能は新 ScheduleModal に移植する。入力内容は localStorage に自動保存（`saveDraft/loadDraft`）し、次回起動時に復元する
- **FR-025** ★ New: `Avatar` コンポーネントに `ds-avatar` クラスを追加し、ホバー時に `hop` アニメーションが発火するようにする
- **FR-026** ★ New: Primary/Ghost/Subtle ボタンのホバー色変化（→ピンク系）が `globals.css` の `.btn--*:hover` 定義により正しく機能することを確認・修正する
- **FR-027** ★ New: `docs/DESIGN.md` を styles.css との差分に基づき以下を更新する:
  - CSS Variables セクションに `--info-dim`・`--card-border/raised`・ピンクパレット（`--pink`〜`--glow-pink`）・`--glow-mult`・`--font-head/body`・`--space-3xl`・`--radius-2xl`・Primary 全段を追加する
  - Interaction States のボタン hover 定義を「ピンクシフト（`var(--pink)` 背景）」に更新する
  - Motion テーブルに badge/tag/avatar hover → `hop` アニメーション行を追加する
  - Keyframes セクションに `drop-down`・`ring-spin`・`bar-grow`・`hop` を追加する

## Success Criteria

- **SC-001**: サイドバー全項目（8小項目+1直遷移項目）がクリック可能で正しいパスへ遷移する
- **SC-002**: アカウントドロップダウンが開閉し、ログアウトが実行できる
- **SC-003**: モバイル（375px幅）でツールバーが表示され「その他」ドロワーが右から開く
- **SC-004**: スケジュール月表示で複数日予定が日付数字の下・単日予定の上に正しく表示される
- **SC-005**: 統合モーダルが870px幅で開き、追加・編集・削除が成功する
- **SC-006**: 終日トグルがON/OFF双方向に動作する
- **SC-007**: Primary ボタンのホバー時に背景がピンク（#ec4f95）に変化する
- **SC-008**: Avatar ホバー時に hop アニメーションが発火する
- **SC-009**: TypeScriptコンパイルエラー・ESLintエラーが0件

## Assumptions

- 既存の Tailwind CSS カスタムプロパティ（`var(--primary)`, `var(--surface)` 等）はそのまま利用する
- `pop-scale` アニメーションは `opacity: 1` ベースで、`transform: scale` のみを変化させる
- アカウントメニューのユーザー情報は既存の `useAuthStore` から取得する
- 統合モーダルの「追加」側は旧 ScheduleForm の保存ロジックを引き継ぐ
- 統合モーダルの「編集」側は旧 ScheduleDetailModal の保存・削除ロジックを引き継ぐ
- 広告バナーは今回スコープ外（specs/013-ui-schedule-redesign/deprecated.md に将来対応として記録）
