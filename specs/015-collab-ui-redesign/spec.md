# Feature Specification: コラボ調整機能 UI リデザイン

**Feature Branch**: `015-collab-ui-redesign`
**Created**: 2026-06-09
**Status**: Draft
**Design Source**: `specs/015-collab-ui-redesign/design/gg-readme/project/コラボ.html`

---

## 概要

コラボ調整機能の画面を全面リデザインする。コラボ一覧画面とコラボ詳細画面（ポップアップ）を、デザインファイル（`コラボ.html`）に基づいた新UIに置き換える。新ステータス体系（準備中・募集中・確定）・横長行カード・左右分割詳細フォーム・カード型候補日時エディタ・チャット形式コメント欄・レスポンシブデザインを実装する。

---

## User Scenarios & Testing

### User Story 1 - コラボ一覧の閲覧 (Priority: P1)

配信者が `/collabs` を開き、「調整中のコラボ」ゾーンと「予定確定したコラボ」ゾーンに案件が振り分けて表示されている。

**Why this priority**: 一覧画面がすべての操作の起点。

**Independent Test**: `/collabs` にアクセスし、2つのゾーンと横長行カードが表示されることを確認。

**Acceptance Scenarios**:

1. **Given** コラボが存在する, **When** `/collabs` を開く, **Then** `draft`・`open`（recruit相当）のコラボが「調整中のコラボ」ゾーンに、`confirmed`（fixed相当）が「予定確定したコラボ」ゾーンに表示される
2. **Given** コラボカードが表示されている, **When** カードを確認する, **Then** タイトル・ステータスバッジ・参加者アバター（重ね）・残り回答者数+プログレスバー・詳細ボタン・削除ボタンが表示される
3. **Given** ゾーンにコラボが0件, **When** 画面を開く, **Then** 空状態メッセージが表示される

---

### User Story 2 - 新規コラボ作成 (Priority: P1)

「コラボ調整開始」ボタンをクリックし、詳細ポップアップで新規コラボを作成する。

**Why this priority**: コラボ作成はコア機能。

**Independent Test**: ボタンクリック → ポップアップ → 必須項目入力 → 保存 → 一覧反映。

**Acceptance Scenarios**:

1. **Given** 一覧画面, **When** 「コラボ調整開始」ボタンをクリック, **Then** 詳細ポップアップが新規モードで開く（ステータス初期値=準備中、削除ボタン非表示）
2. **Given** 新規モードで必須項目が未入力, **When** 保存する, **Then** バリデーションエラーが表示される
3. **Given** タイトル・参加者・候補日時（1件以上）が入力済み, **When** 保存する, **Then** コラボが作成され一覧に追加される

---

### User Story 3 - コラボ編集・ステータス更新 (Priority: P2)

既存コラボの詳細ボタンから編集し、ステータスを変更する。

**Acceptance Scenarios**:

1. **Given** コラボカードが表示されている, **When** 「詳細」ボタンをクリック, **Then** 詳細ポップアップが編集モードで開く（削除ボタン表示）
2. **Given** ステータスを「募集中」→「確定」に変更して保存, **When** 保存する, **Then** カードが「予定確定したコラボ」ゾーンに移動する
3. **Given** 編集モードで削除ボタンをクリック, **Then** 確認後コラボが削除される

---

### User Story 4 - 候補日の参加可否確認とホバー表示 (Priority: P2)

詳細フォームの候補日カードに `〇N △M ×K` が表示され、ホバーで参加者名が確認できる。

**Acceptance Scenarios**:

1. **Given** 参加者が回答済みのコラボを詳細で開く, **When** 候補日カードを確認, **Then** `〇{ok} △{maybe} ×{ng}` が表示される
2. **Given** 候補日カードの `〇N` 数字をホバー, **Then** 参加可能な参加者のアバターと名前がツールチップで表示される

---

### User Story 5 - コメント/メモの利用 (Priority: P3)

詳細ポップアップ右ペインでコメントを投稿・閲覧できる。

**Acceptance Scenarios**:

1. **Given** 詳細ポップアップが開いている, **When** コメントを入力して送信, **Then** 右ペインにアバター・名前・テキスト・日時が表示される
2. **Given** コラボ回答フォームからコメントが投稿されている, **When** 詳細ポップアップを開く, **Then** 回答者コメントが右ペインに表示される（既定の単色アイコン）

---

### Edge Cases

- 参加者0人で保存 → バリデーションエラー
- 候補日0件で保存 → バリデーションエラー
- モバイル（390px）: ゾーン切替ピルタブ、コンパクトカード、詳細は縦1カラム
- 参加者が4名超: 最大4件表示 + `+N` バッジ

## Requirements

### 機能要件 — コラボ一覧画面

| ID | 要件 |
|----|------|
| R-001 | 「調整中のコラボ」ゾーン: `draft`+`open` のコラボを横長行カードで表示 |
| R-002 | 「予定確定したコラボ」ゾーン: `confirmed` のコラボを表示 |
| R-003 | コラボカードに タイトル・ステータスバッジ・参加者アバター（重ね4件+N）・残り回答者数+プログレスバー・詳細ボタン・削除ボタン を表示 |
| R-004 | ステータスバッジ3種: 準備中 (`draft`) / 募集中 (`open`) / 確定 (`confirmed`) |
| R-005 | 一覧画面上部のコントロールバー（追加ボタン + ? アイコン）から新規作成ポップアップを開く。バナーヘッダーは不要 |
| R-006 | 確定案件カードは回答バーの代わりに確定日時を表示する |

### 機能要件 — コラボ詳細ポップアップ

| ID | 要件 |
|----|------|
| R-010 | 左右2ペイン: 左=入力項目、右=コメント/メモ（デスクトップ: 320px固定 / モバイル: 最大高さ280pxで縦積み）|
| R-011 | 入力項目（上から順）: タイトル・ステータス・内容・候補日時・参加者 |
| R-012 | 候補日時は**カード型エディタ**: 日時カードのリスト + 「候補日時を追加」ボタン（インライン入力） |
| R-013 | 候補日カードに `〇N △M ×K` 表示。各数字ホバーで参加者アバター+名前を React state によるカスタム Tooltip（`position: absolute`）で表示 |
| R-014 | 参加者入力: プルダウン（チームメンバー選択）+ テキスト（外部ゲスト直接入力）+ 追加ボタン |
| R-015 | 追加済み参加者はチップ表示（×削除可）。ゲストには「ゲスト」バッジ |
| R-016 | 右ペインはチャット形式コメント欄（アバター・名前・テキスト・日時）+ 入力欄+送信ボタン |
| R-018 | フッターボタン（左→右）: 削除（編集時のみ・mr-auto） ｜ URLをコピー ｜ 調整を確定（open時・候補日選択必須） ｜ 保存（open時・常時有効） |
| R-019 | 新規作成時 必須: タイトル・参加者（1人以上）・候補日時（1件以上）・ステータス（初期値: 準備中）|
| R-020 | コラボ回答フォームのコメントが右ペインに表示される（アイコン=単色既定、名前=回答者名）|

### 非機能要件

| ID | 要件 |
|----|------|
| NF-001 | デザイントークン（`globals.css` CSS変数）を使用。FPSテーマ（`.cb--fps`）を適用 |
| NF-002 | モバイル（768px 以下）: `useMediaQuery` で `isMobile` を検知。一覧: ゾーン切替ピルタブ・コンパクトカード（`mcbcard`）。詳細: `md:` ブレークポイント（768px）でボトムシートレイアウト（オーバーレイ `items-end`）＋縦1カラム、モバイルではドラッグ無効。別コンポーネントは作成しない。 |
| NF-003 | 既存共通コンポーネント（`TopBar`, `Icon`, `Spinner` 等）を活用 |
| NF-004 | TypeScript strict: true 準拠。`any` 使用禁止 |

## ステータス体系（新 → 既存マッピング）

| デザイン値 | 表示名 | 既存 `CollabStatus` への対応 |
|------------|--------|------------------------------|
| `draft` | 準備中 | 新規追加 |
| `open` | 募集中 | 既存 `open`（ラベル変更: 調整中→募集中） |
| `confirmed` | 確定 | 既存 `confirmed`（ラベル変更: 予定決定→確定） |
| `expired` | 終了 | 既存 `expired`（変更なし） |
| `cancelled` | 終了 | 既存 `cancelled`（変更なし） |

## Clarifications

### Session 2026-06-09

- Q: コラボ詳細フォームにメタ情報（作成者・作成日時・最終更新者・最終更新日時）を表示しますか？ → A: 表示しない（デザイン準拠）。デザインファイル chat8 の削除を採用。`updatedBy`/`updatedAt` フィールドは Firestore には書き込むが UI には表示しない。
- Q: モバイルレスポンシブの実装方式は？ → A: 同一コンポーネント＋CSS クラス切り替え（`sch--mobile`）。`useMediaQuery` で幅を検知し、768px 以下で `sch--mobile` クラスを付与する。デザインファイルの実装方式に準拠。
- Q: 候補日の「日程確定」ボタンの振る舞いは？ → A: トグル選択 + 保存時に確定。ボタンクリックで `is-fixed` をトグル（候補日の選択状態を変更）し、「保存」ボタン押下時に Firestore を更新して `status: 'confirmed'` に移行する。
- Q: 候補日 ○△× の参加者ホバー表示方式は？ → A: React state によるカスタム Tooltip。`onMouseEnter`/`Leave` で state 切り替え、`position: absolute` のアバター+名前リストを表示。外部ライブラリ不要。
- Q: 回答フォームのコメントを詳細ポップアップに表示する方法は？ → A: `CollabComment` 型に変換して `comments[]` に保存。`CollabResponseForm` 送信時に `CollabComment` として Firestore に追記。右ペインに一元表示。アイコンは既定の単色アバター。
