# Feature Specification: コラボ再調整・復元

**Feature Branch**: `005-collab-reopen`  
**Created**: 2026-05-19  
**Status**: Draft

## User Scenarios & Testing

### User Story 1 - 確定済みコラボを再調整状態に戻す (Priority: P1)

日程確定後に都合が変わった場合、確定済みコラボを「調整中（open）」の状態に戻して、再度日程調整ができる。

**Why this priority**: コラボ確定後に出演者の都合変更や機材トラブルで日程変更が必要になるケースは頻繁にある。現状、確定を取り消す手段がなく、コラボを削除して一から作り直すしかない。

**Independent Test**: 確定済みコラボの詳細画面で「再調整する」ボタンをクリックし、ステータスが「調整中」に戻り、候補日程や参加者情報が元の状態で残っていることを確認。

**Acceptance Scenarios**:

1. **Given** コラボが `confirmed` ステータス、**When** 「再調整する」ボタンをクリックし確認ダイアログで承認、**Then** ステータスが `open` に戻り、確定日・`linkedScheduleId` がクリアされる
2. **Given** 確定時に自動作成されたスケジュールが存在する、**When** 再調整を実行、**Then** そのスケジュールは削除される（再調整のため不要になるため）
3. **Given** 再調整後のコラボ詳細画面、**When** 表示を確認、**Then** 候補日程・参加者・内容・メモは確定前と同じ状態で残っている
4. **Given** 再調整済みコラボ、**When** 公開リンクを共有して回答フォームを開く、**Then** 参加者が再度回答を送信できる

---

### User Story 2 - 確定済みコラボを複製して新規調整を作成する (Priority: P2)

確定済みコラボと同じ相手・同じタイトルで、日程だけ異なる新しいコラボ調整を素早く作成できる。

**Why this priority**: 定期コラボや「NG になった日程で別の機会を設ける」場合に、毎回タイトルや相手名を入力し直す手間を省ける。

**Independent Test**: 確定済みコラボの詳細画面で「このコラボをコピーして新規作成」ボタンをクリックし、タイトル・相手名が引き継がれた状態でコラボ作成フォームが開くことを確認。

**Acceptance Scenarios**:

1. **Given** 確定済みコラボの詳細画面、**When** 「コピーして新規作成」ボタンをクリック、**Then** コラボ作成フォームがタイトル・パートナー名・有効期限を引き継いだ状態で開く
2. **Given** コラボ作成フォームが開いた状態、**When** 候補日程を新たに入力して作成、**Then** 元のコラボとは別の新規コラボセッションが作成される
3. **Given** 元のコラボが確定済み、**When** コピーから新規作成、**Then** 元のコラボのステータスは変化しない

---

### Edge Cases

- 再調整（reopen）を実行した際、確定時に作成されたスケジュールが既に削除済みの場合はエラーにせず再調整のみ実行する
- コラボが `cancelled`（削除済み）の場合、再調整・複製ボタンは表示しない
- `open` ステータス（未確定）のコラボに再調整ボタンは表示しない（既に調整中のため）
- 再調整後、参加者の回答（`participantResponses`）はリセットしない（前回回答の参考として残す）。ただし全消去オプションも提供する

## Requirements

### Functional Requirements

- **FR-001**: 確定済み（`confirmed`）コラボ詳細画面に「再調整する」ボタンを表示しなければならない
- **FR-002**: 「再調整する」実行前に確認ダイアログを表示しなければならない
- **FR-003**: 再調整を実行した際、コラボのステータスを `confirmed` → `open` に変更しなければならない
- **FR-004**: 再調整を実行した際、`confirmedDate` を null にリセットしなければならない
- **FR-005**: 再調整を実行した際、確定時に自動作成されたスケジュール（`linkedScheduleId` のスケジュール）を削除しなければならない
- **FR-006**: 再調整を実行した際、`linkedScheduleId` を null にリセットしなければならない
- **FR-007**: 再調整後、候補日程・参加者・タイトル・内容・コメントは保持しなければならない
- **FR-008**: 確定済みコラボ詳細画面に「コピーして新規作成」ボタンを表示しなければならない
- **FR-009**: 「コピーして新規作成」では、タイトル・パートナー名・有効期限を引き継いだコラボ作成フォームを開かなければならない
- **FR-010**: 「コピーして新規作成」は元のコラボのステータスを変更してはならない

### Key Entities

- **CollabSession**: `status`（`open` / `confirmed` / `cancelled`）、`confirmedDate`、`linkedScheduleId` フィールドを持つ。再調整により `confirmed` → `open` に遷移する
- **ScheduleEntry**: 確定時に自動作成されるスケジュール。再調整時に削除対象となる

## Success Criteria

### Measurable Outcomes

- **SC-001**: 再調整の操作が「再調整するボタン → 確認ダイアログ → 実行」の 2 ステップで完了する
- **SC-002**: コラボの複製から新規コラボ作成完了まで、入力項目が初回作成と比較して 50% 以下になる
- **SC-003**: 再調整後のコラボ詳細画面に、以前の候補日程・参加者データが維持されている

## Assumptions

- 再調整はチームの Owner/Editor 権限を持つメンバーのみ実行可能
- 再調整によるスケジュール削除は確定時に自動生成されたスケジュールのみ対象（ユーザーが手動で作成したスケジュールは対象外。`linkedScheduleId` で管理）
- 再調整後の `participantResponses`（回答データ）はデフォルトで保持する。前回の回答を参考にできるため
- コラボ複製はクライアント側でフォームを事前入力するのみ（Cloud Function は既存の `createCollabSession` を再利用）
- `cancelled` ステータスの再調整は対象外（削除は不可逆）
