# Feature Specification: UIリデザイン — サイドバー・ダッシュボード・通知 + タスク管理画面

**Feature Branch**: `002-002-redesign`
**Created**: 2026-05-16
**Updated**: 2026-05-17
**Status**: 実装中（スプリント1完了、スプリント2進行中）
**Input**: UIリデザイン要件 — `docs/risukeru_gg_screens.html` 参照

> **スプリント構成**
> - **スプリント1**（`001-risukeru-gg-app`・実装済み）: User Story 1〜3 — サイドバー・ダッシュボード・通知
> - **スプリント2**（`002-002-redesign`・進行中）: User Story 4〜6 — タスク管理画面リデザイン

## 概要

既存アプリの UI を `docs/risukeru_gg_screens.html` のモックアップに合わせて 2 スプリントで再設計する。

**スプリント1（完了）**: Azouaoui Mohamed スタイルのサイドバー（折りたたみ・アコーディオン）・5つの統計ウィジェット付きダッシュボード・タスクカード詳細モーダル・通知ドロップダウンを実装した。

**スプリント2（進行中）**: タスク管理画面のカンバンボードをフル幅化し、タスク詳細のインライン編集モーダル（`TaskDetailModal`）と、設定画面に「タスク管理」タブ（列・カテゴリ・ステータス管理）を追加する。タスクカテゴリを Firestore バックのエンティティに移行（`Task.category` enum → `Task.categoryId` Firestore ID）する破壊的変更を含む。

### User Story 1 — アコーディオン折りたたみサイドバー (Priority: P1) ✅ 実装済み

配信者・チームメンバーが画面幅に応じてサイドバーを折りたたみ、ナビゲーション項目をアコーディオンで整理できる。

**Why this priority**: 全画面の土台となるナビゲーション。他の機能より先に完成させる必要がある。

**Independent Test**: サイドバーのトグルボタンをクリックすると 260px ↔ 72px に切り替わり、セクションヘッダーをクリックすると子項目が展開・収納される。リロード後も折りたたみ状態が維持される。

**Acceptance Scenarios**:

1. **Given** アプリを開いた状態で, **When** サイドバーのトグルボタンをクリックする, **Then** サイドバー幅が 260px から 72px に縮小し、テキストが非表示になりアイコンのみが残る
2. **Given** サイドバーが折りたたまれた状態で, **When** トグルボタンを再クリックする, **Then** 260px に戻りテキストが再表示される
3. **Given** サイドバーが展開された状態で, **When** 「メイン」セクションヘッダーをクリックする, **Then** スケジュール・タスク管理・コラボ調整の子項目が展開/収納される
4. **Given** サイドバーが折りたたまれた状態で, **When** ページをリロードする, **Then** 折りたたみ状態が維持される（localStorage 永続化）
5. **Given** 現在スケジュールページを閲覧中で, **When** サイドバーを確認する, **Then** 「メイン」セクションが展開され、「スケジュール」アイテムがアクティブ状態（ハイライト）で表示される
6. **Given** サイドバーのロゴアイコンをクリックする, **Then** ダッシュボード（/dashboard）に遷移する
7. **Given** Material Icons が使用されている, **When** ナビゲーション項目を確認する, **Then** 各項目に適切な Material Icon が表示されている

### User Story 2 — ダッシュボード再設計（5統計ウィジェット＋タスクボード） (Priority: P1) ✅ 実装済み

ダッシュボードに 5 つの統計ウィジェットと大き目タスクカードグリッドが表示され、タスクカードクリックで詳細モーダルが開く。

**Why this priority**: ダッシュボードはログイン後の最初の画面。情報密度と視認性の向上が即時の UX 改善につながる。

**Independent Test**: ダッシュボードにアクセスすると 5 つの統計ウィジェット（今月の配信枠数・編集タスク数・今月のタスク数・コラボ調整中・タスク完了率）が表示され、タスクカードをクリックするとモーダルが開く。

**Acceptance Scenarios**:

1. **Given** ダッシュボードにアクセスした状態で, **When** 統計ウィジェットエリアを確認する, **Then** 5 つのウィジェット（今月の配信枠数・今月の編集タスク数・今月のタスク数・コラボ調整中・タスク完了率）が横並びで表示される
2. **Given** タスクが存在する状態で, **When** ダッシュボードのタスクボードエリアを確認する, **Then** タスクカードが複数列グリッドで表示され、各カードにタスク名・カテゴリ・期限・担当者が表示される
3. **Given** タスクカードが表示されている状態で, **When** カードをクリックする, **Then** タスク詳細モーダルが開き、タスク名・カテゴリ・期限・担当者・カラム（進捗状態）が表示される
4. **Given** タスク詳細モーダルが開いている状態で, **When** モーダル外またはクローズボタンをクリックする, **Then** モーダルが閉じてダッシュボードに戻る
5. **Given** タスクが 0 件の状態で, **When** ダッシュボードのタスクボードエリアを確認する, **Then** 「タスクはありません」メッセージが表示される

### User Story 3 — 通知ドロップダウン (Priority: P1) ✅ 実装済み

TopBar の通知ベルをクリックすると、ページ遷移なしでドロップダウンに通知一覧が表示される。

**Why this priority**: 通知確認のために別ページに遷移するフローを改善し、操作効率を向上させる。

**Independent Test**: TopBar の通知ベルをクリックするとドロップダウンが開き、未読通知が一覧表示される。ドロップダウン外をクリックすると閉じる。

**Acceptance Scenarios**:

1. **Given** 未読通知がある状態で, **When** TopBar の通知ベルをクリックする, **Then** ドロップダウンが開き最大 4 件の通知が表示される（未読ドット付き）
2. **Given** 通知ドロップダウンが開いている状態で, **When** ドロップダウン外の領域をクリックする, **Then** ドロップダウンが閉じる
3. **Given** 通知ドロップダウンが開いている状態で, **When** 「すべて見る」をクリックする, **Then** `/notifications` ページに遷移しドロップダウンが閉じる
4. **Given** 未読通知がある状態で, **When** 通知ベルを確認する, **Then** ベルに未読件数バッジが表示されている

### User Story 4 — カンバンボード フル幅レイアウト (Priority: P1)

タスク管理ページのカンバンボードが画面幅いっぱいに表示され、列数が少ない場合でも右側に無駄な余白が生じない。

**Why this priority**: モックの UI に合わせることで視認性を向上し、今後の詳細モーダル実装の土台となる。

**Independent Test**: `/tasks` を開くとカンバンボードの列が画面幅を均等に分割して表示され（`flex-1 min-w-[240px]`）、カード上にカテゴリ名がストアから取得されて正しく表示される。

**Acceptance Scenarios**:

1. **Given** `/tasks` ページを開いた状態で, **When** カンバンボードを確認する, **Then** 列が画面幅いっぱいに均等配置される（固定 272px 幅ではなく `flex-1`）
2. **Given** カテゴリが Firestore に存在する状態で, **When** タスクカードを確認する, **Then** カテゴリ名が正しく表示される（`taskCategories` ストアから取得）
3. **Given** 新規タスク作成フォームを開いた状態で, **When** カテゴリを選択する, **Then** Firestore のカテゴリ一覧がドロップダウンに表示される

### User Story 5 — タスク詳細モーダル（インライン編集） (Priority: P1)

タスクカードをクリックすると詳細モーダルが開き、ステータス・カテゴリ・担当者・期限・タスク説明・コメントをページ遷移なしに閲覧・編集できる。

**Why this priority**: タスクの詳細確認・更新のたびに別ページに遷移する手間を解消し、操作効率を大幅に向上させる。

**Independent Test**: タスクカードをクリックすると `TaskDetailModal` が開き、ステータス（`<select>` onChange 即時保存）・カテゴリ（`<select>` onChange 即時保存）・担当者（鉛筆アイコン→select→保存ボタン）・期限（カレンダーアイコン→date input→保存ボタン）・タスク説明（鉛筆アイコン→textarea→保存ボタン）が編集できる。モーダル外クリックまたはフッターの「閉じる」ボタンでモーダルが閉じる。

**Acceptance Scenarios**:

1. **Given** タスクカードが表示されている状態で, **When** カード（編集/削除ボタン以外の領域）をクリックする, **Then** `TaskDetailModal` が開き、タスクのタイトル・ステータス・カテゴリ・担当者・期限・タスク説明が表示される
2. **Given** モーダルが開いている状態で, **When** ステータスの `<select>` を変更する, **Then** 変更が即時 Firestore に保存される（保存ボタン不要）
3. **Given** モーダルが開いている状態で, **When** 担当者の鉛筆アイコンをクリックし変更して「保存」ボタンを押す, **Then** 担当者が更新される
4. **Given** モーダルが開いている状態で, **When** 期限のカレンダーアイコンをクリックし日付を選択して「保存」ボタンを押す, **Then** 期限が更新される
5. **Given** モーダルが開いている状態で, **When** タスク説明の鉛筆アイコンをクリックしテキストを編集して「保存」ボタンを押す, **Then** タスク説明が更新される
6. **Given** モーダルが開いている状態で, **When** コメント入力欄にコメントを入力して送信する, **Then** コメントがモーダル内のローカルリストに追加される（Firestore 保存なし）
7. **Given** モーダルが開いている状態で, **When** モーダル外をクリックするまたはフッターの「閉じる」ボタンをクリックする, **Then** モーダルが閉じる
8. **Given** モーダルが開いている状態で, **When** フッターの「削除」ボタンをクリックする, **Then** タスクが削除されモーダルが閉じる

### User Story 6 — 設定画面「タスク管理」タブ（3セクション） (Priority: P1)

設定画面の「タスク管理」タブ内で、カンバン列の管理・タスクカテゴリの管理・完了ステータスの設定ができる。

**Why this priority**: タスクカテゴリを Firestore バックにすることでユーザーがカテゴリを自由に追加・編集・削除できる。完了ステータスの管理により、ダッシュボードのタスク完了率計算の精度が向上する。

**Independent Test**: `/settings` の「タスク管理」タブを開くと「列の管理」「カテゴリの管理」「ステータスの管理」の 3 セクションが表示される。カテゴリの追加・編集・削除が Firestore に反映される。カラムに「完了」ロールを設定するとダッシュボードの完了率計算に使用される。

**Acceptance Scenarios**:

1. **Given** `/settings` を開いた状態で, **When** 「タスク管理」タブをクリックする, **Then** 「列の管理」「カテゴリの管理」「ステータスの管理」の 3 セクションが表示される
2. **Given** 「カテゴリの管理」セクションで, **When** 新しいカテゴリ名と色を入力して追加する, **Then** Firestore に保存されタスク管理画面のカテゴリ選択肢に反映される
3. **Given** 「カテゴリの管理」セクションで, **When** 既存カテゴリの「削除」ボタンをクリックする, **Then** カテゴリが Firestore から削除され、関連タスクの `categoryId` が `null` になる
4. **Given** 「ステータスの管理」セクションで, **When** あるカラムを「完了ステータス」としてマークする, **Then** そのカラムの `role` が `'done'` に設定され、ダッシュボードの完了率計算に使用される

## Requirements

### Functional Requirements

#### スプリント1（実装済み）

- **FR-UI-001**: サイドバーはトグルボタンで 260px（展開）↔ 72px（折りたたみ）を切り替えられなければならない
- **FR-UI-002**: サイドバーの「メイン」「チーム管理」「各種連携」の各セクションはクリックで展開/収納できなければならない
- **FR-UI-003**: 折りたたみ状態は localStorage に永続化されリロード後も維持されなければならない
- **FR-UI-004**: サイドバーのナビゲーションアイコンは Google Material Icons を使用しなければならない
- **FR-UI-005**: サイドバーのアプリロゴアイコンをクリックすると `/dashboard` に遷移しなければならない
- **FR-UI-006**: ダッシュボードは「今月の配信枠数」「今月の編集タスク数」「今月のタスク数」「コラボ調整中」「タスク完了率」の 5 つの統計ウィジェットを表示しなければならない
- **FR-UI-007**: ダッシュボードのタスクボードはタスクカードを複数列グリッドで表示しなければならない
- **FR-UI-008**: 各タスクカードにはタスク名・カテゴリ・期限・担当者が表示されなければならない
- **FR-UI-009**: タスクカードをクリックするとタスク詳細モーダルが開かなければならない
- **FR-UI-010**: TopBar の通知ベルをクリックすると通知ドロップダウンが表示されなければならない
- **FR-UI-011**: 通知ドロップダウンはドロップダウン外クリックで閉じなければならない

#### スプリント2（進行中）

- **FR-TASK-001**: カンバンボードの各列は画面幅を均等に分割して表示されなければならない（`flex-1 min-w-[240px]`）
- **FR-TASK-002**: タスクカード（編集/削除ボタン以外の領域）をクリックすると `TaskDetailModal` が開かなければならない
- **FR-TASK-003**: `TaskDetailModal` ではステータス・カテゴリ（onChange 即時保存）・担当者・期限・タスク説明（鉛筆アイコン/カレンダーアイコン→保存ボタン）のインライン編集ができなければならない
- **FR-TASK-004**: `TaskDetailModal` のフッターには左に「削除」ボタン・右に「閉じる」ボタンが配置されなければならない（各フィールドが独立保存するためフッター右は「閉じる」）
- **FR-TASK-005**: タスクカテゴリは `teams/{teamId}/taskCategories/{categoryId}` コレクションで管理され、ユーザーが追加・編集・削除できなければならない
- **FR-TASK-006**: タスクカテゴリ削除時は、関連する全タスクの `categoryId` を `null` に更新しなければならない
- **FR-TASK-007**: `Task` エンティティは `categoryId: string | null`・`description: string | null` フィールドを持たなければならない（`category` enum は deprecated）
- **FR-TASK-008**: `KanbanColumn` エンティティは `role: 'done' | null` フィールドを持ち、設定画面で完了ステータスとして設定できなければならない
- **FR-TASK-009**: ダッシュボードのタスク完了率は `column.role === 'done'` で完了カラムを特定して計算しなければならない（カラム名依存の実装を廃止）
- **FR-TASK-010**: 設定画面の「タスク管理」タブ（旧「カンバン」タブ）に「列の管理」「カテゴリの管理」「ステータスの管理」の 3 セクションが表示されなければならない
- **FR-TASK-011**: `src/lib/utils/exportTasksCsv.ts` は `Task.categoryId` と `TaskCategory[]` を使用するよう更新されなければならない（`Task.category` enum 参照を廃止）

### Non-Functional Requirements

- **NFR-UI-001**: サイドバーの開閉アニメーションは `transition-[width] duration-300` でスムーズに動作しなければならない
- **NFR-UI-002**: TypeScript strict モードでコンパイルエラーゼロでなければならない
- **NFR-UI-003**: 既存の Tailwind CSS `@theme` デザイントークンを使用しなければならない
- **NFR-UI-004**: コメントは日本語で記述しなければならない

### Key Entities

#### スプリント1（実装済み）

- **SidebarState**: collapsed（boolean）・openSections（string[]）を持つ Zustand ストア（localStorage 永続化）
- **NavSection**: label・icon（Material Icons 名）・items（NavItem[]）を持つサイドバーセクション定義
- **NavItem**: href・label・icon・badge（optional）・disabled（optional）を持つナビゲーションアイテム

#### スプリント2（進行中）

- **TaskCategory**: id・name・color（`#RRGGBB`）・order・createdAt を持つ Firestore エンティティ（`teams/{teamId}/taskCategories/{categoryId}`）
- **Task** (変更): `categoryId: string | null`・`description: string | null` フィールド追加、`category` enum 削除
- **KanbanColumn** (変更): `role: 'done' | null` フィールド追加

## Assumptions

- Mobile（md 未満）では Sidebar は非表示のまま（BottomNav を使用）。今回の変更対象外
- 各種連携（Googleカレンダー・Discord・YouTube・X）の実際の機能は将来実装。今回は disabled 表示のみ
- タスク詳細モーダルのコメントはローカル状態のみで管理する（Firestore 保存は将来機能として保留）
- `TaskDetailModal` からダッシュボードページへの統合はスプリント2の対象外（`/tasks` ページのみ対応）
- タスクカテゴリは Firestore バックのため、既存の `Task.category` enum（`shooting`・`editing`・`thumbnail`・`announcement`・`other`）は deprecated となり、シードデータで代替カテゴリを提供する
