# Feature Specification: スケジュール・UI改善 + 複数チーム所属

**Feature Branch**: `003-schedule-ui-improvements`  
**Created**: 2026-05-18  
**Status**: Draft

## User Scenarios & Testing

### User Story 1 - 複数日程の予定を正しく表示する (Priority: P1)

配信者が3日間にまたがる合宿配信を登録した際に、カレンダーの各日にイベントカードが表示される。

**Why this priority**: 現在バグとして存在している機能不全。登録した予定が見えないと最も基本的な用途を損なう。

**Independent Test**: 3日間の予定を作成して、週ビュー・月ビューそれぞれで3日分カードが表示されることを確認。

**Acceptance Scenarios**:

1. **Given** 2026-05-18 09:00 〜 2026-05-20 18:00 の予定が登録済み、**When** スケジュール画面を表示、**Then** 5/18・5/19・5/20 の各日に予定カードが表示される
2. **Given** 単日の予定が登録済み、**When** スケジュール画面を表示、**Then** 開始日のみに予定カードが表示される（既存動作を維持）

---

### User Story 2 - 日曜始まりカレンダー (Priority: P2)

週ビュー・月ビューの先頭が日曜日になっている。

**Why this priority**: 日本の配信者が週のサイクルを日〜土で考えることが多い。視覚的な使いやすさの改善。

**Independent Test**: スケジュール画面を開いて、週ヘッダーの左端が「日」であることを確認。

**Acceptance Scenarios**:

1. **Given** スケジュール画面を開く、**When** 週ビューを表示、**Then** 左端の列が「日」、右端が「土」になっている
2. **Given** スケジュール画面を開く、**When** 月ビューを表示、**Then** 月間カレンダーの1列目が日曜日になっている

---

### User Story 3 - フォームへのマークダウン入力 (Priority: P2)

スケジュールやタスクの「内容（説明）」フィールドでマークダウン記法（**太字**、- 箇条書き、`コード`など）が使える。

**Why this priority**: 配信メモや企画内容を構造化して書きたいというニーズに応える。

**Independent Test**: スケジュール作成フォームの説明欄に `**テスト**` と入力し、プレビューで太字表示されることを確認。

**Acceptance Scenarios**:

1. **Given** スケジュール作成フォームを開く、**When** 説明欄に `## 見出し` と入力してプレビューボタンをクリック、**Then** 見出しとしてレンダリングされる
2. **Given** 既存の説明文が表示されている、**When** 詳細画面を開く、**Then** 保存済みのマークダウンがレンダリングされた状態で表示される

---

### User Story 4 - フォームドラフト自動保存 (Priority: P2)

「スケジュール追加」を開いてタイトルを入力した後、誤って閉じてしまっても、再度開くと入力内容が残っている。

**Why this priority**: 入力途中で誤って閉じた際のデータ損失を防ぐ。配信者が途中まで書いた企画メモを失わないようにする。

**Independent Test**: スケジュール作成フォームにタイトルを入力 → ×で閉じる → 再度「予定を追加」をクリック → タイトルが復元されていることを確認。

**Acceptance Scenarios**:

1. **Given** スケジュール作成フォームにタイトル「テスト配信」を入力済み、**When** ×ボタンで閉じて再度フォームを開く、**Then** タイトルフィールドに「テスト配信」が入っている
2. **Given** スケジュール作成フォームに入力後「確定」ボタンを押して保存、**When** 再度フォームを開く、**Then** フォームが空白の状態で開く

---

### User Story 5 - スケジュールカードにアイコン表示 (Priority: P3)

週ビューの予定カードにカテゴリのアイコンが表示され、一目でカテゴリを識別できる。

**Why this priority**: カテゴリの色に加えてアイコンが見えると、色弱ユーザーや素早い視認性向上に役立つ。

**Independent Test**: アイコン付きカテゴリを持つ予定を作成し、週ビューでカードにアイコンが表示されることを確認。

**Acceptance Scenarios**:

1. **Given** 「ゲーム配信」カテゴリ（sports_esports アイコン）の予定が存在、**When** 週ビューを表示、**Then** 該当予定カードにゲームコントローラーのアイコンが表示される

---

### User Story 6 - 終日イベント作成 (Priority: P3)

スケジュール作成時に「終日」ボタン1クリックで、その日の全時間帯をカバーする予定を素早く作成できる。

**Why this priority**: 配信者にとって「今日は配信日」のような終日ブロックが多い。毎回 00:00〜23:59 を手入力する手間を省く。

**Independent Test**: スケジュール作成フォームで日付を入力 → 「終日」ボタンをクリック → 開始時刻が 00:00、終了時刻が 23:59 になることを確認。

**Acceptance Scenarios**:

1. **Given** 開始日時に 2026-05-20 14:00 を入力済み、**When** 「終日」ボタンをクリック、**Then** 開始日時が 2026-05-20 00:00、終了日時が 2026-05-20 23:59 になる
2. **Given** 開始日時を 2026-05-20 10:00 に入力、**When** 終了日時を変更しない、**Then** 終了日時が自動的に 2026-05-20 12:00（2時間後）に設定される

---

### User Story 7 - 複数チームへの同時所属とチーム切替 (Priority: P3)

1人のユーザーが複数のチームに同時に所属でき、ヘッダーのドロップダウンから素早く切り替えられる。

**Why this priority**: 複数の配信グループに関わる配信者が、アカウントを分けずに管理できるようになる。

**Independent Test**: 2つのチームに参加した状態で、チームスイッチャーから切り替えて異なるスケジュール・タスクが表示されることを確認。

**Acceptance Scenarios**:

1. **Given** チームAとチームBに所属している、**When** チームスイッチャーからチームBを選択、**Then** スケジュール・タスクがチームBのデータに切り替わる
2. **Given** チームAに所属している、**When** チームコードを入力してチームBに参加、**Then** チームAからの退出なしにチームBにも所属できる
3. **Given** 2つのチームに所属している、**When** 特定チームから退出、**Then** そのチームのデータにアクセスできなくなり、残りのチームのデータは引き続き利用できる

---

### Edge Cases

- 複数チーム所属でチームAを退出した際、チームAが唯一のチームだった場合は solo チームを自動生成する
- チーム切替中に他のチームのデータが前のチームに混入しない
- マークダウン入力で XSS につながる `<script>` タグは無害化される
- ドラフト保存で `Date` 型は ISO 文字列にシリアライズして保存・復元される
- 終日ボタンは開始日時が未入力でも動作し、本日の 00:00〜23:59 を設定する

## Requirements

### Functional Requirements

- **FR-001**: カレンダーは複数日にまたがるイベントを各日付のセルに表示しなければならない
- **FR-002**: 週ビュー・月ビューは日曜日始まりでなければならない
- **FR-003**: テキスト入力フィールドはマークダウン記法をサポートし、プレビューモードでレンダリングしなければならない
- **FR-004**: 「確定」以外の操作でフォームを閉じた際、入力内容を自動保存し次回起動時に復元しなければならない
- **FR-005**: 週ビューのスケジュールカードはカテゴリアイコンを表示しなければならない
- **FR-006**: 日付入力コンポーネントは日付と時刻を同一フィールドで入力できなければならない
- **FR-007**: スケジュール作成フォームは「終日」ボタンを提供し、開始 00:00・終了 23:59 を自動設定しなければならない
- **FR-008**: 開始日時を入力した際、終了日時が未設定の場合は自動的に 2時間後を設定しなければならない
- **FR-009**: 1ユーザーが複数のチームに同時所属できなければならない
- **FR-010**: チームスイッチャーで任意のチームをアクティブチームに切り替えられなければならない
- **FR-011**: チームへの新規参加時に既存チームから退出しないようにしなければならない
- **FR-012**: 特定チームからの退出が可能でなければならない

### Key Entities

- **ScheduleEntry**: スケジュールエントリ。`allDay?: boolean` フィールドを追加
- **User**: ユーザー。`teamIds: string[]` フィールドを追加（全所属チームIDリスト）
- **MarkdownEditor**: マークダウン入力・プレビューを切替可能な UI コンポーネント
- **DateTimeInput**: 日付と時刻を統一フォーマットで入力する UI コンポーネント
- **FormDraft**: localStorage を使ったフォーム入力の一時保存ユーティリティ

## Success Criteria

### Measurable Outcomes

- **SC-001**: 複数日にまたがる予定が、全対象日付のカレンダーセルに表示される（表示漏れゼロ）
- **SC-002**: フォームを「確定」以外で閉じて再度開いた際、100% のケースで入力内容が復元される
- **SC-003**: 「終日」ボタンのクリック 1回で開始 00:00・終了 23:59 が設定される（操作 1ステップ）
- **SC-004**: チーム切替後、1秒以内に新チームのデータが表示される
- **SC-005**: マークダウンで入力した内容が、プレビューで意図通りレンダリングされる

## Assumptions

- マルチチーム所属は最大チーム数を制限しない（プランによる制限は将来対応）
- チームスイッチャー UI はサイドバーまたはヘッダーの目立つ位置に配置
- マークダウンのレンダリングには GFM（GitHub Flavored Markdown）をサポートする
- フォームドラフトはブラウザの localStorage に保存し、ローカルデバイスに閉じる（クロスデバイス同期は対象外）
- 既存ユーザーへのマイグレーション: `teamIds` フィールドは `currentTeamId` から自動生成。`switchActiveTeam` / `leaveSpecificTeam` の Cloud Function 実行時に `teamIds` が未設定（undefined / 空配列）であれば `currentTeamId` を元に自動補完する
